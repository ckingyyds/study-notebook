## 1. 日志管理（必会）
> 🏷️ ⭐ 开发必会 —— 出 bug、查问题、定位线上故障的第一手工具，务必掌握

### 1.1 日志系统介绍（了解）
> 🏷️ 📖 概念了解 —— 理论背景，读懂即可

Linux 日志系统由两部分组成（开发要知道这是两套并存的东西）：

- **rsyslog**：传统日志服务，按类型写到 `/var/log/` 下不同文件（文本格式，cat/tail/grep 直接看）
- **journald**：systemd 自带的二进制日志（CentOS 7+ 默认），只能用 `journalctl` 命令查，不能直接 cat

### 1.2 重要日志文件（开发必记这 5 个）（必会）
> 🏷️ ⭐ 开发必会 —— 出问题先去这里翻

```bash
# 系统主日志（CentOS 7）
tail /var/log/messages        # 系统通用日志（出问题先看这个）
tail /var/log/secure          # 安全相关日志（登录失败、sudo 记录）
tail /var/log/cron            # 定时任务执行日志
tail /var/log/dmesg           # 内核启动日志
tail /var/log/yum.log         # YUM 装包记录

# 应用日志（你部署的服务日志都在这里）
ls /var/log/nginx/            # Nginx access.log / error.log
tail /var/log/mysqld.log      # MySQL 启动/错误日志
```

### 1.3 查看日志的 3 种核心姿势（必会）
> 🏷️ ⭐ 开发必会 —— 开发查问题 90% 用 tail + grep，systemd 服务用 journalctl

```bash
# ① tail 实时查看（最常用）
tail -f /var/log/nginx/access.log     # 实时滚动看（Ctrl+C 退出）
tail -n 100 /var/log/nginx/error.log  # 看最后 100 行

# ② grep 过滤（找特定错误）
grep "ERROR" /var/log/messages        # 找所有 ERROR
grep "2026-07-30" /var/log/messages    # 按日期找
grep -i "failed" /var/log/secure | tail -20  # -i 忽略大小写

# ③ journalctl 查 systemd 服务日志（开发部署的服务都用它管）
journalctl -u nginx                   # 看 nginx 服务日志
journalctl -u nginx -f                # 实时跟踪（= tail -f 的 journald 版）
journalctl -u nginx --since today     # 只看今天的
journalctl -u nginx -n 50             # 最近 50 条
journalctl -u nginx --no-pager        # 不分页（脚本/管道里必加，否则卡住）
journalctl -xe                        # 看最近的错误（服务起不来时用）
```

## 10. 综合实战：Web 服务器部署（必会）
> 🏷️ ⭐ 开发必会 —— 软件开发日常高频使用，务必掌握

### 10.1 部署架构：Vue3 + Django 为什么需要 Nginx（必会）

先不碰任何配置，搞懂"一个请求从浏览器到数据库，中间经过谁"，后面的配置每行都能对上号。

```
┌──────────────┐
│   浏览器      │  用户打开网页 / 点按钮发请求
└──────┬───────┘
       │  HTTP（80/443）
       ▼
┌──────────────────────────────────────────────┐
│  Nginx（80 端口）—— 全站唯一对外的大门         │
│  职责①：托管 Vue3 打包后的静态文件（dist）     │
│  职责②：把 /api/ 开头的请求"反向代理"给 Django │
└──────┬───────────────────────┬───────────────┘
       │ /（找文件）            │ /api/（转发）
       ▼                       ▼
┌──────────────────┐   ┌────────────────────────┐
│ dist/ 目录        │   │ gunicorn（127.0.0.1:8000）│
│ index.html/js/css│   │ 里面跑着 Django 程序       │
└──────────────────┘   └───────────┬────────────┘
                                   │ 查数据
                                   ▼
                          ┌─────────────────┐
                          │ MySQL（3306）    │
                          └─────────────────┘
```

**每个组件是干嘛的（一句话版）：**

| 组件 | 角色 | 类比 |
|------|------|------|
| **Nginx** | Web 服务器：发静态文件又快又稳；同时当"前台接待"，动态请求转给后端 | 餐厅前台：凉菜自己上，热菜转交后厨 |
| **gunicorn** | Python 的"应用服务器"，真正运行 Django 代码、返回 JSON | 后厨（Django 自带的 runserver 是试吃摊，不能营业） |
| **Django** | 你的后端业务代码（API、admin 后台） | 菜谱+厨师 |
| **MySQL** | 数据库 | 仓库 |
| **Vue3 dist** | `npm run build` 产出的一堆静态文件 | 印好的菜单宣传单 |

**两个典型请求的完整路径：**

1. 打开 `http://服务器IP/`：浏览器 → Nginx 在 dist 目录找到 `index.html` 直接返回（**全程不碰 Django**，所以静态页面极快）
2. 打开 `http://服务器IP/api/users/`：浏览器 → Nginx 发现是 `/api/` 开头 → 转发给 `127.0.0.1:8000` 的 gunicorn → Django 查 MySQL → JSON 原路返回

> 🔑 **为什么要 Nginx，Django 不能直接对外吗？** 能，但不该：① gunicorn 发静态文件（图片/js/css）又慢又浪费；② 后端只监听 `127.0.0.1:8000`（只有本机能访问），不暴露公网更安全；③ Nginx 还负责 HTTPS、限流、日志。**记住：公网只开 80/443，8000 和 3306 一律不对公网开放。**

### 10.2 Nginx 配置一步一步学（必会）

> 🏷️ ⭐ 开发必会 —— 本节从零讲清每行配置的作用，10.5 部署时直接套这个模板

#### 10.2.1 配置文件在哪（先找对地方，宝塔和命令行不一样）

| 安装方式 | 主配置文件 | 站点配置放哪（推荐写这里） |
|----------|-----------|--------------------------|
| yum 装的 Nginx | `/etc/nginx/nginx.conf` | `/etc/nginx/conf.d/*.conf`（主配置里有 `include /etc/nginx/conf.d/*.conf;` 自动加载） |
| **宝塔装的 Nginx** | `/www/server/nginx/conf/nginx.conf` | **不要手改主配置**，在面板「网站 → 站点设置 → 配置文件」里改，实际落在 `/www/server/panel/vhost/nginx/站点名.conf` |

> ⚠️ 宝塔环境最常见的坑：把配置写进 `/etc/nginx/conf.d/`，但宝塔的 nginx.conf 根本不 include 这个目录，结果"语法对、不生效、还 403/404"。**用宝塔就老实在面板的站点配置里改。**

#### 10.2.2 配置的四层结构（先建立大局观）

```nginx
# nginx.conf 的骨架（不用背，认识层级即可）
events { }                  # 连接相关，保持默认不用动

http {                      # 所有网站配置都在 http { } 里面
    server {                # 一个 server { } = 一个网站（按端口+域名区分）
        location / { }      # 一个 location = 这个网站里"某类 URL"的处理规则
        location /api/ { }  # 可以有多个 location，按 URL 前缀分工
    }
}
```

包含关系：**http 里有多个 server，server 里有多个 location**。我们要写的就是一个 `server { }`。

#### 10.2.3 第一步：最小站点——把一个网页发出去

先在服务器上准备一个测试页面：

```bash
mkdir -p /www/demo                        # 建站点目录
echo '<h1>Hello Nginx</h1>' > /www/demo/index.html
```

写站点配置（yum 装的：`vi /etc/nginx/conf.d/demo.conf`；宝塔：10.2.8 讲，先看命令行版）：

```nginx
server {
    listen 80;                    # 监听 80 端口（HTTP 默认端口，所以访问时 URL 不用带端口）
    server_name 192.168.233.131;  # 匹配哪个域名/IP；没有域名就写服务器 IP
    root /www/demo;               # 网站根目录：URL 对应的文件都从这个目录找
    index index.html;             # 访问"目录"时默认返回哪个文件
}
```

生效并验证：

```bash
nginx -t                  # 每次改完必须先测语法：看到 syntax is ok / test is successful
systemctl reload nginx    # 平滑重载（不断开已有连接，重启的是 reload 不是 restart）
curl http://127.0.0.1/    # 本机自测：返回 <h1>Hello Nginx</h1> 就成功
```

**这一步发生了什么**：访问 `http://IP/` 时，Nginx 拿 URL 路径 `/` 拼到 root 后面 → 找 `/www/demo/` → 发现是目录 → 用 index 指定的 `/www/demo/index.html` 返回。

#### 10.2.4 第二步：location 与 try_files（Vue 刷新 404 的根治）

Vue3 项目打包后只有**一个** `index.html`，页面跳转全靠浏览器端的 Vue Router。直接访问 `/users/3` 这种地址时，Nginx 会去 dist 里找名为 `users/3` 的文件——当然找不到，返回 404。解决：

```nginx
server {
    listen 80;
    server_name 192.168.233.131;
    root /www/myproject/frontend/dist;     # 指向 Vue 打包产物 dist 目录
    index index.html;

    location / {                                          # 匹配所有路径
        try_files $uri $uri/ /index.html;                 # 见下方逐字解释
    }
}
```

`try_files $uri $uri/ /index.html;` 按顺序尝试：

1. `$uri`：URL 路径本身（如 `/assets/index-a1b2.js`）→ dist 里有这个 js 文件就直接发；
2. `$uri/`：当目录找；
3. **`/index.html`：都找不到，返回首页**，剩下的路由交给 Vue Router 解析 → 刷新不再 404。

> 🔑 这是前后端分离部署出镜率最高的一行，必须理解。

#### 10.2.5 第三步：反向代理——把 /api/ 交给 Django

```nginx
    # 动态请求：/api/ 开头的 URL 转发给本机 8000 端口的 gunicorn
    location /api/ {
        proxy_pass http://127.0.0.1:8000;          # 转发目标（Django 监听的地址）

        proxy_set_header Host $host;               # 把原始域名带给后端（Django 的 ALLOWED_HOSTS 要靠它）
        proxy_set_header X-Real-IP $remote_addr;   # 把访客真实 IP 带给后端（否则日志里全是 127.0.0.1）
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;  # 经过的代理链 IP
        proxy_set_header X-Forwarded-Proto $scheme;# 告诉后端用户用的是 http 还是 https
    }

    # Django admin 后台也要代理（如果用后台的话）
    location /admin/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
```

**⚠️ proxy_pass 带不带结尾 `/` 的大坑（面试和实战都高频）：**

| 写法 | 效果（请求 `/api/users/`） |
|------|--------------------------|
| `proxy_pass http://127.0.0.1:8000;`（不带路径） | **保留 `/api/` 前缀**，Django 收到 `/api/users/`（Django 路由也要带 /api 前缀时用它，本教程用这个） |
| `proxy_pass http://127.0.0.1:8000/;`（带 `/`） | **剥掉 `/api/` 前缀**，Django 收到 `/users/`（Django 路由不带前缀时用） |

**为什么是 127.0.0.1 而不是服务器公网 IP？** gunicorn 和 Nginx 在同一台机器，走本机回环地址最快，且 gunicorn 只监听回环地址，公网摸不到它。

#### 10.2.6 第四步：Django 静态文件（root 和 alias 的区别）

Django 的 admin 样式、`collectstatic` 收集的静态文件不能让 Python 处理，交给 Nginx 直接发：

```nginx
    location /static/ {
        alias /www/myproject/backend/static/;   # alias：用后面路径【替换】URL 中的 /static/
        expires 30d;                            # 让浏览器缓存 30 天（静态文件带哈希，不怕不更新）
        access_log off;                         # 静态请求不写访问日志，减少噪音
    }
```

`alias` vs `root`（容易混）：

- `root /www/myproject/backend;` + 访问 `/static/a.css` → 找 **`/www/myproject/backend/static/a.css`**（root 是"拼接"，完整 URL 路径都保留）
- `alias /www/myproject/backend/static/;` + 访问 `/static/a.css` → 找 **`/www/myproject/backend/static/a.css`**（alias 是"替换"，把 `/static/` 替换掉）
- 记忆：**location 路径和磁盘目录同名用 root，不同名用 alias；alias 结尾的 `/` 不要漏**。

如果项目有用户上传的文件（settings 里的 `MEDIA_ROOT`），同样加一条：

```nginx
    location /media/ {
        alias /www/myproject/backend/media/;
    }
```

#### 10.2.7 其他高频指令（照着抄即可）

```nginx
    client_max_body_size 50M;     # 允许上传的最大文件（默认仅 1M，上传图片/导入 Excel 必调）

    charset utf-8;                # 响应头声明 UTF-8，防止中文乱码

    access_log /www/myproject/logs/nginx_access.log;   # 访问日志位置
    error_log  /www/myproject/logs/nginx_error.log;    # 错误日志位置（502/403 先看它）

    gzip on;                      # 开启压缩，js/css 传输体积可降 70%
    gzip_types text/css application/javascript application/json;
    gzip_min_length 1k;           # 小于 1k 不压（压了反而更大）
```

#### 10.2.8 完整模板（Vue3 + Django，可直接改路径使用）

```nginx
server {
    listen 80;
    server_name 192.168.233.131 your-domain.com;   # IP 和域名都写上，空格分隔
    charset utf-8;

    # ① Vue3 前端静态文件
    root /www/myproject/frontend/dist;
    index index.html;

    # ② Vue Router history 模式：找不到文件一律回退到首页
    location / {
        try_files $uri $uri/ /index.html;
    }

    # ③ 后端 API：转发给 gunicorn
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # ④ Django admin 后台
    location /admin/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # ⑤ Django 静态文件与用户上传文件
    location /static/ {
        alias /www/myproject/backend/static/;
        expires 30d;
        access_log off;
    }
    location /media/ {
        alias /www/myproject/backend/media/;
    }

    # ⑥ 上传大小、日志、压缩
    client_max_body_size 50M;
    access_log /www/myproject/logs/nginx_access.log;
    error_log  /www/myproject/logs/nginx_error.log;
    gzip on;
    gzip_types text/css application/javascript application/json;
    gzip_min_length 1k;
}
```

改完固定两步：`nginx -t` 测语法 → `systemctl reload nginx` 生效。

#### 10.2.9 在宝塔面板里怎么改这份配置

宝塔装的 Nginx，**不用 SSH 手写文件**，全程图形化：

1. **网站 → 添加站点**：填域名（没有域名填服务器 IP），根目录默认 `/www/wwwroot/站点名`，PHP 版本选「纯静态」
2. 把 dist 内容传到站点根目录（面板「文件」拖拽上传即可）
3. **站点名 → 设置 → 配置文件**：在打开的 `server { }` 里照 10.2.8 加 `location /api/`、`/static/` 等段落，保存（宝塔会自动 `nginx -t` 校验并 reload）
4. HTTPS：站点设置 → SSL → Let's Encrypt → 勾选域名一键申请（10.5.9 细讲）

> ⚠️ **宝塔 403 Forbidden 三连查**（最高频问题）：
> ① root 路径下确实有 `index.html`（`ls /www/wwwroot/站点名/`）；
> ② Nginx 运行用户（宝塔是 `www`）对目录有 r-x 权限：`chmod -R 755 目录`、`chown -R www:www 目录`；
> ③ 配置确实被加载：在面板站点配置里改，而不是写进 `/etc/nginx/conf.d/`。

### 10.3 部署更新脚本（必会）

第一次部署按 10.5 一步步做；之后每次发版重复敲十几条命令太累，写个 `deploy.sh`（第四章学的内容正好用上），一条命令完成"拉代码 → 装依赖 → 迁移 → 收静态 → 重启"：

```bash
#!/bin/bash
# 功能：更新 Django 后端 + Vue 前端并重启服务（在服务器项目根目录执行）
set -euo pipefail                                  # 任何一步失败立即停（第四章 1.5）

PROJ_DIR="/www/myproject"                          # 项目根目录
BACKUP_DIR="/data/backup/myproject"
TS=$(date '+%Y%m%d_%H%M%S')

echo "==> 1/6 备份当前版本"
mkdir -p "$BACKUP_DIR/$TS"
cp -r "$PROJ_DIR/backend" "$BACKUP_DIR/$TS/"      # 出问题可以回滚

echo "==> 2/6 更新后端代码"
cd "$PROJ_DIR/backend"
git pull origin main                               # 从仓库拉最新代码

echo "==> 3/6 安装 Python 依赖 + 数据库迁移"
"$PROJ_DIR/venv/bin/pip" install -r requirements.txt   # 用绝对路径调用虚拟环境里的 pip
"$PROJ_DIR/venv/bin/python" manage.py migrate          # 执行数据库迁移（没新迁移也安全）
"$PROJ_DIR/venv/bin/python" manage.py collectstatic --noinput  # 重新收集静态文件

echo "==> 4/6 更新前端"
# 方式 A（推荐）：dist 在本地 npm run build 编译好随仓库/上传更新，这里什么都不用做
# 方式 B：服务器上编译才需要下面两行（耗内存，小服务器不推荐）
# cd "$PROJ_DIR/frontend/src" && git pull && pnpm install && pnpm build
# rm -rf "$PROJ_DIR/frontend/dist" && mv dist "$PROJ_DIR/frontend/dist"

echo "==> 5/6 重启 Django（gunicorn）"
sudo systemctl restart gunicorn                    # 重启 10.5.6 配置的 systemd 服务
sleep 2
systemctl is-active --quiet gunicorn && echo "gunicorn 运行正常"

echo "==> 6/6 检查并重载 Nginx"
sudo nginx -t && sudo systemctl reload nginx       # && 保证语法通过才重载
echo "部署完成：$(date '+%F %T')"
```

使用：`chmod +x deploy.sh && ./deploy.sh`。Nginx 配置本身没变时不用 reload；脚本里带上是为了覆盖"顺手改了配置"的情况。

### 10.4 宝塔面板（BT Panel）—— 可视化运维利器（必会）

> 🏷️ ⭐ 开发了解 —— 国内中小企业用得非常多，进公司接手已有项目很可能遇到，能看懂、会用即可
> 适合谁：不想每次都敲命令装环境、配 Nginx、开数据库的新手；或者公司让你快速接手一台没人维护的服务器
> 不适合谁：纯命令行党、要部署到生产做精细控制的老手

#### 10.4.1 宝塔是什么 —— 一句话定位

**一句话**：宝塔是国内中小企业/个人站长最常用的 Linux 可视化运维面板——通过浏览器点鼠标就能装 Nginx/MySQL/PHP、建网站、申请 HTTPS、看监控，避免手敲一堆命令。

**企业分布简单结论**：宝塔在中小公司、个人开发、初创团队里**用得非常多**；但在大厂、金融、外企基本不用（用 K8s/Ansible/自研平台）。作为开发，进公司后很可能遇到，特别是接手已有中小项目时。

#### 10.4.2 宝塔 vs 命令行（开发要知道的取舍）

| 维度 | 宝塔面板 | 纯命令行 |
|------|---------|---------|

> ⚠️ **常见坑**：`url=` 后面**不要加反引号** `` ` ``（反引号是执行命令的意思），直接写地址或用双引号包起来。

**命令拆解（看懂每一步在干嘛）**：

| 命令 | 作用 |
|------|------|
| `url="..."` | 把安装脚本的下载地址存到变量 url 里（双引号防止特殊字符） |
| `if [ -f /usr/bin/curl ]` | 判断系统有没有 curl 命令（`-f` = file 存在） |
| `curl -sSO "$url"` | 有 curl 就用它下载脚本（`-s` 静默不显示进度，`-O` 用原文件名保存，`-S` 出错时显示错误） |
| `wget -O installStable_12.sh "$url"` | 没有 curl 就用 wget 下载（`-O` 指定保存的文件名） |
| `bash installStable_12.sh 5x59vxy56` | 用 bash 执行安装脚本，后面的 `5x59vxy56` 是安装密钥（官方固定的） |

#### 10.4.7 宝塔上的项目部署（Java + Python + Vue3）

> 你是 Java/Python 后端 + Vue3 前端，下面按步骤讲清楚**每个东西放宝塔的哪个目录、怎么跑起来**。本地虚拟机和云服务器操作一样。

##### ① 先搞清楚宝塔的默认目录结构

```
/www/
├── wwwroot/              ← 所有网站的根目录（前端 dist、后端代码都放这里）
│   └── myproject.com/    ← 宝塔"添加站点"时自动建的目录
├── server/
│   ├── nginx/            ← Nginx 安装目录
│   │   └── conf/         ← Nginx 主配置 nginx.conf
│   ├── mysql/            ← MySQL 安装目录
│   └── panel/            ← 宝塔面板自身
│       └── vhost/
│           └── nginx/    ← 每个站点的 Nginx 配置文件（*.conf）
├── server/data/          ← MySQL 数据库文件（不要手动动）
└── wwwlogs/              ← 所有网站的日志（access.log、error.log）
```

##### ② 第 1 步：建数据库

宝塔面板 → **数据库 → 添加数据库**：
- 数据库名：`myproject_db`
- 用户名：`myproject_user`
- 密码：自己设一个
- 访问权限：本地服务器（只允许本机连，安全）

> 建好后记住这 3 个信息，后端配置数据库连接要用。

##### ③ 第 2 步：部署 Vue3 前端

**本地打包**（在你 Windows 开发机上）：
```bash
cd 你的vue3项目
npm run build
# 产出 dist/ 目录，里面是 index.html + assets/
```

**上传到宝塔**：
- 宝塔面板 → **文件** → 进 `/www/wwwroot/你的站点目录/`
- 把 dist 里的所有文件（index.html、assets/ 等）上传到这里
- 或者宝塔面板 → **网站 → 添加站点**，根目录填 `/www/wwwroot/你的站点目录`

> 💡 前端就是一堆静态文件（html/js/css），放在站点目录下，Nginx 直接对外提供访问。

##### ④ 第 3 步：部署后端（Java 和 Python 二选一或都有）

**方式 A：Java 后端（Spring Boot jar 包）**

```
/www/wwwroot/myproject.com/
├── frontend/          ← Vue3 前端 dist 内容（index.html + assets）
└── backend/
    └── myproject.jar  ← Spring Boot 打包的 jar 包
```

在宝塔里跑起来（宝塔不自带 Java 进程管理，用 systemd）：
```bash
# /etc/systemd/system/myproject.service
[Unit]
Description=My Spring Boot App
After=network.target

[Service]
WorkingDirectory=/www/wwwroot/myproject.com/backend
ExecStart=/usr/bin/java -jar myproject.jar --server.port=8080
Restart=on-failure

[Install]
WantedBy=multi-user.target
```
```bash
sudo systemctl daemon-reload
sudo systemctl enable --now myproject
```

**方式 B：Python 后端（Django）**

```
/www/wwwroot/myproject.com/
├── frontend/          ← Vue3 前端 dist 内容
└── backend/
    ├── manage.py
    ├── venv/          ← 虚拟环境
    ├── requirements.txt
    └── 你的django代码...
```

在宝塔里跑起来（用 gunicorn + systemd）：
```bash
cd /www/wwwroot/myproject.com/backend
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
pip install gunicorn
```

```ini
# /etc/systemd/system/myproject.service
[Unit]
Description=My Django App
After=network.target

[Service]
WorkingDirectory=/www/wwwroot/myproject.com/backend
ExecStart=/www/wwwroot/myproject.com/backend/venv/bin/gunicorn myproject.wsgi:application --bind 127.0.0.1:8000
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

##### ⑤ 第 4 步：配置 Nginx（前后端统一入口）

宝塔面板 → **网站 → 你的站点 → 设置 → 配置文件**，改成：

```nginx
server {
    listen 80;
    server_name 你的域名或IP;

    # 前端：Vue3 静态文件
    root /www/wwwroot/myproject.com/frontend;
    index index.html;

    # Vue 路由刷新 404 的根治
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 后端 API：反向代理到 Java(8080) 或 Python(8000)
    location /api/ {
        proxy_pass http://127.0.0.1:8000;   # Django 用 8000，Spring Boot 用 8080
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

> 💡 Java 后端把 `proxy_pass` 改成 `http://127.0.0.1:8080`；Python 后端用 `http://127.0.0.1:8000`。

# 3. Windows 浏览器访问

#### 10.4.8 企业级安全加固（生产必做 6 条）

真实生产环境的安全做法（参考 2026 年企业级部署实战）：

1. **改 SSH 默认端口**（最重要）
   ```bash
   # 改成高位随机端口，如 32281
   sudo vi /etc/ssh/sshd_config
   # Port 32281
   sudo systemctl restart sshd
   sudo firewall-cmd --add-port=32281/tcp --permanent
   sudo firewall-cmd --reload
   # 实测：SSH 扫描次数从日均 800+ 降至 20 以内
   ```

2. **改宝塔面板端口 + 安全入口**
   - 面板设置 → 面板端口：8888 改成 39821（高位随机）
   - 面板设置 → 安全入口：设个复杂路径，如 `/mypanel2024/`
   - 命令行：`bt 8` 改端口，`bt 10` 改路径

3. **限制面板访问 IP**
   - 面板设置 → 授权 IP → 只填你公司出口 IP 或 VPN 网段
   - 学习用可填内网网段：`192.168.233.0/24`

4. **关闭无用端口**
   - 面板 → 安全 → 只保留 80、443、SSH 端口、面板端口
   - 3306（MySQL）、6379（Redis）、8000（Django）**一律不对公网开放**

5. **开启 SSH 公钥登录 + 禁用密码**
   ```bash
   sudo vi /etc/ssh/sshd_config
   # PasswordAuthentication no    # 禁用密码登录
   # PubkeyAuthentication yes      # 只允许密钥
   sudo systemctl restart sshd
   ```

6. **定期备份 + 漏洞扫描**
   - 面板 → 计划任务 → 每天 2 点打包网站 + 数据库到 /backup
   - 面板 → 软件商店 → 装"宝塔漏洞扫描"定期查
   - 企业版用户开启 WAF + 防篡改

#### 10.4.9 何时该用宝塔，何时不该用（开发要知道的取舍）

**免费版够用吗？** 个人学习、日访问 < 1000 的博客、内网测试服——**免费版完全够**；中小企业电商站、公司官网、管理后台建议买企业版（699/年起）开 WAF；金融/涉密数据**不要用宝塔**，用专业安全方案。

| 场景 | 适不适合 | 说明 |
|------|---------|------|
| 个人学习虚拟机 | ✅ 适合 | 一键搭好 LNMP 环境，学 Nginx/MySQL 比命令行直观 |
| 公司内部测试服 | ✅ 适合 | 团队多人共享，快速搭环境 |
| 阿里云/腾讯云单机生产 | ✅ 适合 | 个人站长、中小企业，免费版够用 |
| 中小企业生产 + 企业版 WAF | ✅ 适合 | 电商站、公司官网、管理后台 |
| 大厂 K8s 集群 | ❌ 不适合 | 用 Helm、Argo CD 等 GitOps 工具 |
| 国企/金融生产 | ❌ 不适合 | 安全合规要求高，宝塔第三方工具要审计 |
| 需要精细控制 Nginx/MySQL 参数 | ❌ 不适合 | 宝塔的自动化配置会覆盖手改的 |

**宝塔 vs VS Code Remote-SSH**：两者不冲突，**推荐组合用**——宝塔负责"装环境 + 监控 + 建站 + 安全"，VS Code Remote-SSH 负责"改代码 + 调试 + 终端"。

**新趋势：1Panel（开源、Docker 化）**：1Panel 是 2023 年发布的开源面板，基于 Docker 容器化、资源占用更小（~150MB vs 宝塔 200-300MB）、应用隔离更好，在技术团队和开发者中越来越流行。但宝塔在中小企业和传统运维里仍是主流。懂 Docker 的开发者可以试 1Panel。

### 10.5 实战：Django + MySQL + Vue3 项目部署（必会）

> 🏷️ ⭐ 开发必会 —— Python 后端 + Vue 前端是国内最常见的全栈组合，部署流程必须掌握
> 本节目标：在服务器上从零部署一个 Django REST API + MySQL + Vue3 前端的项目
> 整体架构和请求流转已在 10.1 讲过：浏览器 → Nginx (80) → dist 静态文件 / 反代 gunicorn(8000) → MySQL(3306)

**两条操作路线（效果一样，按你是否装了宝塔选一条）：**

| 步骤 | 路线 A：纯命令行 | 路线 B：宝塔面板（本教程重点，你后面用的方式） |
|------|-----------------|----------------------------------------------|
| 装 Nginx / MySQL | yum 安装 | 软件商店一键安装，密码自动生成 |
| 建数据库 | SQL 命令 | 数据库 → 添加数据库，填表单 |
| 传代码/dist | git/scp | 文件 → 拖拽上传，或终端 git |
| Python/gunicorn | venv + systemd（命令行） | Python 项目管理器，或同样用命令行（推荐，更可控） |
| 改 Nginx 配置 | `vi conf.d/xxx.conf` | 网站 → 设置 → 配置文件 |
| HTTPS | certbot | 站点 SSL → Let's Encrypt 一键 |

#### 10.5.2 配置 MySQL 数据库

> 🐳 **宝塔用户**：已在「数据库 → 添加数据库」建好 `mydb`/`myuser` 的，直接跳到 10.5.3，本节只需看懂 SQL 在做什么。

```bash
# 1. 查看初始 root 密码（MySQL 8 安装后自动生成一个临时密码）
sudo grep 'temporary password' /var/log/mysqld.log

# 粘贴临时密码（输时不显示字符，正常）

# 3. 改 root 密码（MySQL 8 要求密码至少 8 位 + 大小写 + 数字 + 特殊字符）

# 4. 建项目数据库和用户

CREATE USER 'myuser'@'localhost' IDENTIFIED BY 'MyPass123!';
GRANT ALL PRIVILEGES ON mydb.* TO 'myuser'@'localhost';
FLUSH PRIVILEGES;
EXIT;

# 5. 验证新用户能登录
mysql -u myuser -p
# 输 MyPass123!，进入后 SHOW DATABASES; 应该看到 mydb
```

#### 10.5.5 配置 Nginx（前后端统一入口）

配置每行什么意思已在 10.2 节讲透，这里只讲"在你机器上具体怎么落地"，分两条路线。

**第 1 步：前端文件就位**

```bash
sudo mkdir -p /www/myproject/frontend/dist /www/myproject/logs
# 把本地 npm run build 产出的 dist 内容（scp 或宝塔文件上传）放进该目录
ls /www/myproject/frontend/dist/        # 必须能看到 index.html 和 assets/ 目录
```

**第 2 步：写站点配置**

- 🐳 **宝塔路线**：网站 → 添加站点（域名填服务器 IP 或真实域名，根目录可保持默认，PHP 选纯静态）→ 站点名 → 设置 → **配置文件**，在它生成的 `server { }` 内：
  - 把 `root` 改成 `/www/myproject/frontend/dist;`
  - 照 10.2.8 模板补入 `location /`、`/api/`、`/admin/`、`/static/`、`/media/`（⚠️ location 必须写在 `server { }` 大括号**里面**，不能追加到文件末尾）
  - 点保存——宝塔会自动执行 `nginx -t` 校验并重载，语法错误会弹提示
- **命令行路线**：把 10.2.8 的完整模板写进 `/etc/nginx/conf.d/myproject.conf`（`server_name`、各路径按实际改）

**第 3 步：权限（宝塔环境 403 的头号原因）**

宝塔的 Nginx 以 `www` 用户运行，要保证它能读站点文件、能写日志目录：

```bash
sudo chown -R www:www /www/myproject/frontend/dist /www/myproject/backend/static /www/myproject/logs
sudo chmod -R 755 /www/myproject/frontend
# 命令行装的 Nginx 用户通常是 nginx：把上面的 www 换成 nginx
```

**第 4 步：检查并生效**

```bash
sudo nginx -t                 # syntax is ok + test is successful 才能继续
sudo systemctl reload nginx   # 宝塔面板保存时已自动 reload，命令行才需要手动执行
sudo tail -20 /www/myproject/logs/nginx_error.log   # 有报错先看这里（宝塔也可在 /www/wwwlogs 看）
```

> 🔑 刷新页面验证：静态资源 200、`/api/` 不通时先看 gunicorn 是否在跑（10.5.6）——出现 **502 一定是后端 8000 的问题**（没启动/崩了），不是 Nginx 配置问题。

#### 10.5.6 用 systemd 管理 gunicorn（开机自启）

> 🐳 用宝塔「Python 项目管理器」添加项目时（框架选 Django、启动方式选 gunicorn、端口 8000），面板会自动生成并托管这个服务，可跳过本小节的手写过程；但**看懂这份文件能帮你排查面板服务起不来的问题**。

```bash
sudo vi /etc/systemd/system/gunicorn.service
```

```ini
[Unit]
Description=gunicorn daemon for myproject
After=network.target mysql.service      # 等网络和 MySQL 起来后再启动本服务

[Service]
User=qyz                                # 用哪个用户跑（改成你登录的普通用户，不要用 root）
Group=qyz
WorkingDirectory=/www/myproject/backend # 项目目录（manage.py 所在目录）
ExecStart=/www/myproject/venv/bin/gunicorn \   # 虚拟环境里的 gunicorn 绝对路径
    --bind 127.0.0.1:8000 \             # 只监听本机回环地址，公网摸不到
    --workers 3 \                       # 进程数：经验值 = CPU核数×2+1
    --timeout 120 \                     # 单个请求超时秒数（导出大报表之类要调大）
    --access-logfile /www/myproject/logs/gunicorn_access.log \
    --error-logfile /www/myproject/logs/gunicorn_error.log \
    myproject.wsgi:application          # myproject 换成你的 Django 项目包名（含 wsgi.py 的那个目录）
Restart=on-failure                      # 崩了自动拉起
RestartSec=5                            # 崩溃后等 5 秒再重启

[Install]
WantedBy=multi-user.target
```

```bash
# 启用服务
sudo systemctl daemon-reload
sudo systemctl start gunicorn
sudo systemctl enable gunicorn
sudo systemctl status gunicorn        # 看到 active (running) 就是成功

# 之后改代码重启 Django 用这个命令
sudo systemctl restart gunicorn
```

#### 10.5.8 常见问题排查

| 现象 | 原因 | 解决 |
|------|------|------|
| 403 Forbidden | root 下无 index.html / `www` 用户没权限 / 配置没被加载 | 见 10.2.9 三连查：`ls` 目录、`chown -R www:www` + `chmod 755`、在宝塔站点配置里改 |
| 宝塔改了配置不生效 | 写进了 `/etc/nginx/conf.d/`，宝塔不 include 它 | 在「网站 → 设置 → 配置文件」里改，配置实际落在 `/www/server/panel/vhost/nginx/` |
| Vue 首页 404 | dist 路径不对 | 检查 Nginx `root` 路径，`ls /www/myproject/frontend/dist/` |
| Vue 刷新 404 | history 模式缺 try_files | Nginx 加 `try_files $uri $uri/ /index.html` |
| /api/ 502 Bad Gateway | Django 没起或端口错 | `systemctl status gunicorn`、`ss -tlnp \| grep 8000` |
| /api/ 404 | proxy_pass 尾斜杠把前缀剥掉了 | 见 10.2.5：Django 路由带 `/api` 就不要在结尾加 `/` |
| /api/ 跨域报错 | CORS 没配 | settings.py 加 `django-cors-headers`，`CORS_ALLOWED_ORIGINS` |
| admin 页面没样式 | collectstatic 没跑或 /static/ 路径错 | `python manage.py collectstatic`，检查 Nginx `alias` 路径和权限 |
| 上传文件 413 | 超过 Nginx 默认 1M 限制 | 加 `client_max_body_size 50M;` 后 reload |
| mysqlclient 装不上 | 缺 mysql-devel | `yum install -y mysql-devel python3-devel` |
| gunicorn 起不来 | 权限或路径 | 看 `journalctl -u gunicorn -f` 日志 |
| 数据库连不上 | 密码错或 socket 路径错 | `mysql -u myuser -p` 测试，检查 settings.py HOST 和 .env |
| 504 Timeout | Django 处理太慢 | gunicorn `--timeout 120` 加大 |

#### 10.5.9 上 HTTPS（生产必备，可选）

**🐳 宝塔路线（最简单，推荐）：**

前提：域名已备案（国内服务器）且 DNS 的 A 记录已解析到本服务器 IP。

1. 网站 → 站点设置 → **SSL → Let's Encrypt**
2. 勾选要申请的域名 → 点「申请」，宝塔自动验证、写入证书、改 Nginx 配置并开启**强制 HTTPS**（80 自动跳 443）
3. 证书 90 天到期，宝塔自带定时任务自动续签，不用管

**命令行路线（certbot）：**

```bash
# 1. 装 certbot（Let's Encrypt 免费证书，同样要求域名已解析到本机）
sudo yum install -y certbot python3-certbot-nginx

# 2. 自动申请证书并改好 Nginx 的 443 配置
sudo certbot --nginx -d your-domain.com

# 3. 验证自动续期任务（证书 90 天有效，certbot 会自动加续期定时任务）
sudo certbot renew --dry-run
```

> 💡 没有域名、只是虚拟机学习时不用上 HTTPS，用 IP + 80 端口即可。
