## 1. Linux 应用领域（了解）
> 🏷️ 📖 概念了解 —— 知道 Linux 用在哪、为什么开发要学即可

- **服务器领域（开发者最相关）**：互联网公司的 Web 服务器、数据库服务器几乎全跑在 Linux 上；阿里云/腾讯云/AWS 的默认服务器镜像也是 Linux。
- **云计算与大数据**：Docker、Kubernetes、Hadoop、Spark 等生态都构建在 Linux 之上。
- **嵌入式/移动端**：路由器、智能家居、Android 手机内核都基于 Linux（了解即可，与后端开发关系不大）。
- **桌面领域**：占比很小，不是学习重点。

**对开发者的现实意义**：后端、运维、测试岗位必备——你写的代码最终都要部署到 Linux 服务器上跑，不会 Linux 就无法独立部署和排查线上问题。国产化替代（麒麟、统信 UOS、openEuler）也都基于 Linux 内核。

## 2. Linux 概述（了解）
> 🏷️ 📖 概念了解 —— 理论背景，读懂即可

### 2.1 什么是 Linux（了解）

> 🏷️ 📖 概念了解 —— 理论背景，读懂即可
- Linux 是一个 **免费、开源的类Unix操作系统内核**
- 由 Linus Torvalds 于 1991 年开发
- 严格来说，Linux 是指 **内核（Kernel）**，而完整的操作系统发行版是 Linux 内核 + GNU 工具 + 应用软件

> 👤 **人物小传：Linus Torvalds（林纳斯·托瓦兹，1969— ）**
>
> 芬兰裔美国程序员，被称为 **"Linux 之父"**。1991 年他还是赫尔辛基大学的学生时，嫌教学用的 Minix 系统限制太多，就在网上发起了一个"业余项目"并公开源代码——这就是 Linux。当时他的留言很谦虚，大意是"做个免费的操作系统，纯属爱好，不会做得很大很专业"，而今天几乎所有服务器、安卓手机、超级计算机跑的都是它。
>
> 他还有一个开发者人人在用的作品：**Git**（2005 年为管理 Linux 内核源码而发明，就是我们提交代码用的那个 Git）。至今他仍是 Linux 内核的最终维护决策者，名言是 **"Talk is cheap. Show me the code."（废话少说，上代码）**。

**2.1.1 GNU 计划（重要背景）**

- 1983 年 Richard Stallman 发起 **GNU（GNU's Not Unix）** 计划
- 目标：创建一个完全自由的类 Unix 操作系统
- GNU 提供了大量基础工具：gcc、bash、glibc、coreutils（ls/cp/cat 等）
- 但 GNU 缺少一个核心 —— **内核**（GNU Hurd 内核开发滞后）
- 1991 年 Linus 写出 Linux 内核，正好补上了 GNU 缺失的拼图
- 因此 **完整的系统常被称为 "GNU/Linux"**

**2.1.2 GPL 协议**

- **GPL（GNU General Public License）**：Linux 内核采用的许可证
- 核心精神：**任何人都可自由使用、修改、分发，但衍生作品必须同样以 GPL 开源**
- 与 MIT、Apache、BSD 等"宽松开源协议"不同，GPL 是"传染性"的
- 这保证了 Linux 内核生态始终开源，不会被闭源商业化"吞噬"
- Linus 至今仍是 Linux 内核的最终维护决策者（通过邮件列表 review 补丁）

**2.1.3 Linux 内核版本演进（关键里程碑）**

| 年份 | 内核版本 | 重要特性 |
|------|----------|----------|
| 1991 | 0.01 | Linus 首次发布，仅支持 x86 |
| 1994 | 1.0 | 第一个正式版本 |
| 1996 | 2.0 | 对称多处理（SMP）支持 |
| 1999 | 2.2 | 更完善的 SMP、USB |
| 2001 | 2.4 | 企业级特性，支持 64 位 CPU |
| 2003 | 2.6 | 抢占式调度、巨大性能提升 |
| 2011 | 3.0 | 版本号策略调整，大量改进 |
| 2015 | 4.0 | 支持热替换内核代码 |
| 2019 | 5.0 | 全新特性累积 |
| 2022 | 6.0 | 支持 Rust 编写内核模块 |
| 2024+ | 6.x | 持续演进 |

> 查看本机内核版本：`uname -r` 或 `cat /proc/version`

### 2.3 Linux 特点（了解）
> 🏷️ 📖 概念了解 —— 理论背景，读懂即可
- **免费开源**：源代码公开，可自由修改和分发
- **多用户、多任务**：支持多个用户同时登录，同时运行多个程序
- **稳定性高**：长时间运行不崩溃
- **安全性好**：内置防火墙、权限管理
- **硬件支持广泛**：支持各种架构（x86、ARM等）
- **网络功能强大**：内置完整的TCP/IP协议栈

## 3. Linux 与 Unix（一句话背景）（了解）
> 🏷️ 📖 概念了解 —— 知道即可，不影响任何实际操作

- Unix 是 1969 年贝尔实验室诞生的老牌操作系统，Linux（1991 年）借鉴了它的设计思想，但**内核代码是 Linus 从零独立写的，没有用 Unix 源码**。
- Linux 遵循 **POSIX 标准**（一套统一的系统接口规范），所以叫"类 Unix 系统"，在 Linux 上学的命令/脚本在 macOS、各类 Unix 上也通用。
- AIX、HP-UX、Solaris、FreeBSD 都是 Unix 家族成员，开发者基本只会在老国企/银行的小型机上见到，不用深究。

### 4.2 安装步骤（了解）
> 🏷️ 📦 环境搭建 —— 跟着操作一次即可，无需记忆

1. **下载 VMware Workstation**

   - 当前下载入口已迁移至 Broadcom 支持门户（原 VMware 官网不再提供直接下载）
   - 下载入口（任选其一）：
     - Broadcom Support Portal：https://support.broadcom.com/
     - VMware 产品页：https://www.vmware.com/products/desktop-hypervisor/workstation-and-fusion
   - 下载步骤：
     1. 注册 Broadcom 基础账号（使用邮箱即可，无需企业信息）
     2. 登录后进入 "My Downloads" → "Free Software Downloads"
     3. 搜索 "VMware Workstation Pro"
     4. 选择 17.5.2 及以上版本（推荐 17.6.2 或最新稳定版）
     5. 阅读并同意用户协议 → 点击下载图标
     6. 部分版本会要求填写简单英文验证表单（仅英文，避免特殊字符）
   - 推荐版本：17.6.2

2. **安装前准备**
   - 确保 CPU 支持虚拟化技术（Intel VT-x / AMD-V）
   - 在 BIOS 中开启硬件虚拟化
   - 预留足够内存（建议至少 8GB）和磁盘空间（至少 100GB）
   - 可以参考这个做：https://jingyan.baidu.com/article/ab0b56305f2882c15afa7dda.html
   
3. **安装过程**
   ```
   步骤1：双击安装程序 .exe
   步骤2：接受许可协议 → Next
   步骤3：选择安装路径（建议非系统盘，如 D:\VMware）
   步骤4：增强键盘驱动（Enhanced Keyboard Driver）可勾可不勾
   步骤5：检查更新、用户体验计划两个勾选框都可取消
   步骤6：快捷方式按默认 → Install 开始安装
   步骤7：等待完成 → 启动时选择"个人使用"即可（无需许可证密钥）
   ```
   > 注意：安装 VMware 过程中**没有**选网络类型的步骤，NAT/桥接是以后"新建虚拟机"时才选的（见第 6 章）。

   > 注：若安装后提示 "与 vmx86 驱动程序版本不匹配"，重新运行安装包选择 "修复" 即可。

4. **硬件虚拟化开启方法**
   
   ```
   重启电脑 → 进入 BIOS (按 F2/Del/F10)
   → 找到 "Intel Virtualization Technology" 或 "AMD-V"
   → 设置为 Enabled
   → 保存并退出 (F10)
   ```

## 5. CentOS 安装

### 5.1 下载 CentOS
> 🏷️ 📦 环境搭建 —— 跟着操作一次即可，无需记忆

#### 5.1.0 CentOS 是否免费？与 RHEL 的关系（重要背景）

**结论：CentOS 完全免费**，可以自由下载、安装、商用，无需许可证。

但要理解 CentOS 的免费来源，需要先了解它与 Red Hat Enterprise Linux（RHEL）的关系：

| 项目 | RHEL | CentOS |
|------|------|--------|
| 是否免费 | ❌ 商业收费 | ✅ 完全免费 |
| 来源 | Red Hat 公司官方发布 | 社区基于 RHEL 源码重新编译 |
| 商业支持 | ✅ 提供 7×24 付费支持 | ❌ 无官方支持，靠社区 |
| 更新速度 | 优先（Red Hat 先发） | 滞后几天到几周（重新编译耗时） |
| Logo/商标 | 含 Red Hat 商标 | 去除商标，换 CentOS 自己的 |
| 软件包内容 | 与 CentOS **完全一致** | 与 RHEL **完全一致**（同源） |

- CentOS 全称 **Community Enterprise Operating System**（社区企业操作系统）
- 工作原理：Red Hat 遵守 GPL 协议，必须开源 RHEL 的源代码
- CentOS 社区拿到 RHEL 公开源码后，**去除 Red Hat 商标**（商标受法律保护，不在 GPL 范围内），重新编译成 CentOS
- 因此 CentOS 与 RHEL 在软件包层面**完全一致**，只是去掉了商标和支持服务
- 这就是 CentOS "免费"的本质：**它不是盗版，而是 GPL 协议赋予的合法权利**

#### 5.1.0.1 CentOS 的版本演变与 CentOS Stream 的出现（务必了解）

CentOS 的历史有三个关键阶段：

**阶段 1：CentOS Linux（2004-2020）—— 经典时期**
- 2004 年 CentOS 项目成立，作为 RHEL 的免费下游重建版
- 长期作为企业服务器的免费首选，稳定性与 RHEL 一致
- 版本号与 RHEL 对应：RHEL 7 → CentOS 7，RHEL 8 → CentOS 8

**阶段 2：CentOS Stream（2020 年 12 月起）—— 政策突变**
- Red Hat 公司被 IBM 收购后，2020 年 12 月宣布重大政策调整
- **CentOS 8 提前停止维护**（原计划维护到 2029，实际 2021 年底就 EOL）
- CentOS 项目重心转向 **CentOS Stream**，定位变为"RHEL 的滚动测试版"
- CentOS Stream 处于 RHEL 上游与下游之间：Fedora → CentOS Stream → RHEL
- 意味着 CentOS Stream 比 RHEL 更新更快，但**稳定性不如之前的 CentOS Linux**
- 这一变化引发了 CentOS 用户的强烈不满，社区出现了多个替代项目

**阶段 3：后 CentOS 时代（2022 至今）—— 替代品崛起**
| 替代方案 | 性质 | 维护方 | 与 RHEL 关系 |
|---------|------|--------|-------------|
| **Rocky Linux** | 重建版（与原 CentOS 理念相同） | Rocky Enterprise Software Foundation（CentOS 创始人 Gregory Kurtzer） | 1:1 兼容，下游重建 |
| **AlmaLinux** | 重建版 | CloudLinux 公司 + 社区 | 1:1 兼容，下游重建 |
| **CentOS Stream** | 滚动测试版 | Red Hat 官方 | RHEL 上游，更新快 |
| **RHEL 开发者订阅** | 官方原版 | Red Hat | 免费但限 16 节点 |

- Rocky Linux 由 CentOS 原始创始人发起，目标是**延续经典 CentOS 的定位**
- AlmaLinux 由 CloudLinux 公司支持，社区治理，目标相同
- 这两个项目都承诺长期维护，已成为 CentOS 替代的首选

#### 5.1.0.2 RHEL 现在也免费了（Red Hat Developer 订阅）
2021 年起 Red Hat 对个人开发者开放免费 RHEL 订阅：
- **免费条件**：注册 Red Hat Developer 账号（个人邮箱即可）
- **使用限制**：最多 16 个物理/虚拟节点
- **适用范围**：开发、测试、小型生产环境
- **包含支持**：开发者级别的官方支持
- 注册地址：https://developers.redhat.com/articles/2021/02/10/free-rhel-developer-subscription

**对比选择：**
- 想要 100% 兼容 RHEL 又无需注册 → Rocky Linux / AlmaLinux
- 想要官方原版 RHEL + 有限免费 → Red Hat Developer 订阅
- 学习用，习惯旧环境 → CentOS 7.9（已 EOL，仅学习）

> ⚠️ **重要提示：CentOS 7 已于 2024 年 6 月 30 日停止维护（EOL）**
> - 官方不再提供安全更新，yum 源已迁移至 vault.centos.org
> - 学习环境仍可继续使用 CentOS 7.9，**生产环境建议使用替代发行版**

- **Everything ISO**：所有软件包合集，体积最大（约 10GB），适合离线仓库

### 5.2 创建虚拟机

12. 磁盘：选择 "创建新虚拟磁盘"
13. 最大磁盘大小：建议 40GB
14. 存储为单个文件 → 下一步 → 完成

1. **挂载 ISO 镜像**

#### 5.3.1 磁盘分区（推荐手动分一次，掌握标准方案）

**① 为什么要分区？**

和 Windows 装系统分 C 盘、D 盘一个道理：把不同用途的数据放到不同区域。区别在于：

- Windows：分区出来是 `C:\`、`D:\` 这样的盘符
- Linux：**只有一棵目录树，根是 `/`**，分区要"挂"到某个目录上才能用，这个目录就叫**挂载点**（比如 `/boot` 分区挂到 `/boot` 目录）

**② 自动分区 vs 手动分区**

| 方式 | 适用场景 | 说明 |
|------|---------|------|
| 自动分区 | 学习机图省事 | 安装器自动把整个磁盘划给 `/`，一键完成 |
| 手动分区 | **推荐至少做一次** | 理解 Linux 目录结构，面试、生产都用这套方案 |

**③ 手动分区操作步骤（对照安装界面）**

```
1. 点"安装位置" → 选中磁盘 → 选"我要配置分区" → 点"完成"
2. 左上角"分区方案"下拉框 → 选"标准分区"
3. 点左下角 "+" 号 → 依次添加下面表格里的挂载点
4. 全部加完 → 点"完成" → 弹窗点"接受更改"
```

每添加一个挂载点，在右侧填两项：**期望容量** 和 **文件系统**。

**④ 推荐分区方案（20GB 学习虚拟机）**

| 挂载点 | 作用 | 建议容量 | 文件系统 |
|--------|------|---------|---------|
| `/boot` | 启动分区：存放内核和引导程序 | 1GiB | ext4 |
| `swap` | 交换分区：内存不够时临时顶上 | 2GiB | swap |
| `/` | 根分区：其余所有文件都在这里 | 剩余全部（约 17GiB） | xfs |

填容量小技巧：
- `/boot` 填 `1GiB`，`swap` 填 `2GiB`
- `/` 的期望容量**留空**，安装器自动使用剩余全部空间

为什么要这样分：
- `/boot` 单独分：即使根分区出问题，系统还能正常引导启动
- `swap`：物理内存不够时当"临时内存"用，避免程序直接被杀掉
- 剩余空间全给 `/`：新手不用纠结，够用

**⑤ 生产服务器的分区思路（了解即可）**

生产上会把"容易膨胀的目录"单独分出去，防止把根分区占满导致系统崩溃：

| 额外挂载点 | 什么时候单独分 |
|-----------|---------------|
| `/var` | 日志多的服务器（防止日志撑爆根分区） |
| `/home` | 多人共用、用户文件多 |
| `/data` | 存数据库、大数据文件等 |

**⑥ 三个相关概念（了解）**

- **文件系统**：分区里数据怎么组织存放的规则。CentOS 7 默认 **xfs**（大文件性能好），老牌 **ext4** 也很稳定，保持默认即可
- **swap 给多大**：内存 ≤ 8GB 时设成和内存一样大；> 8GB 给 8GB 即可
- **LVM（逻辑卷）**：支持在线扩容（磁盘不够了能加），生产常用；学习机用标准分区就够

> ⚠️ 分错了想重来：在分区界面点"**重置全部**"即可推倒重来，此时还没真正写入磁盘，不会丢任何东西。

#### 5.3.2 其他安装选项说明
- **KDUMP**：内核崩溃时捕获信息，学习时可关闭（省 128MB 内存），生产建议开启。
- **安全策略**：SELinux 默认 Enforcing，先保持默认（后面排障时如果被它拦，再临时设为 Permissive）。
- **软件选择**：
  - **带 GUI 的服务器**（✅ 推荐新手）：约 1500+ 包，含图形桌面 + 常用服务器工具，上手友好
  - 最小安装：仅命令行 + 基础工具（约 300+ 包），适合纯服务器或熟练后练命令

7. **开始安装**
   - 设置 root 密码（至少8位，包含大小写字母和数字）
   - 创建普通用户（可选）
   - 等待安装完成（约 20-30 分钟）

8. **安装后设置**
   - 接受许可协议
   - 完成配置 → 登录系统

## 6. 网络连接三种方式
> 🏷️ 📦 环境搭建 —— 跟着操作一次即可，无需记忆

### 6.0 "网络连接"对话框逐项详解（对照安装界面）
> 🏷️ 📦 环境搭建 —— 跟着操作一次即可，无需记忆

这个对话框出现在两个地方：
- **新建虚拟机向导** → "网络类型"这一步（即截图所示）
- **已建好的虚拟机**：`虚拟机设置 → 硬件 → 网络适配器 → 网络连接`（随时可改，不用重装）

截图中的 5 个选项，本质是在选择"虚拟机的虚拟网卡接到哪台虚拟交换机上"：

#### ① 桥接模式(B)：直接连接物理网络
- **原理**：虚拟网卡通过 **VMnet0** 虚拟交换机，直接"桥接"到宿主机的物理网卡上
- **效果**：虚拟机就像局域网里一台**独立的真实电脑**，与宿主机平级
- **IP 地址**：与宿主机同一网段（如宿主机是 `192.168.1.10`，虚拟机就是 `192.168.1.100`，例如：`192.168.1 .XXX` → **192.168.1 是网段，最后一段是主机号** ✅ `192.168.1.10` 和 `192.168.1.20`：**同一网段** ❌ `192.168.1.10` 和 `192.168.2.20`：**不同网段**），由家里/公司的路由器 DHCP 分配，或手动设置
- **通信能力**：
  - 虚拟机 → 外网：✅ 直接访问
  - 虚拟机 ↔ 宿主机：✅ 同网段互访
  - 局域网其他设备（手机、同事电脑）→ 虚拟机：✅ **可直接访问**
- **代价**：占用一个真实局域网 IP；在公司/学校网络中，可能因网管策略、WiFi 客户端隔离而无法使用
- **适用场景**：需要让局域网其他设备访问虚拟机（如用手机测试虚拟机里的网站、部署供团队访问的服务）

#### ☑ 复制物理网络连接状态(P)（复选框，仅桥接模式可用）
- **作用**：让虚拟机网卡的连接状态"跟随"宿主机的物理网卡
- **解决的问题**：笔记本在**网线 ↔ WiFi** 之间切换、或从一个无线网络移到另一个无线网络时，虚拟机网络会自动重连而不必手动处理
- **建议**：笔记本 + 桥接模式时**勾选**；台式机环境勾不勾都无所谓

#### ② NAT 模式(N)：用于共享主机的 IP 地址（默认选中，✅ 推荐）
- **原理**：虚拟机位于宿主机背后的私有虚拟网络 **VMnet8**（网段**不是固定的**：课件示例用 `192.168.100.0/24`，你的 VMware 17 可能是 `192.168.233.0`、`192.168.137.0` 等任意网段，以"编辑 → 虚拟网络编辑器 → VMnet8"里看到的为准），宿主机充当"路由器"，虚拟机访问外网时由宿主机做 **NAT 地址转换**（对外只看得到宿主机的 IP）
- **IP 地址**：由 VMware 内置 DHCP 服务自动分配（VMnet8 网段内的 x），也可手动固定
- **通信能力**：
  - 虚拟机 → 外网：✅ 经宿主机转发
  - 虚拟机 ↔ 宿主机：✅ 通过 VMnet8 虚拟网卡互访
  - 局域网其他设备 → 虚拟机：❌ **默认不能直接访问**（需要时可在"虚拟网络编辑器"里配置端口转发）
- **优点**：不占用真实局域网 IP；**换网络环境（公司/家里/咖啡店 WiFi）虚拟机零改动即可上网**
- **适用场景**：**学习、开发的默认选择**，本课件所有实验默认用它

#### ③ 仅主机模式(H)：与主机共享的专用网络
- **原理**：虚拟机连接到 **VMnet1** 私有虚拟网络（默认网段 `192.168.150.0/24`），该网络**没有 NAT 网关**，与外网物理隔离
- **通信能力**：
  - 虚拟机 → 外网：❌ **完全不能**
  - 虚拟机 ↔ 宿主机：✅ 可以
  - 多台同为仅主机模式的虚拟机之间：✅ 可以（可用来模拟纯内网）
- **适用场景**：安全实验（病毒分析、渗透靶机）、模拟隔离内网、防止实验机误连外网

#### ④ 自定义(U)：特定虚拟网络
- **原理**：手动指定虚拟机网卡连接到哪一个 VMnet（VMnet0 ~ VMnet19，可在虚拟网络编辑器中增删）
- **用途**：搭建复杂网络拓扑。例如给一台虚拟机配双网卡——一块接 VMnet8（NAT 上网），一块接 VMnet2（自定义内网）——用来做 Linux 路由器、防火墙实验
- **初学者用不到**，做进阶网络实验时才需要

#### 底部下拉框：VMnet0（自动桥接）
- 仅在选择"桥接模式"或"自定义"时可用
- **自动桥接**：VMware 自动挑选宿主机当前活动的物理网卡（插网线用有线、连 WiFi 用无线）
- 也可手动指定桥接到某一块网卡（如宿主机同时有有线和无线，强制桥接到有线网卡）

#### 三种核心模式对比总表
| 对比项 | 桥接模式 | NAT 模式 | 仅主机模式 |
|--------|----------|----------|------------|
| 对应虚拟交换机 | VMnet0 | VMnet8 | VMnet1 |
| 虚拟机 IP 来源 | 真实局域网 DHCP / 手动 | VMware DHCP（192.168.100.x） | VMware DHCP（192.168.150.x） |
| 虚拟机访问外网 | ✅ 直接访问 | ✅ 经宿主机转发 | ❌ 不能 |
| 宿主机访问虚拟机 | ✅ | ✅ | ✅ |
| 局域网其他设备访问虚拟机 | ✅ | ❌（需配置端口转发） | ❌ |
| 占用真实局域网 IP | 是 | 否 | 否 |
| 换 WiFi / 换网络环境后 | 可能要重新配 IP | 零改动 | 零改动 |
| 安全隔离程度 | 低 | 中 | 高 |
| 典型用途 | 对外提供服务 | **学习开发（默认）** | 安全实验 / 内网模拟 |

#### 三种模式生活化比喻（一看就懂）

把你的**物理路由器**想象成**小区大门**，**宿主机**想象成**你家**，**虚拟机**想象成**你想安排住处的亲戚**：

**1️⃣ 桥接模式 = 给亲戚单独办了个户口，住隔壁独立公寓**
- 亲戚（虚拟机）直接在小区里**分到一间独立公寓**，门牌号跟你家同一排（同一网段 IP）
- 小区里任何人（手机、同事电脑）都能**直接敲门找他** ✅
- 代价：占用了小区一个独立门牌号（真实局域网 IP）
- 亲戚出门办事（访问外网）直接走小区大门，跟你家无关
- **生活场景**：你开了个小卖部（部署网站），希望全小区的人都能来买东西 → 用桥接

**2️⃣ NAT 模式 = 亲戚住你家，出门用你家地址寄信**（默认推荐）
- 亲戚（虚拟机）住在你家**客房**，没有独立门牌号
- 亲戚要给外面寄信（访问外网）→ 信封上写的是**你家的地址**，邮递员只认你家（宿主机做 NAT 转换）
- 外面的人想直接找亲戚？**找不到**，因为他们只知道你家地址 ❌
- 你家内部互相串门 ✅（宿主机 ↔ 虚拟机）
- **好处**：亲戚换个小区住（你带笔记本从家到咖啡店），不用重新办户口，照常寄信
- **生活场景**：你在自己房间学 Linux、跑代码，外面没人需要主动找你 → 用 NAT（课件默认）

**3️⃣ 仅主机模式 = 把亲戚关在家里客房，不许出门**
- 亲戚（虚拟机）只能在你家**客房范围内活动**
- 不能出门办事（不能访问外网）❌
- 不能跟小区其他人打交道 ❌
- 只能跟你（宿主机）说话 ✅
- **生活场景**：亲戚在研究危险化学品（病毒分析/安全实验），你不让他接触外界，避免出事 → 用仅主机

**一句话总结**：
| 模式 | 亲戚住哪 | 能不能出门 | 外人能不能找他 |
|------|---------|-----------|---------------|
| 桥接 | 隔壁独立公寓 | ✅ 自己出门 | ✅ 直接敲门 |
| NAT | 你家客房 | ✅ 用你家地址寄信 | ❌ 找不到 |
| 仅主机 | 你家客房（锁门） | ❌ 不许出门 | ❌ 找不到 |

#### 怎么选？
- 跟着课件学 Linux、做实验 → **NAT 模式**（保持默认，直接下一步）
- 要用手机/同事电脑访问虚拟机里的网站 → **桥接模式**（笔记本记得勾"复制物理网络连接状态"）
- 做安全实验、不希望虚拟机联网 → **仅主机模式**
- 选错不怕：随时可在 `虚拟机设置 → 网络适配器` 中修改，无需重装系统

下面分别详解三种模式的原理、拓扑与配置方法。

### 6.1 桥接模式（Bridged）（了解）
> 🏷️ 📦 环境搭建 —— 跟着操作一次即可，无需记忆
- **原理**：虚拟机直接连接到物理网络，与宿主机在同一网段
- **特点**：虚拟机像网络中的独立物理机
- **优点**：可被网络中其他设备访问
- **缺点**：占用独立IP，需手动配置
- **适用场景**：服务器、需要被外部访问的场景

### 6.2 NAT 模式（网络地址转换）（了解）
> 🏷️ 📦 环境搭建 —— 跟着操作一次即可，无需记忆
- **原理**：通过宿主机的网络访问外部网络
- **特点**：虚拟机通过宿主机转发网络请求
- **优点**：自动获取IP，无需额外配置，可访问外网
- **缺点**：外部网络无法直接访问虚拟机
- **适用场景**：学习、开发、个人使用

### 6.3 仅主机模式（Host-Only）（了解）
> 🏷️ 📦 环境搭建 —— 跟着操作一次即可，无需记忆
- **原理**：虚拟机只能与宿主机通信
- **特点**：独立网络，与外部隔离
- **优点**：网络安全、隔离
- **缺点**：无法访问外部网络
- **适用场景**：安全性要求高的开发测试

### 6.3.1 三种模式网络拓扑对比（了解）
> 🏷️ 📦 环境搭建 —— 跟着操作一次即可，无需记忆
```
桥接模式:
  物理路由器(192.168.1.1)
       │
  ┌────┴────┐
  │宿主机   │ 192.168.1.10
  │虚拟机   │ 192.168.1.100   ← 与宿主机平级，占用真实网段IP
  └─────────┘

NAT 模式:
  物理路由器(192.168.1.1)
       │
  ┌────┴────┐
  │宿主机   │ 192.168.1.10   ← 唯一对外IP
  │VMnet8   │ 192.168.100.1  ← NAT 网关
  │虚拟机   │ 192.168.100.100  ← 私有网段，由宿主机转发
  └─────────┘

仅主机模式:
  ┌─────────┐
  │宿主机   │
  │VMnet1   │ 192.168.150.1  ← 虚拟交换机
  │虚拟机   │ 192.168.150.100  ← 只能与宿主机通信
  └─────────┘
  ✗ 无法访问外网
```

### 6.3.2 VMware 虚拟网络适配器
> 🏷️ 📦 环境搭建 —— 跟着操作一次即可，无需记忆
- 安装 VMware 后，宿主机的"网络连接"会多出两个虚拟网卡：
  - **VMnet1**：仅主机模式（Host-Only）的虚拟交换机
  - **VMnet8**：NAT 模式的虚拟交换机 + NAT 服务
- 桥接模式不需要专门网卡（直接桥接到物理网卡）
- 可通过 `VMware → 编辑 → 虚拟网络编辑器` 修改：
  - 子网 IP 段
  - DHCP 是否开启
  - NAT 网关 IP
- 如果 VMware 服务未启动，虚拟网络可能丢失，执行：
  ```
  Win+R → services.msc → 启动 "VMware NAT Service" 和 "VMware DHCP Service"
  ```

### 6.3.3 网络故障排查（常见）
> 🏷️ 📦 环境搭建 —— 跟着操作一次即可，无需记忆
| 现象 | 可能原因 | 解决方法 |
|------|----------|----------|
| 虚拟机 ping 不通外网 | 网关配置错/DNS 未配 | 检查 GATEWAY 和 DNS1 |
| 虚拟机 ping 不通宿主机 | 防火墙拦截 | 宿主机放行 ICMP，或临时关闭防火墙 |
| 宿主机 ping 不通虚拟机 | NAT 模式限制 | 改用桥接，或在 NAT 上做端口转发 |
| 网卡名变成 ens33 又无法联网 | ONBOOT=no | 修改 ifcfg-ens33，ONBOOT=yes |
| IP 冲突告警 | 桥接模式 IP 已被占用 | 换一个未使用的 IP |
| 重启网络失败 | 配置文件写错（IP/网关/网卡名）或与 NetworkManager 冲突 | 先看报错 `systemctl status network`；学习环境可改用 `systemctl restart NetworkManager`，不要轻易禁用/卸载它 |
| ifconfig 命令找不到 | 未装 net-tools（最小安装常见） | 先按第三章 7.1.0 修好 yum 源，再 `yum install -y net-tools` |

### 6.4 网络配置步骤
> 🏷️ 📦 环境搭建 —— 跟着操作一次即可，无需记忆

> 💡 **先别急着配！** NAT 模式默认就是 DHCP 自动获取 IP，装完系统直接 `ping www.baidu.com` 大概率已经能上网，不需要本节任何操作。只有当你**需要 IP 固定不变**（如远程连接、以后部署服务）时，才按下面配静态 IP。配之前先用 `ip addr` 和 `ip route` 记下你实际的网段和网关（第 10 章开头有详细步骤），示例里的 `192.168.100.x` 要换成你自己的网段。

**NAT 模式配置：**
```bash
# 1. 查看当前网络接口
ip addr

# 2. 查看 VMware NAT 网关设置
# VMware菜单 → 编辑 → 虚拟网络编辑器 → VMnet8 → NAT设置
# 记录子网IP，如 192.168.100.0，网关如 192.168.100.2

# 3. 配置网卡
vi /etc/sysconfig/network-scripts/ifcfg-ens33

# 修改以下内容：
BOOTPROTO=static          # 静态IP
ONBOOT=yes                # 开机启动
IPADDR=192.168.100.100    # 自定义IP（与VMnet8同网段）
NETMASK=255.255.255.0     # 子网掩码
GATEWAY=192.168.100.2     # 网关（VMnet8网关）
DNS1=114.114.114.114      # DNS服务器

# 4. 重启网络服务
systemctl restart network

# 5. 测试网络
ping www.baidu.com
```

**桥接模式配置：**
```bash
# 编辑网卡配置
vi /etc/sysconfig/network-scripts/ifcfg-ens33

# 修改为：
BOOTPROTO=static
ONBOOT=yes
IPADDR=192.168.1.100      # 与宿主机同网段
NETMASK=255.255.255.0
GATEWAY=192.168.1.1       # 宿主机网关
DNS1=192.168.1.1
DNS2=114.114.114.114

# 重启网络
systemctl restart network
```

## 8. VMware Tools 安装
> 🏷️ 📦 环境搭建 —— 跟着操作一次即可，无需记忆

### 8.1 VMware Tools 是什么、能干什么
> 🏷️ 📦 环境搭建 —— 跟着操作一次即可，无需记忆

一句话：VMware 给虚拟机装的**驱动增强包**（不装也能用，但鼠标、显示、文件互传都很别扭）。

- 剪贴板共享（宿主机 ↔ 虚拟机直接复制粘贴文字）
- 文件拖放、自适应分辨率、时间同步、增强网卡/磁盘性能
- **共享文件夹**：把宿主机的目录（如 `D:\share`）映射进虚拟机，最常用，见 8.1.2

### 8.1.1 怎么装、能不能两个都装
> 🏷️ 📦 环境搭建 —— 跟着操作一次即可，无需记忆

**两个版本，二选一：**

| | open-vm-tools（推荐） | 官方 VMware Tools |
|---|---|---|
| 来源 | 开源，VMware 自 2015 年起官方推荐，在系统 yum 源里 | VMware 官方，需挂 ISO 跑 perl 脚本 |
| 安装/更新 | `yum install` 一键装，随系统更新 | 手动挂载安装、手动重装，只有 CentOS 5/6 等极老系统才需要 |

**不能同时装**：两者是同一套东西（同一个 `vmtoolsd` 服务、同样的内核模块），同时装会报文件冲突，硬装还会导致剪贴板、共享文件夹时灵时不灵。**一台虚拟机只装一个，直接用 open-vm-tools。**

```bash
# CentOS 7 安装（-desktop 包含图形界面的剪贴板/拖放/自适应分辨率和共享文件夹挂载工具 vmhgfs-fuse）
yum install -y open-vm-tools open-vm-tools-desktop

# 启动 + 开机自启（注意服务名是 vmtoolsd，不是 open-vm-tools）
systemctl enable --now vmtoolsd

reboot
```
> 纯命令行、不装图形界面的服务器只装 `open-vm-tools` 即可；但要使用共享文件夹，需要 `open-vm-tools-desktop` 里的 vmhgfs-fuse。

**验证装好了没（在虚拟机里敲命令，三种查法都看一下）：**

```bash
# ① 查包装没装：有输出 = 已安装；啥都不显示 = 没装
rpm -qa | grep open-vm-tools
# 正常应看到两行（第二个 desktop 包是共享文件夹/剪贴板/拖放要用的）：
#   open-vm-tools-10.x.x-xxx.el7.x86_64
#   open-vm-tools-desktop-10.x.x-xxx.el7.x86_64

# ② 查服务跑没跑：看到绿色 active (running) 才是真正生效
systemctl status vmtoolsd

# ③ 查版本号（能打印出版本号 = 工具可用）
vmware-toolbox-cmd -v
```

**判断方法：**
- ①有两行 + ②是 active (running) + ③能出版本号 → 安装正常，直接用
- ①没输出 → 根本没装，回到上面 `yum install`
- ①有包但 ②显示 inactive/dead → 执行 `systemctl enable --now vmtoolsd` 启动
- 只有 `open-vm-tools` 一行、没有 `-desktop` → 共享文件夹/拖放用不了，补装：`yum install -y open-vm-tools-desktop`

> 也可以在 VMware 界面辅助确认（各版本通用）：点顶部菜单 **虚拟机(V)**——显示"**重新安装 VMware Tools**"表示已装；显示"**安装 VMware Tools**"（可点击）表示没装。

**怎么用**：剪贴板、拖放、分辨率自适应装完重启即自动生效，不需要任何操作；唯一要手动配的是共享文件夹。

### 8.1.2 共享文件夹：本地怎么设置、虚拟机里在哪看
> 🏷️ 📦 环境搭建 —— 跟着操作一次即可，无需记忆

**① 本地（宿主机）设置——在 VMware 界面操作：**

1. 虚拟机 → 设置 → 选项 → **共享文件夹** → 选"总是启用"
2. 点"添加" → 选宿主机目录（如 `D:\share`）→ 起一个**共享名**（如 `share`，虚拟机里看到的就是这个名字）

**② 服务器端（虚拟机里）查看：**

**位置固定：`/mnt/hgfs/共享名/`**（hgfs = Host Guest File System，宿主机-虚拟机文件系统）。你起的共享名叫 `share`，在虚拟机里看到的就是 `/mnt/hgfs/share/`，它对应 Windows 的 `D:\share\`。

```bash
# 图形界面：打开"文件"管理器 → 其他位置 → 计算机 → mnt → hgfs，能直接看到 share 文件夹
# 命令行：
cd /mnt/hgfs/
ls                    # 看到 share 目录
ls /mnt/hgfs/share/   # 里面就是 D:\share 里的文件
vmware-hgfsclient     # 只列出已启用的共享名（share），用于确认 VMware 侧配置已生效

# 一般装了 open-vm-tools-desktop 并启用共享后，重启一次虚拟机会自动挂载，无需下面的操作。
# 如果 /mnt/hgfs 是空的，再手动挂载（需要 root；挂到与共享名同名的子目录，方便以后加第二个共享）：
mkdir -p /mnt/hgfs/share
vmhgfs-fuse .host:/share /mnt/hgfs/share -o allow_other,uid=$(id -u),gid=$(id -g)

# 确认手动挂载能用后，想开机自动挂载，写进 /etc/fstab（先检查别重复追加）：
grep -q '/mnt/hgfs/share' /etc/fstab || \
  echo '.host:/share /mnt/hgfs/share fuse.vmhgfs-fuse allow_other,uid=1000,gid=1000,nofail,_netdev 0 0' >> /etc/fstab
mount -a              # 不重启，立即按 fstab 挂载；下次开机会自动挂
# nofail = 共享不可用时也正常开机，不卡在挂载界面；_netdev = 等网络/虚拟通道就绪后再挂
```

挂载成功后，在虚拟机里读写 `/mnt/hgfs/share/` 就等于在 Windows 上读写 `D:\share\`：**两边是同一个文件夹，任意一边新建/修改/删除文件，另一边立刻能看到，实时双向同步**。注意：只有共享目录里的内容同步；性能低于原生磁盘，适合互传文件，不建议把大项目的编译目录长期放这里。
