## 1. 帮助指令（必会）(已总结)
> 🏷️ ⭐ 开发必会 —— 软件开发日常高频使用，务必掌握

Linux 常用命令上百个，每个还有一堆参数，**没人能全记住，也不用记**。工作中的真实状态是：记得"有个 tar 能打包"，但忘了参数怎么写 → 现场查帮助 → 用完就忘，下次再查。所以这一节学的不是知识，是**"忘了去哪查"的能力**。

**一个典型的日常场景：**
> 领导让你把服务器上的日志打包发给他。你记得有 `tar` 命令，但想不起来解压/压缩参数 → 敲 `tar --help` 翻到 `-zcvf`（打包）和 `-zxvf`（解包）→ 30 秒解决。

**先记住这张"我想要什么 → 用什么查"选择表：**

| 我想…… | 用什么 | 频率 |
|--------|--------|------|
| 忘了某个参数怎么写（如 tar 的参数） | `命令 --help` | ⭐⭐⭐ 最高，80% 的情况 |
| 看完整权威说明，或查**配置文件格式**（如 fstab、passwd 各字段） | `man` | ⭐⭐ |
| 查 `cd`、`export` 这类内置命令（man 里没有独立手册） | `help` | ⭐ |
| 英文手册看不下去，只想要现成例子 | `tldr`（可选安装） | 可选 |

### 1.1 --help：日常第一选择（80% 的场景）（必会）(已总结)
> 🏷️ ⭐ 开发必会 —— 软件开发日常高频使用，务必掌握

绝大多数命令都支持 `--help`（或 `-h`），在屏幕上直接打印一份**简明帮助**：命令语法、参数列表、常用示例，看完即走，不用翻整本手册。

```bash
ls --help           # 忘了 -l -a -h 各是什么意思时
tar --help          # 最常用！tar 参数多如牛毛，谁都记不住，用前查一下
cp --help
grep --help
useradd --help
```

输出通常很长，配合管道看：
```bash
tar --help | less        # 内容太多时用 less 分页看（上下箭头翻，q 退出）
tar --help | grep -i compress   # 只看跟"压缩"有关的参数行
```

> 注意：`--help` 不是所有命令都支持（个别老命令只认 `-h` 或只认 man），但日常命令（ls/cp/mkdir/tar/grep/find……）都支持。

### 1.2 man：最权威的完整手册（必会）(已总结)
> 🏷️ ⭐ 开发必会 —— 软件开发日常高频使用，务必掌握

`man`（manual）是系统自带的**官方手册**，内容比 `--help` 全得多：不仅有每个参数的详细解释，还有使用示例、相关命令、配置文件说明。

```bash
man ls              # 打开 ls 的手册
man tar             # 学 tar 必看，里面有最权威的参数组合示例
man useradd         # 管理员命令也有手册
man find            # 查看 find 命令的官方完整手册
```

**man 手册的内部结构（打开后知道看哪几段）：**

```
NAME         一句话说明这命令是干嘛的
SYNOPSIS     语法格式（方括号 [] 里的是可选项）
DESCRIPTION  详细说明
OPTIONS      所有参数的解释 ← 你最常看的部分
EXAMPLES     使用示例（部分手册有）
FILES        相关配置文件
SEE ALSO     相关命令
```

**man 里的操作按键（和 vim 类似，都是全屏界面）：**

```
↑↓ / PgUp PgDn    上下滚动、翻页
/关键字  回车      在手册内搜索（如 /compress 找压缩相关内容）
n / N             跳到下一个 / 上一个匹配
q                 退出 man
```



### 1.3 终端快捷键与历史命令（必会）(已总结)
> 🏷️ ⭐ 开发必会 —— 每天都在用，学会后敲命令效率翻倍

查帮助解决"命令怎么写"，这节解决"怎么写得快、敲错了怎么办"。

**① 终端快捷键（高频 9 个，先练加粗的 4 个）**

| 快捷键 | 作用 | 典型场景 |
|--------|------|---------|
| **Tab** | 补全命令 / 路径 | 敲两三个字母按 Tab 自动补全；连按两下列出候选——**最重要的习惯**，还防敲错 |
| **Ctrl + C** | 中止当前命令 | ping 刷屏停不下来、程序卡死、输错想重来的**标准逃生键** |
| **Ctrl + D** | 结束输入 / 退出会话 | 等价敲 `exit`，登出终端就按它 |
| **↑ / ↓** | 逐条翻上/下一条历史命令 | 改个小参数重跑上一条命令，不用重敲 |
| Ctrl + L | 清屏 | 等价 `clear`，屏幕太乱时一键清爽 |
| Ctrl + A / E | 光标跳到**行首 / 行尾** | 敲了长命令才发现开头忘加 `sudo`：Ctrl+A 回行首补 |
| Ctrl + U / K | 删掉光标**前 / 后**的所有内容 | 密码敲错整行重来 |
| Ctrl + W | 删掉光标前**一个单词** | 长命令只错一个参数 |
| Ctrl + R（了解） | **搜索**历史命令 | 敲几个字母就带出以前用过的长命令，越用越省 |

**② 三个必会快捷键的实际效果**

```bash
# Ctrl+C：ping 一直刷屏，不想干等 —— 一键中止
ping www.baidu.com
^C                                        # 屏幕出现这个符号，就是 Ctrl+C 的痕迹

# Ctrl+R：搜历史命令（用过一次的长命令永远不用敲第二遍）
# 按 Ctrl+R 后输入几个字母，比如输 tar：
(reverse-i-search)`tar': tar -czvf logs_20260912.tar.gz /var/log/
# 回车=执行这条；Esc=只调出来不执行（还想改改）；继续按 Ctrl+R=找更早的

# Ctrl+A 补救现场：敲完发现没权限
yum install -y nginx                      # 提示 You need to be root...
# 按 Ctrl+A 跳到行首，补上 sudo 回车，不用删光重敲
```

**③ 历史命令 history**

```bash
history                    # 列出本次登录前+至今的所有命令（带编号，默认存 1000 条）
history | grep tar         # 只看用过的 tar 命令（配合 grep，找回上周敲过的长命令）

!1002                      # 重新执行编号 1002 的那条命令
!!                         # 重复上一条命令
sudo !!                    # 经典组合：上一条忘了 sudo，一键补上重跑
!$                         # 上一条命令的最后一个参数
```

```bash
# sudo !! 完整演示：
cat /etc/shadow            # 报错 Permission denied（普通用户看不了）
sudo !!                    # 自动变成 sudo cat /etc/shadow，密码验证后正常输出
```

> 💡 历史命令存在用户家目录的 `~/.bash_history` 里，退出登录时自动保存，下次登录还在——找"上周那条长命令"就靠它。
>
> ⚠️ 两个小坑：① 误按 **Ctrl+S** 终端会"假死"（屏幕没反应），其实不是死机，按 **Ctrl+Q** 解锁即可；② Ctrl+C 只能中止前台命令，中止后台跑的程序要用 kill（见第三章）。

**ls -l 输出格式解读（共 7 列，空格隔开）：**

```
drwxr-xr-x  2 root root 4096 May 10 08:30 test
    ①       ②  ③   ④   ⑤       ⑥        ⑦
```

| 列 | 例子里的值 | 含义 |
|----|-----------|------|
| ① 权限 | `drwxr-xr-x` | 文件类型 + 三组权限（10 个字符怎么读见 [6.1](#)：第 1 位 d=目录，后面属主 rwx、属组 r-x、其他人 r-x） |
| ② 硬链接数 | `2` | 有多少个硬链接指向它（目录默认 2，知道即可） |
| ③ 属主 | `root` | 文件所有者 |
| ④ 属组 | `root` | 文件所属的组 |
| ⑤ 大小 | `4096` | 字节数（普通文件才准；目录固定显示 4096，不代表里面内容大小）。加 `-h` 显示成 4.0K |
| ⑥ 修改时间 | `May 10 08:30` | 最后一次修改的日期时间 |
| ⑦ 文件名 | `test` | 名字；`l` 开头的软链接这列会显示 `链接名 -> 真实路径` |

### 2.6 cp — 复制文件/目录（必会）(已总结)
> 🏷️ ⭐ 开发必会 —— 软件开发日常高频使用，务必掌握

基本语法：`cp [选项] 源文件 目标`。**新手 90% 的困惑来自"目标存不存在、是文件还是目录"**——同一个命令，目标状态不同，结果完全不一样。

**2.6.1 复制单个文件（4 种情况，必须看懂）**

先造测试文件：cat  > a..txt   输入后ctrl +d

```bash
# 情况1：目标不存在 → 复制并改名（相当于"另存为"）
cp a.txt b.txt         # 当前目录没有 b.txt → 新建 b.txt，内容和 a.txt 一样

# 情况2：目标是一个已存在的文件 → 覆盖它（危险，默认不提示！）
cp a.txt b.txt         # b.txt 已存在 → b.txt 原内容被覆盖，无确认提示

# 情况3：目标是一个已存在的目录 → 复制进这个目录，文件名不变
mkdir backup           #创建在当前文件夹下
cp a.txt backup/       # backup/ 是目录 → 得到 backup/a.txt（注意末尾的 / 是好习惯）

# 情况4：目标是一个不存在的目录（末尾带 / 但目录不存在）→ 报错
cp a.txt notexist/     # cp: cannot create regular file 
```

> ⚠️ 对比 Windows：Windows 复制会弹窗问"是否替换"，**Linux 的 cp 默认直接覆盖、一声不吭**。养成两个习惯：重要复制加 `-i`（覆盖前询问），目标目录路径末尾写 `/` 表明你想放进去。

**2.6.2 复制整个文件夹**

**必须加 -r**

```bash
cp dir1 dir2              # ❌ 报错：cp: omitting directory 'dir1'（cp 默认不复制目录）
cp -r dir1 dir2           # ✅ -r = recursive 递归，目录连同里面所有东西一起复制
```

复制目录时，目标目录存不存在又是两种结果：

```bash
# dir2 不存在 → 整个 dir1 复制一份并改名为 dir2
cp -r dir1 dir2           # 得到 dir2/，里面内容和 dir1 一样

# dir2 已存在（是目录）→ dir1 整个被放进 dir2 里面
cp -r dir1 dir2           # 得到 dir2/dir1/（多套了一层！这是最常见的意外）
```

**2.6.3 常用选项**

| 选项 | 作用 | 什么时候用 |
|------|------|-----------|
| `-r` / `-R` | 递归复制目录 | 复制目录必加 |
| `-a` | 归档模式 = `-dR --preserve=all`，**原样复制**（保留权限、属主、时间戳、软链接） | 备份、复制配置目录的首选，比 `-r` 更"原汁原味" |
| `-p` | 保留修改时间和权限（preserve） | 只复制文件但想保留原属性 |
| `-i` | 覆盖前询问（interactive） | 怕覆盖错时加，回答 y 才覆盖 |
| `-n` | 已存在的文件不覆盖（no-clobber） | 批量复制时保护已有文件 |
| `-f` | 强制覆盖（force） | 脚本里用 |
| `-v` | 显示复制过程（verbose） | 复制大量文件时看进度 |
| `-u` | 只复制比目标新的文件（update） | 增量备份、同步目录 |

```bash
# 实际高频组合
cp -a /etc/nginx /etc/nginx.bak          # 改配置前先原样备份整个目录
cp -rv project/ /backup/                  # 递归 + 显示过程
cp -u *.log /backup/logs/                 # 只备份更新过的日志

# 一次复制多个文件到目录（最后一个参数必须是已存在的目录）
cp a.txt b.txt c.txt backup/              # 三个文件都进 backup/
cp *.conf /etc/nginx/conf.d/              # 通配符：所有 .conf 复制过去
```

> 💡 **`-a` vs `-r`**：日常复制自己的文件用 `-r` 够了；**复制系统配置、做备份用 `-a`**——否则文件的属主、权限、时间戳会变成你当前用户的，可能导致服务起不来。

### 2.7 rm — 删除文件/目录（必会）(已总结)
> 🏷️ ⭐ 开发必会 —— 软件开发日常高频使用，务必掌握

**2.7.1 基本用法**

```bash
rm file.txt               # 删除单个文件（默认直接删，不提示）
rm a.txt b.txt c.txt      # 一次删多个
rm *.log                  # 通配符：删除当前目录所有 .log
```

**2.7.2 为什么删除目录必须加 -r？**

```bash
rm mydir                  # ❌ rm: cannot remove 'mydir': Is a directory
rm -r mydir               # ✅ 递归删除：目录 + 里面所有子目录和文件
```

和 cp 一样，r = recursive。Linux 认为"删掉一个装着东西的文件夹"是重大操作，**必须显式声明"我知道里面有东西，连着一起删"**。

| 选项 | 作用 |
|------|------|
| `-r` / `-R` | 递归删除目录及其内容 |
| `-f` | 强制删除（force）：不提示、文件不存在也不报错 |
| `-i` | 每个文件删除前都询问确认（interactive） |
| `-v` | 显示删除过程 |
| `-rf` | 递归 + 强制（最常用，也最危险） |

```bash
rm -rf mydir              # 删目录的标准写法，不问不报错
rm -i important.txt       # 谨慎删除：rm: remove regular file 'important.txt'?  按 y 确认
rm -f /tmp/notexist.tmp   # 文件不存在也不报错（脚本里常用，保证脚本能继续跑）
```

**2.7.3 🚨 安全红线（rm 是 Linux 上闯祸最多的命令）**

**Linux 的 rm 不进回收站，删了就是删了，没有"撤销"。** 以下几条务必记住：

```bash
# ① 永远不要在没看清当前路径时执行带通配符的 rm -rf
cd /opt/myapp/logs        # 先 cd 进去、pwd 确认、ls 看一眼，再删
rm -rf *.log              # 确认无误才执行

# ② 这些写法极度危险，看到就要警惕：
rm -rf /                  # 自杀命令：删除整个系统所有文件（新版 rm 有保护，加 --no-preserve-root 才真执行，但别试）
rm -rf $VAR/              # 变量为空时变成 rm -rf /，会删全盘！
rm -rf /*                 # 同理

# ③ 路径开头的空格会要命
rm -rf / tmp/x            # 看起来想删 /tmp/x，实际系统解析成删 / 和 tmp/x 两个目标！
```

### 2.8 mv — 移动 / 重命名（必会）(已总结)
> 🏷️ ⭐ 开发必会 —— 软件开发日常高频使用，务必掌握

mv = move，但它身兼两职：**在同一个目录里 = 重命名；跨目录 = 移动**。一条命令搞定，没有单独的 rename 命令（Windows 是改名和剪切分开的）。

```bash
# ① 在同一个目录 → 重命名（目标不存在时）
mv oldname.txt newname.txt     # 文件改名
mv olddir newdir               # 目录改名（不需要 -r！）

# ② 跨目录 → 移动（目标是已存在的目录时）
mv file.txt /aaa     这个分两种情况: 1.如果aaa存在，那么就会把file.txt放到aaa文件夹。 2.如果原来aaa文件夹不存在，就相当于给file.txt重命名为aaa,并移动到/根目录下面。含义不同。
其实情况2就相当于移动的同时改名
mv file.txt /tmp/newname.txt   # 移动的同时改名

mv file.txt /home/111/aaa/  把文件移动到/home/111/aaa/，不是根目录你要写好绝对路径，mv file.txt /aaa/的意思是移动到根目录下面的aaa，不是/home/111/aaa/下面的aaa文件夹,  第二个/明确告诉命令： 这东西必须是【目录】


mv a.txt b.txt c.txt /tmp/     # 多个文件移动到目录（最后一个参数是目录）
mv *.log /var/log/archive/     # 通配符批量移动
```



**目标已存在时的行为（和 cp 一样容易踩坑）：**

```bash
mv a.txt b.txt        # 目标存在时,b.txt 已存在 → b.txt 被覆盖，无提示！
mv dir1 dir2          # dir2 已存在且是目录 → dir1 整个移进 dir2/ 里面（变 dir2/dir1）
                         # dir2 不存在 → dir1 直接改名为 dir2
```

| 选项 | 作用 |
|------|------|
| `-i` | 覆盖前询问（推荐重要操作加） |
| `-f` | 强制覆盖 |

### 2.14 通配符与特殊字符（必会）(已总结)
> 🏷️ ⭐ 开发必会 —— 软件开发日常高频使用，务必掌握

通配符由 **Shell（bash）在命令执行前自动展开**，不是命令本身的功能。你敲 `ls *.txt`，bash 会先把 `*.txt` 替换成所有匹配的文件名，再交给 ls。

**2.14.1 三个基本通配符**

| 符号 | 匹配 | 例子 |
|------|------|------|
| `*` | 任意个任意字符（含 0 个） | `*.log` 所有日志；`a*` 以 a 开头 |
| `?` | **恰好一个**任意字符 | `data?.log` 匹配 data1.log 但不匹配 data10.log |
| `[...]` | 括号里任意一个字符 | `file[abc].txt` 匹配 filea/fileb/filec |

```bash
ls *.txt                    # 所有 .txt 文件
ls data?.log                # data1.log, data2.log（不含 data10.log）
ls [0-9]*                   # 以数字开头的文件（[] 里可以写范围 a-z、0-9）
ls [!a]*                    # 不以 a 开头（! 表示非，bash 里 ^ 也可以）
ls file[123].conf           # file1.conf、file2.conf、file3.conf
rm *.log.[1-5]              # 删除 .log.1 到 .log.5
```

> ⚠️ **通配符匹配不到文件时会原样传递**：目录里没有 .txt，`ls *.txt` 会把字面量 `*.txt` 传给 ls，报 `No such file`。另外 `*` **默认不匹配以点开头的隐藏文件**，要看隐藏文件得显式写 `.*`。

**2.14.2 其他高频特殊符号**

| 符号 | 作用 | 例子 |
|------|------|------|
| `~` | 当前用户家目录 | `cd ~` 回家；`ls ~lisi` lisi 的家目录 |
| `{a,b,c}` | 花括号展开：生成多个参数 | `mkdir -p /data/{logs,conf,bin}` 一次建 3 个目录 |
| `{1..5}` | 生成序列 | `touch file{1..5}.txt` 建 file1~file5 |
| `;` | 顺序执行多条命令（不管成败） | `cd /tmp; ls` |
| `&&` | 前一条成功才执行后一条 | `make && make install` |
| `\|\|` | 前一条失败才执行后一条 | `ping -c1 host \|\| echo "不通"` |
| `\` | 转义符：让特殊字符变回普通字符 | `echo "价格是 \$100"` |


### 2.15 重定向与管道（必会）ccc注:必会nm呢?,还真是必会,我错了哥,我先简单掌握一下,考完了来还愿
> 🏷️ ⭐ 开发必会 —— Shell 自动化的核心，务必吃透

**先搞懂两个词到底什么意思：**

| 词 | 大白话 | 符号 | 类比 |
|----|-------|------|------|
| **重定向** | 把命令的**输入/输出**从"默认位置"改到"你指定的地方" | `>` `>>` `<` `2>` | 本来要喊给老板听的话（默认屏幕），改写到纸上（文件）递过去 |
| **管道** | 把前一个命令的**输出**直接当成后一个命令的**输入**，串起来形成流水线 | `|` | 第一道工序的半成品直接传给第二道，不用中间落地 |

#### 2.15.1 先理解：每个命令都有"两个输出"

Linux 里每条命令运行时有三条数据流，各有编号：

| 编号 | 名字 | 默认去哪 |
|------|------|---------|
| 0 | 标准输入 stdin | 键盘 |
| 1 | 标准输出 stdout（**正常结果**） | 屏幕 |
| 2 | 标准错误 stderr（**报错信息**） | 屏幕 |

关键：**正常输出和报错虽然都显示在屏幕上，但走的是两条不同的通道**，所以可以分别重定向。

**用编号控制重定向（核心对照表）：**

| 写法 | 等价写法 | 意思 | 正常结果去哪 | 报错去哪 |
|------|---------|------|-------------|---------|
| `>` | `1>` | 只重定向**正常结果**（编号 1）到文件 | 文件 | 屏幕 |
| `2>` | — | 只重定向**报错信息**（编号 2）到文件 | 屏幕 | 文件 |
| `> 文件 2>&1` | — | 报错跟着正常结果走，合一起进文件 | 文件 | 同一个文件 |
| `&> 文件` | — | 上一条的简写（bash 才支持） | 文件 | 同一个文件 |
| `> /dev/null 2>&1` | — | 正常和报错全丢黑洞，屏幕干净 | 消失 | 消失 |

> ⚠️ 注意：`2` 和 `>` 之间**不能有空格**！写成 `2 >` 会报错。`2>&1` 也要连写，不能写成 `2> &1`。

#### 2.15.2 输出重定向符（把结果写进文件而不是屏幕）ccc注:什么玩意

```bash
# ⚠️ 第一步：准备测试目录（这步只建空目录，里面还没有任何文件！）
mkdir -p /tmp/redir_test && cd /tmp/redir_test

# ========== 下面每跑一条，redir_test 里就会多出一个文件 ==========

# ① > 覆盖：把 ls 结果写进 out.txt，每次跑都覆盖，文件里只剩最后一次的结果 ccc注:要掌握
ls /etc > out.txt               # 跑这条 → redir_test 里出现 out.txt，内容是 /etc 的文件列表
date > out.txt                  # 再跑一次 → out.txt 原内容没了，只剩一行日期（这就是"覆盖"）

# ② >> 追加：每次在末尾加一行，不覆盖（日志本就是这么积累出来的） ccc注:要掌握
date >> log.txt                 # 跑 1 次 → 出现 log.txt 有 1 行日期；跑 3 次就有 3 行
echo "部署完成" >> log.txt      # 末尾又加一行，之前的内容还在

# ③ 2> 只收报错：正常结果还打屏幕，报错进文件（2 和 > 之间不能有空格）
ls /etc /不存在的目录 2> err.log   # 跑这条 → redir_test 里出现 err.log，里面是 "No such file"
cat err.log                      # 验证：里面只有报错信息，没有正常结果

# ④ 正常和报错分别存两个文件
ls /etc /不存在 > out.log 2> err.log   # 跑这条 → 同时出现 out.log 和 err.log

# ⑤ 2>&1 正常和报错都进同一文件（⭐ 最常用，见下方详解）
ls /etc /不存在 > all.log 2>&1    # 跑这条 → 出现 all.log，里面既有文件列表又有报错

# ⑥ &> 简写：效果同 ⑤，bash 才支持（老的 /bin/sh 脚本不支持，会报错）
ls /etc /不存在 &> all.log

# ⑦ 全丢弃：程序照常跑，但屏幕和文件都不留痕（/dev/null 是"黑洞设备"）
ls /etc > /dev/null 2>&1        # 跑这条 → redir_test 里不会出现新文件，输出全被黑洞吞了
```

**总结：先跑"准备"那条（空目录），再逐条往下跑，每跑一条就用 `ls` 看 redir_test 里多了什么。跑完清理：`rm -rf /tmp/redir_test`**

**7 种写法对照表（看完直接会用）：**

| 想做什么 | 怎么写 | 文件结果 |
|---------|-------|---------|
| 正常结果覆盖写 | `ls > a.txt` | a.txt 里是 ls 的输出 |
| 正常结果追加写 | `echo "xx" >> log` | 末尾加一行，之前内容保留 |
| 只抓报错 | `命令 2> err.log` | err.log 放报错，正常结果仍打屏幕 |
| 正常+报错分开存 | `命令 > out 2> err` | 两个文件各放各的 |
| 正常+报错合一起 | `命令 > all 2>&1` | all.log 里全都有（最常用） |
| 简写合一起 | `命令 &> all` | 同上，bash 限定 |
| 啥都不要 | `命令 > /dev/null 2>&1` | 全丢黑洞，屏幕干净 |

**`2>&1` 到底什么意思（面试常问、新手最懵）：**

从右往左读：
- `2>` = 重定向标准错误（编号 2）
- `&1` = 指向"标准输出当前去的地方"（& 表示后面跟的是文件描述符编号，不是文件名 1）

所以 `> all.log 2>&1` = "先让正常输出去 all.log，再让报错也跟着去 all.log"。

> ⚠️ **顺序不能反**！`2>&1 > file` 的意思是"先让错误跟着当时的输出走（当时还是屏幕），再把输出改到文件"，结果错误仍打在屏幕上。**记忆：`> 文件 2>&1`，文件在前。**

```bash
# 实战：后台跑脚本，日志全收进文件，屏幕什么都不显示
./deploy.sh > /tmp/deploy.log 2>&1

# 实战：只想要报错，正常结果丢掉
find / -name "*.conf" 2>/dev/null        # 2>/dev/null 极高频：过滤掉一堆 Permission denied

# 实战：完全不要任何输出（脚本里安静执行）
systemctl restart nginx > /dev/null 2>&1
```

#### 2.15.3 输入重定向

> 为什么 `>` 朝右、`<` 朝左？**箭头指向谁，谁就是数据要去的"终点"**：
>
> - `命令 > 文件`：输出本来去屏幕，改去文件 → 箭头指向**文件**（终点是文件）
>   
>   ```
>   默认：命令 ──(输出)──▶ 屏幕
>   重定：命令 ──(输出)──▶ 文件    ← 箭头朝右，指向终点
>   ```
> - `命令 < 文件`：输入本来来自键盘，改来自文件 → 箭头指向**命令**（终点是命令）
>   ```
>   默认：键盘 ──(输入)──▶ 命令
>   重定：文件 ──(输入)──▶ 命令    ← 箭头朝左，指向终点（命令）
>   ```
>
> 一句话记：**箭头朝哪，数据往哪流。**

```bash
command < file          # 让命令从 file 读输入，而不是键盘
mysql -uroot -p < backup.sql          # 把 SQL 文件灌进数据库
wc -l < /etc/passwd                   # 统计行数（注意这种写法不显示文件名）

# Here Document（多行输入，写配置/自动应答时用）
command << EOF
第一行输入
第二行输入
EOF
mysql -uroot -p密码 testdb <<'EOF'    # 配合 heredoc 直接执行多条 SQL
CREATE TABLE t (id INT);
SHOW TABLES;
EOF
```

#### 2.15.4 管道符 | —— 把前一个命令的输出喂给后一个命令

> 为什么叫"管道"?你可以把它理解成一根**连接两个命令的水管** —— 前一个命令生产的数据顺着这根水管直接流进后一个命令,**中间不落地、不存文件**,速度极快。

```
命令1 | 命令2 | 命令3 ...
       前一个的 stdout(输出) → 后一个的 stdin(输入)
```



```bash
cat bbb.txt | grep -nv "itheima"  #将cat bbb.txt的结果，作为grep命令的输入，用来过滤`itheima`关键字  (/home/zyc/demo1)
ls -l | grep ".txt"           # 只看含 .txt 的行
ps aux | grep java            # 找 java 进程
cat access.log | wc -l        # 统计日志行数（cat 可省略，直接 wc -l < file）
history | grep ssh            # 从历史命令里找用过的 ssh
ifconfig | grep inet          # 只看 IP 那几行
```

0

**管道 + 重定向组合（经典写法）：**

```bash
# 查日志里的 500 错误，去重统计，取前 10，存到文件
grep " 500 " access.log | awk '{print $7}' | sort | uniq -c | sort -rn | head -10 > top500.txt
```

> ⚠️ **管道默认只传 stdout，不传 stderr**。想让报错也进管道：`command 2>&1 | grep xxx`。管道不会自动把结果写文件，要存盘就在整条链最后加 `> 文件`。

## 4. 查找指令（必会）
> 🏷️ ⭐ 开发必会 —— 软件开发日常高频使用，务必掌握

### 4.1 find — 文件系统查找（必会）
> 🏷️ ⭐ 开发必会 —— 递归遍历目录找文件,功能最强但速度稍慢

#### 基本语法
```
find [搜索范围] [选项]
```

#### 选项说明

| 选项 | 功能 | 开发高频度 |
|------|------|-----------|
| `-name <文件名>` | 按文件名查找(支持通配符 `*` `?`,要加引号) | ⭐⭐⭐ 最高频 |
| `-type <类型>` | 按文件类型找(`f`=普通文件,`d`=目录,`l`=软链接) | ⭐⭐ 常用 |
| `-size <大小>` | 按大小找(`+`大于,`-`小于,无符号=等于;单位:`k`/`M`/`G`) | ⭐⭐ 清磁盘 |
| `-mtime <天数>` | 按修改时间找(`+`N天前,`-`N天内) | ⭐⭐ 清旧日志 |
| `-exec <命令> {} \;` | 找到后对每个文件执行命令(见下方详解) | ⭐⭐ 批量操作 |
| `-maxdepth <层数>` | 限制搜索深度(只查第一层写 1) | ⭐ 偶尔 |
| `-user <用户名>` | 按属主查找 | 了解即可 |

> 💡 全盘搜索加 `2>/dev/null` 把无权限报错扔掉;`-name` 里的通配符(`*.conf`)一定要加引号,否则 bash 会先在当前目录展开。

#### 应用实例

```bash
# 案例1:按文件名 - 找 /home 下的 hello.txt
find /home -name "hello.txt"

# 案例2:按类型 - 只找目录
find /var -type d

# 案例3:按大小 - 找整个系统下大于 200M 的文件(+n 大于,-n 小于,n 等于)
find / -type f -size +200M 2>/dev/null    

# 案例4:按时间 - 清理 7 天前的旧日志
find /var/log -name "*.log" -mtime +7 -delete

# 案例5:找到后执行命令 - 批量给 .sh 加执行权限
find /opt -name "*.sh" -exec chmod +x {} \;
# {} = 当前找到的文件占位符,\; = 命令结尾(必须转义)
```

### 4.2 locate — 数据库快速查找（了解）
> 🏷️ 📖 概念了解 —— 比 find 快得多,但结果取决于数据库更新是否及时

locate 用**提前建立的文件路径数据库**来查找,不是实时遍历磁盘,所以秒出结果。但数据库不会自动更新,**新建的文件可能搜不到**,需要手动 `updatedb`。

#### 基本语法
```
locate 搜索文件
```

#### 特别说明
第一次运行前必须用 `updatedb` 创建数据库;系统默认每天自动更新一次。

#### 应用实例
```bash
# 第一次运行:创建 locate 数据库(需要 root 权限)
sudo updatedb

# 案例1:快速定位 hello.txt 所在目录
locate hello.txt
# 输出:/home/user/hello.txt

# 案例2:按后缀找(加引号)
locate "*.conf"
```

> � 开发日常**优先用 find**(实时、结果一定对),locate 只在全盘搜文件名、要求速度时用。find 找不到 `locate` 还能找到、反过来也成立 —— locate 搜不到刚新建的文件,但 find 能。

### 4.3 which — 查找命令位置（必会）
> 🏷️ ⭐ 开发必会 —— 软件开发日常高频使用，务必掌握

#### grep

**① 为什么要学 grep？**

排障 80% 是从"搜"开始的：日志里找报错、项目里找函数在哪调用、配置里找参数、进程列表里找服务。find 负责找文件，grep 负责找内容——它是 Linux 下的"万能筛子"，配合管道能过滤任何命令的输出。

**② 命令格式与常用选项**

```
grep [选项] "关键词" 文件
grep [选项] "关键词"   # 不写文件名 = 从管道读，如 ps aux | grep nginx
```

1

| 选项 | 作用 | 助记 |
|------|:----:|------|
| `-i` | 忽略大小写 | ignore-case |
| `-n` | 显示行号（定位日志必备） | number |
| `-r` | 递归搜索整个目录 | recursive |
| `-v` | 反向匹配：显示**不含**关键词的行 | invert |
| `-c` | 统计匹配的行数 | count |
| `-l` | 只列出包含关键词的**文件名** | list |
| `-w` | 整词匹配（error 不会匹配 errors） | word |
| `-A n` / `-B n` / `-C n` | 显示匹配行**后/前/前后** n 行 | After / Before / Context |
| `-o` | 只输出匹配到的片段，不输出整行 | only-matching |
| `-E` | 扩展正则（`\|` `()` `{}` 不用加转义） | extended |
| `-q` | 不输出任何内容，只返回"找到没有"（脚本判断用） | quiet |

**③ 基本用法（拿 a.txt 走一遍就懂）**

先准备一个测试文件（多行写入的 heredoc 写法见 2.9 节）：

```bash
cat > a.txt 
2026-09-12 10:00:01 INFO  service started
2026-09-12 10:00:05 ERROR db connect failed
2026-09-12 10:00:09 WARN  retrying
2026-09-12 10:01:00 ERROR timeout after 30s
2026-09-12 10:02:00 INFO  error count 2

```

最基本的用法：把含 ERROR 的行筛出来

```bash
grep "ERROR" a.txt
```

输出（只显示包含 ERROR 的行，其他行全部丢掉）：

```
2026-09-12 10:00:05 ERROR db connect failed
2026-09-12 10:01:00 ERROR timeout after 30s
```

再配合最常用的 4 个选项，各跑一遍看区别：

```bash
grep -n "ERROR" a.txt    # 过滤出来加行号，方便回日志里定位：输出前面多出 2: 4:
grep -i "error" a.txt    # 忽略大小写：连第 5 行的小写 error 也能匹配到
grep -v "INFO" a.txt     # 反向过滤：不含 INFO 的行才显示（剩 2、3、4 行）
grep -c "ERROR" a.txt    # 只输出一个数字 2：统计有 ERROR 的行数
```

#### 4.3.1 上下文与正则（调试日志最常用）
```bash
# 显示匹配行的上下文（极其有用！）
grep -A 3 "ERROR" a.txt          # 匹配行 + 后 3 行（After）
grep -B 3 "ERROR" a.txt          # 匹配行 + 前 3 行（Before）
grep -C 3 "ERROR" a.txt          # 匹配行 + 前后各 3 行（Context）

# 只输出匹配到的片段（-o），配合正则从日志里"抠"内容
grep -oE "[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+" access.log   # 抠出所有 IPv4 地址（-E 支持 + 号）

# 排除多个模式
grep -vE "DEBUG|TRACE|INFO" log.txt   # 只看 ERROR/WARN

# 递归搜代码时限定/排除文件类型（开发极高频）
grep -rn "TODO" --include="*.py" /opt/myproject/
grep -rn "ERROR" --exclude-dir=node_modules --include="*.log" .
```

**正则速查表（grep 够用这 5 个）**

| 符号 | 含义 | 示例 |
|------|------|------|
| `^` | 行首 | `grep "^error"` 以 error 开头的行 |
| `$` | 行尾 | `grep "error$"` 以 error 结尾的行 |
| `.` | 任意单个字符 | `grep "e.ror"` e 和 ror 中间随便一个字符 |
| `*` | 前一个字符重复 0 次或多次 | `grep "go*gle"` ggle/gogle/google 都匹配 |
| `[abc]` | 方括号里任选一个字符 | `grep "[eE]rror"` 同时匹配 error/Error |

> 💡 更复杂的正则（`|` `()` `{}` `+`）记得加 `-E` 就行,需要时 `man grep`。

**⑥ 实战场景速查**

| 场景 | 命令 |
|------|------|
| 日志里找今天的报错 | `grep "2026-09-12" app.log \| grep -i error` |
| 看报错前后几行定位原因 | `grep -C 5 "NullPointerException" app.log` |
| 项目里找函数在哪定义/调用 | `grep -rn "def send_email" --include="*.py" .` |
| 搜代码时排除无关目录 | `grep -rn "TODO" . --exclude-dir={node_modules,.git}` |
| 统计报错出现了多少行 | `grep -c "ERROR" app.log` |
| 提取日志里所有 IP | `grep -oE "[0-9]{1,3}(\.[0-9]{1,3}){3}" access.log` |
| 查进程并过滤 grep 自己 | `ps aux \| grep nginx \| grep -v grep` |
| 找配置项在哪个文件 | `grep -rn "listen" /etc/nginx/` |

**⑦ 常见坑**

```bash
# 坑1：ps aux | grep java 结果里总有一行 grep 自己
# 原因：grep 进程自己的命令行也含 "java"，也被匹配上了
ps aux | grep java | grep -v grep   # 标准解法：再 grep -v 排除掉
pgrep -a java                       # 更省事的替代品：直接按名字查进程

# 坑2：-c 统计的是"行数"不是"次数"（一行出现 3 次也算 1）
grep -c "error" app.log             # 有 error 的行数
grep -o "error" app.log | wc -l     # 真正的出现次数

# 坑3：搜目录忘加 -r → 报错 "Is a directory"
grep -r "listen" /etc/nginx/        # 查目录内容必须 -r

# 坑4：关键词有空格/特殊字符必须加引号
grep "connection refused" app.log   # 有空格 → 双引号包住
grep '$PATH' file.txt               # 含 $ 等特殊字符 → 单引号防止被 shell 展开
```

> 💡 **脚本里用 grep 做判断**:`if grep -q "SUCCESS" log; then ... fi` — `-q` 静默模式,只返回"找到没"的退出码,不打印内容。

### 4.3.2 文本处理辅助工具（sort / uniq / cut）（必会）(文本三剑客)
> 🏷️ ⭐ 开发必会 —— 日志统计三剑客:sort + uniq + cut,开发岗常备

```bash
# sort - 排序,第一个内容排序
sort file.txt                         # 默认按字典序
[zyc@mycentos demo1]$ sort a.txt
1.2026-09-12 10:00:01 INFO  service started
3.2026-09-12 10:00:09 WARN  retrying
4.2026-09-12 10:00:05 ERROR db connect failed
61.2026-09-12 10:01:00 ERROR timeout after 30s
7./mnt
9.2026-09-12 10:02:00 INFO  error count 2

sort -n file.txt                      # -n 按数字排序(避免 "9 > 100" 的字典序错误)
[zyc@mycentos demo1]$ sort -n a.txt
1.2026-09-12 10:00:01 INFO  service started
3.2026-09-12 10:00:09 WARN  retrying
4.2026-09-12 10:00:05 ERROR db connect failed
7./mnt
9.2026-09-12 10:02:00 INFO  error count 2
61.2026-09-12 10:01:00 ERROR timeout after 30s

sort -rn file.txt                     # -r 倒序(统计 Top N 必用)
sort -t: -k3 -n /etc/passwd           # -t: 用冒号分隔,-k3 按第 3 列数字排序

# uniq - 去重(**必须先 sort,否则不相邻的重复行去不掉**)
sort file.txt | uniq                  # 去重
sort file.txt | uniq -c               # -c 去重并显示每行出现次数(最常用)
sort access.log | uniq -c | sort -rn | head  # 访问量 Top 10 IP

# cut - 按分隔符截取列(比 awk 简单,但只能按单字符分隔)
cut -d: -f1 /etc/passwd               # -d: 用冒号分隔,-f1 取第 1 列(awk 能替代,但 cut 更直观)
[zyc@mycentos demo1]$ cut -d- -f1 a.txt
2026
2026
2026
2026
2026
/mnt

```

> 💡 最高频组合:`grep + sort + uniq -c + sort -rn + head` —— 日志统计 Top N 永远是这条流水线。其他工具(tr、paste、column、join、rev)日常基本不用,需要时查 man。

**实战:统计 Nginx 日志中访问量前 10 的 URL**
```bash
# access.log 第 7 列是请求 URL(GET /path HTTP/1.1 的中间段)
awk '{print $7}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head
# 拆解:取 URL 列 → 排序 → 去重计数 → 按数量倒序 → 取前 10
```

### 4.4 sed — 流编辑器（必会）
> 🏷️ ⭐ 开发必会 —— 批量改配置、改日志必用，掌握 3 个用法就够

sed 是"流编辑器"，按行处理文本。**开发岗只需要会 3 件事**：替换、删除、插入。

```bash
# ① 替换（最高频，95% 的场景就用这个）
sed 's/old/new/' file.txt           # 把每行第一个 old 换成 new
sed 's/old/new/g' file.txt          # g = global，换掉每行所有的 old
sed -i 's/old/new/g' file.txt       # -i 直接改原文件（不加只输出不改）
sed -i.bak 's/old/new/g' file.txt   # -i.bak 改之前备份一份 file.txt.bak

# ② 删除行
sed '/error/d' file.txt             # 删掉所有含 error 的行
sed '1,3d' file.txt                  # 删第 1~3 行
sed '/^$/d' file.txt                 # 删空行（^$ 是空行的正则）

# ③ 插入/追加
sed '3i 新内容' file.txt            # 在第 3 行前插入一行
sed '3a 新内容' file.txt            # 在第 3 行后追加一行
```

> ⚠️ `sed -i` 直接改原文件**没有撤销**，重要文件一定加 `.bak` 备份：`sed -i.bak 's/...//'`。

**实战例子：批量改 nginx 配置的端口**

```bash
# 把 nginx.conf 里的 8080 改成 80
sudo sed -i.bak 's/8080/80/g' /etc/nginx/nginx.conf
# 改完看一眼有没有改错
diff /etc/nginx/nginx.conf.bak /etc/nginx/nginx.conf
# 确认无误后 nginx -t 测试配置、systemctl reload nginx 生效
```

### 4.5 awk — 强大的文本分析工具（了解）
> 🏷️ ⭐ —— 日志按列统计必用，掌握 5 个公式就够

awk 按"列"处理文本（默认以空格/Tab 分列），是分析日志的神器。**开发岗只需要了解 5 个公式**：

```bash
# ① 取列（最常用）
awk '{print $1}' file.txt            # 打印第 1 列
awk '{print $1, $3}' file.txt         # 打印第 1 和第 3 列
awk '{print $NF}' file.txt            # $NF = 最后一列（NF=Number of Fields）
awk -F: '{print $1}' /etc/passwd     # -F: 指定冒号为分隔符（看 passwd 第一列用户名）

# ② 带行号
awk '{print NR, $0}' file.txt         # NR = 当前行号（Number of Row），$0 是整行

# ③ 条件过滤
awk '$3 > 100' file.txt              # 第 3 列大于 100 的行
awk '/error/ {print}' log.txt         # 含 error 的行

# ④ 求和
awk '{sum+=$1} END {print sum}' nums.txt       # 所有第 1 列加起来
awk '{sum+=$1; n++} END {print sum/n}' nums.txt  # 求平均值

# ⑤ 分组统计（最高频：Nginx 日志按 IP 统计访问次数）
awk '{count[$1]++} END {for (ip in count) print count[ip], ip}' access.log | sort -rn | head
#                                 ↑ 关联数组：以第 1 列（IP）为下标计数
```

> 💡 **新手记住 `awk '{print $1}'` 和分组统计这两条就够 80% 场景**。其他参数（BEGIN/END 块、内置函数 gsub/substr）需要时查 man awk。

**实战例子：找出 Nginx 日志里访问量前 10 的 IP**
```bash
awk '{print $1}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head
# 拆解：取第1列(IP) → 排序 → 去重计数 → 按数量倒序 → 取前 10
```

### 4.6 xargs — 把前一个命令的输出变成参数（必会）
> 🏷️ ⭐ 开发必会 —— 主要和 find 配合，记住占位符和带空格文件名的写法

```bash
# xargs 把管道传来的内容变成后面命令的参数（有些命令不能直接接管道，就靠它）
find . -name "*.log" | xargs rm -f              # 删除所有 .log
find . -name "*.log" | xargs gzip               # 批量压缩
find . -name "*.bak" | xargs -I{} mv {} /tmp/   # -I{} 用 {} 占位，控制参数放的位置

# ⭐ 文件名可能带空格时，必须用 -print0 / -0 这对组合（否则空格会被当参数分隔符，出错）
find . -name "*.log" -print0 | xargs -0 rm -f
```

> 💡 `find -exec` 和 xargs 都能完成"找到文件再处理"：命令简单用 `-exec`，要和 sort/grep 等其他命令串联时用 xargs（4.1.9 搜代码的例子就是 xargs 场景）。

## 5. 压缩与解压（必会）
> 🏷️ ⭐ 开发必会 —— 软件开发日常高频使用，务必掌握

### 5.1 常见压缩格式（必会）
> 🏷️ ⭐ 开发必会 —— 软件开发日常高频使用，务必掌握

#### 5.1.1 先搞清两件事：打包 ≠ 压缩

这是新手最大的认知门槛，搞懂了后面全顺。

**① 打包（tar）**：把**多个文件/目录拢成一个文件**（`.tar`），方便传输。**不压缩、不减小体积**。
   类比：把一堆散装东西装进一个箱子，箱子本身不会让东西变小。

**② 压缩（gzip/bzip2/xz）**：把**一个文件**用算法变小。**只能压单个文件，不能压目录**。
   类比：用真空袋把衣服抽气变小。只能一袋装一件。

**那怎么压一整个目录？** → **打包 + 压缩两步合一**：先用 tar 把目录拢成 `.tar`，再用 gzip 等把它压小，得到 `.tar.gz`（这就是为什么有两个后缀——一个是打包步骤、一个是压缩步骤）。tar 命令用 `z/J/j` 选项自动把这两步串起来，你只需一条命令。

#### 5.1.2 五种格式对比表

| 格式 | 工具 | 特点 | 何时选 |
|------|------|------|--------|
| `.tar` | tar | 只打包不压缩，体积不变 | 仅归档不瘦身，或已压缩的内容（jpg/mp4 压不动） |
| `.tar.gz` / `.tgz` | tar + gzip | **压缩快、体积中等**，Linux 最主流 | **默认就选它**——日常 90% 场景 |
| `.tar.bz2` | tar + bzip2 | 压缩率更高，但慢 | 文件大、不急，比 gz 小 10~20% |
| `.tar.xz` | tar + xz | 压缩率最高，但最慢，解压也慢 | 源码 tarball、长期归档（Linux 内核源码就是 .tar.xz） |
| `.zip` | zip | 跨平台，Windows/Mac 直接能开 | 给同事传文件、下载源码包 |

> **选择口诀**：日常用 `.tar.gz`，要给 Windows 同学传就用 `.zip`，超大的源码包下载下来是 `.tar.xz`（被动接受，自己很少主动用 xz 压）。

#### 5.1.3 单文件压缩（gzip 最常用）

这三个工具单独使用——**只能压一个文件，不能压目录**（目录要靠 tar，见 5.2）。典型场景：压一个日志、一个 SQL 备份。

```bash
gzip a.txt                 # 压缩：原文件 a.txt 消失，变成 a.txt.gz
gunzip a.txt.gz            # 解压：变回 a.txt（.gz 消失）
zcat a.txt.gz              # 压缩包不用解压，直接看内容（看 .log.gz 日志时最常用）

bzip2 a.txt / bunzip2 a.txt.bz2    # bzip2：压得更小但更慢，bz2 包用 bunzip2 解
xz a.txt / unxz a.txt.xz           # xz：压得最小、最慢，常见于源码包，解压知道 unxz 即可
```

> ⚠️ **重要特性**：gzip/bzip2/xz **压缩后默认删除原文件**！想保留原文件加 `-k`（keep）：`gzip -k a.txt`。
>
> 💡 实际工作中要压的基本是**整个目录**，直接用 tar 一条命令搞定（见 5.2）；单文件命令里最常用的反而是 `zcat`——不用解压就能看 `.log.gz`。

### 5.2 tar — 打包工具（必会）
> 🏷️ ⭐ 开发必会 —— 软件开发日常高频使用，务必掌握

tar（Tape ARchive，磁带归档）是把多个文件/目录拢成一个 `.tar` 文件的工具，配合 `z/j/J` 选项还能顺手压缩。**Linux 上压缩目录的事实标准**，你以后 90% 的"压缩"和"解压"都靠它。

#### 5.2.1 tar 选项怎么读（核心，看不懂就卡在这）

tar 的选项字母分成三类，记住"**动作 1 个 + 压缩方式 1 个 + 必备 f + 可选增强**"：

| 类别 | 字母 | 含义 | 通俗记法 |
|------|------|------|---------|
| **动作（必选1）** | `c` | create 创建打包 | **c**reate = 新建 |
| | `x` | eXtract 解包 | e**x**tract = 提取 |
| | `t` | list 列出内容（不解包） | **t**able = 列表 |
| **压缩方式（选1或0）** | `z` | gzip 压缩 → `.tar.gz` | g**z**ip |
| | `j` | bzip2 压缩 → `.tar.bz2` | 难记，记住 bz2 用 j 即可 |
| | `J` | xz 压缩 → `.tar.xz` | 大写 J = 更高压缩率 |
| | （不写） | 不压缩，只打包 → `.tar` | — |
| **必备** | `f` | 指定**输出的文件名**（必写，且放在最后，紧跟文件名） | **f**ile = 文件 |
| **常用增强** | `v` | verbose 显示过程详细信息，列出处理的文件 | **v**erbose |
| | `p` | 保留权限（解压时用） | **p**reserve |
| | `C` | 解压到**指定目录**（大写） | `cd` 的 C |

**组合规律**：

- **打包压缩** = `c` + 选压缩方式 + `f` + `v`（可选）→ 如 `czf`、`cjf`、`cJf`
- **解压** = `x` + 选压缩方式 + `f` → 如 `xzf`、`xjf`、`xJf`
- **查看内容** = `t` + 选压缩方式 + `f` → 如 `tzf`

> 三个小疑问一次说清：
> 1. **选项前要不要加 `-`？** 现代 tar 可加可不加，`tar -czf` 和 `tar czf` 等价，**习惯上加 `-`**（看着更像正经命令）。脚本里两种写法都常见。
> 2. **字母顺序重要吗？** 不重要，`-czf` 和 `-zcf` 一样。但 **`f` 必须放最后**，因为它后面要紧跟"文件名"——如果写 `-fczf archive.tar.gz`，tar 会把 `czf` 当文件名。
> 3. **为什么 .tar.gz 有两个后缀？** tar 打包（.tar）+ gzip 压缩（.gz）两步合一的结果。tar 命令自动做两步。

#### 5.2.2 打包压缩（最常用）

```bash
# 准备测试目录
mkdir -p project/static && echo "code" > project/app.py && echo "data" > project/static/data.json
ls project/                              # app.py  static

# ① 最常用：打包 + gzip 压缩 → .tar.gz（90% 场景就这一条）
tar -czf project.tar.gz project/
ls project.tar.gz                        # 生成了压缩包，project/ 原目录还在
tar -czvf project.tar.gz project/        # 加 v：能看到处理过程
# 输出：
# project/
# project/app.py
# project/static/
# project/static/data.json

# ② 压缩率更高：用 bzip2 → .tar.bz2（比 gz 小，但慢）
tar -cjf project.tar.bz2 project/

# ③ 压缩率最高：用 xz → .tar.xz
tar -cJf project.tar.xz project/

# ④ 只打包不压缩 → .tar（用于"已经压不动"的内容，如一堆 jpg）
tar -cf project.tar project/
```

**对比三种压缩结果（同一份 project 目录）：**

```bash
$ ls -lh project.tar.*
-rw-r--r-- 1 root root 184K project.tar.bz2
-rw-r--r-- 1 root root 160K project.tar.gz     ← 速度/体积平衡最好，默认选它
-rw-r--r-- 1 root root 148K project.tar.xz     ← 体积最小，但慢
```

#### 5.2.3 解压（和打包一样高频）

```bash
# ① 最常用：解压 .tar.gz 到当前目录
tar -xzf project.tar.gz
# （x = 解，z = 用 gzip 解，f = 指定文件）

# ② 解压到指定目录（很常用，避免污染当前目录）
tar -xzf project.tar.gz -C /tmp/
ls /tmp/project/                         # 解到 /tmp 下了

# ③ 解压各种格式（按后缀选 z/j/J，记不住也行——下面 5.2.6 有偷懒写法）
tar -xjf project.tar.bz2                 # bzip2 格式
tar -xJf project.tar.xz                  # xz 格式
tar -xf   project.tar                    # 不带压缩的纯 tar

# ④ 加 v 看解压过程
tar -xzvf project.tar.gz
```

> ⚠️ **解压前先看内容**：这是**好习惯**，避免一解压炸出 100 个文件污染当前目录。`tar -tf project.tar.gz` 先看看里面有啥、有没有套着一层父目录。**下载的源码包**尤其要先看——有的打包时多套了一层 `project-1.0/` 目录，解压后就多一层；有的没套，解压出来一堆文件直接糊在当前目录。

#### 5.2.4 查看内容（不解压）

```bash
tar -tf  project.tar.gz                  # 列出里面的文件名
tar -tzvf project.tar.gz                 # 带详细信息（类似 ls -l 的输出）
# -rw-r--r-- root/root  5 2026-09-10 10:00 project/app.py
# -rw-r--r-- root/root  5 2026-09-10 10:00 project/static/data.json
```

#### 5.2.5 实用技巧

```bash
# ① 排除某些文件不打包（如排除 .log 日志、.git 目录）
tar -czf project.tar.gz --exclude='*.log' --exclude='.git' project/

# ② 只解压包里的某个文件（不用整个解出来）
tar -xzf project.tar.gz project/app.py   # 只拿 app.py 出来
tar -xzf project.tar.gz project/static/  # 只拿 static/ 目录出来
```

> 💡 `.tar.gz` 压缩包**不能往里追加文件**（未压缩的纯 `.tar` 才能用 `tar -rf 包名 新文件` 追加）；想加文件只能解压 → 加文件 → 重新打包。

#### 5.2.6 日常速查与场景（只记这 3 条就够 90% 场景）

| 要做的事 | 命令 |
|---------|------|
| **压缩目录** | `tar -czf 名字.tar.gz 目录名/` |
| **解压 .tar.gz** | `tar -xzf 包名.tar.gz`（要解到别处加 `-C /路径/`） |
| **看里面有啥** | `tar -tf 包名.tar.gz` |

> 💡 **偷懒大法**：现代 GNU tar 会**自动识别压缩格式**，解压时**不带 z/j/J 也行**：
> ```bash
> tar -xf project.tar.gz     # 不写 z 也能正确解 .tar.gz
> tar -xf project.tar.xz     # 不写 J 也能正确解 .tar.xz
> tar -xf project.tar.bz2    # 不写 j 也能
> ```
> 所以**解压时统一写 `tar -xf 包名`** 就行，省得记哪个后缀配哪个字母。但**打包时必须明确写 `czf`/`cjf`/`cJf`**——因为你要告诉它压成哪种格式。

**日常场景：**

| 场景 | 命令 |
|------|------|
| 备份项目代码到 /backup | `tar -czf /backup/project_$(date +%F).tar.gz /www/myproject/` |
| 给同事打包日志让他下载 | `tar -czf logs.tar.gz /var/log/nginx/access.log*` |
| 解压下载的源码包 | `tar -xf nginx-1.24.tar.gz && cd nginx-1.24` |
| 给 Windows 同学传代码 | 不用 tar，用 zip（见 5.3） |

**案例 1 答案：压缩两个文件**

```bash
tar -zcvf pc.tar.gz /home/pig.txt /home/cat.txt
```

参数拆解：`z`（gzip 压缩）+ `c`（create 创建包）+ `v`（verbose 显示打包过程，能看到压了哪些文件）+ `f`（指定包名，必须紧挨文件名），后面跟**要压的文件，可以写多个，空格隔开**。

> ⚠️ 屏幕可能出现一行提示：`tar: Removing leading '/' from member names`（从成员名中删除开头的 /）。**这不是报错**，是 tar 的保护机制：用绝对路径打包时，它会偷偷去掉开头的 `/`，防止以后解压时按绝对路径直接覆盖掉原文件。所以包里存的名字是 `home/pig.txt`，不是 `/home/pig.txt`。

**案例 2 答案：压缩整个 /home 目录**

```bash
tar -zcvf myhome.tar.gz /home/
```

压缩目录不用加额外参数，直接写目录路径即可，目录里的所有内容会递归打进去。同样会有 `Removing leading '/'` 提示，原理同上。

**案例 3 答案：切到 /opt/ 后解压 pc.tar.gz**

```bash
cd /opt/
tar -zxvf pc.tar.gz
```

参数拆解：`x`（extract 解包）替换掉打包时的 `c`，其余 `z`/`v`/`f` 不变。

两个注意点：

```bash
# ① 先确认包的位置：cd /opt 后，pc.tar.gz 不一定还在当前目录
#    tar 找不到包会报：tar (child): pc.tar.gz: Cannot open: No such file or directory
#    解决：写包的完整路径，例如（按你实际打包时所在的目录改）：
tar -zxvf /root/pc.tar.gz

# ② 解压后不会直接看到 pig.txt，因为案例 1 打包时带了 home/ 这层目录
ls /opt/                                  # 会看到 /opt/home/pig.txt、/opt/home/cat.txt
cat /opt/home/pig.txt                     # I am pig
```

> 💡 不想先 `cd` 也可以用 `-C`（大写 C = Change to directory，先切到指定目录再解压），效果一样：
> ```bash
> tar -zxvf pc.tar.gz -C /opt/
> ```

**案例 4 答案：解压 myhome.tar.gz 到 /opt/tmp2/**

```bash
mkdir -p /opt/tmp2                        # ⚠️ -C 指定的目录必须【已存在】，tar 不会帮你建
tar -zxvf myhome.tar.gz -C /opt/tmp2/

ls /opt/tmp2/home/                        # 验证：pig.txt、cat.txt 都在
```

> ⚠️ **最常见的错**：忘了先 `mkdir`，直接解压报 `tar: /opt/tmp2: Cannot chdir: No such file or directory`。养成习惯：用 `-C` 解压前先 `mkdir -p 目标目录`。

**做完后的验证与清理：**

```bash
# 验证两个包都生成了
ls -lh pc.tar.gz myhome.tar.gz            # -h 人类可读大小

# 看包里有什么（不解压，5.2.4 讲过的查看命令）
tar -tf pc.tar.gz                          # home/pig.txt、home/cat.txt

# 练习完清理解压出来的测试文件（包可以留着多练几遍）
rm -rf /opt/home /opt/tmp2
```

**4 个案例的核心规律总结：**

| 动作 | 命令模板 |
|------|----------|
| 打包（多个文件/目录都放最后） | `tar -zcvf 包名.tar.gz 文件1 文件2 目录1/` |
| 解压到当前目录 | 先 `cd 目标目录`，再 `tar -zxvf 包名.tar.gz` |
| 解压到指定目录 | `mkdir -p 目标目录 && tar -zxvf 包名.tar.gz -C 目标目录` |

</details>


### 5.3 zip / unzip —— 给 Windows 同学传文件用（必会）
> 🏷️ ⭐ 开发必会 —— 软件开发日常高频使用，务必掌握

tar/gzip 在 Linux 是绝对主流，但 **Windows 老版本默认解不开 `.tar.gz`**（Win11 才开始原生支持）。所以：给同事/客户传文件用 **zip**（他双击就能开），服务器之间传用 **tar.gz**（更高效、保留权限），GitHub release 的源码包大多也是 **zip**。

**安装**（CentOS 7 最小化安装默认不带）：

```bash
which zip unzip                          # 没输出就是要装
yum install -y zip unzip                 # 需要先修好 yum 源，见第三章 7.1.0
```

**压缩**：zip 不需要像 tar 那样先打包，一条命令同时完成两件事；常用选项就两个——`-r` 递归（压目录必须加）、`-x` 排除文件：

```bash
# 准备测试目录
mkdir -p project && echo "code" > project/app.py && echo "data" > project/data.json

zip project.zip project/app.py           # ① 压单个文件
# 输出：adding: project/app.py (deflated 25%)

zip -r project.zip project/              # ② 压整个目录（必须加 -r，否则只压顶层）
# 输出：
#   adding: project/ (stored 0%)
#   adding: project/app.py (deflated 25%)
#   adding: project/data.json (deflated 50%)

zip -r project.zip project/ -x '*.log' -x '.git/*'   # ③ 排除日志和 .git
```

**解压**：

```bash
unzip project.zip                        # ① 解到当前目录（有同名文件会问 y/n/A/N/r）
unzip project.zip -d /tmp/extracted/     # ② 解到指定目录（推荐，不污染当前目录）
unzip -l project.zip                     # ③ 只看内容不解压（解压前先看的好习惯）
unzip -o project.zip                     # ④ 自动覆盖不问（脚本里常用，否则卡在交互）
```

> ⚠️ **和 tar 的两个不同**：
> 1. **zip 压缩后原文件还在**（gzip 会删原文件）
> 2. **可以往 zip 包追加文件**（.tar.gz 不能）：`zip project.zip newfile.txt`

**日常场景：**

| 场景 | 命令 |
|------|------|
| 给同事打包代码（Windows 友好） | `zip -r project.zip project/ -x '.git/*' -x '*.pyc'` |
| 下载了 GitHub 的 zip 源码 | `unzip nginx-1.24.zip -d /usr/local/src/` |

> 💡 如果收到 Windows 的 **`.rar`** 包：先 `yum install -y epel-release unrar`，再用 `unrar x 包.rar` 解压（保留目录结构）。自己打包用 zip/tar.gz 即可，不要用 rar。

### 5.4 压缩工具横向对比与选择（必会）

学完这几个工具，实际工作时怎么选？一张表搞定：

| 你要做什么 | 用什么 | 命令（只记这一条） |
|----------|--------|-------------------|
| **压目录（Linux 服务器间）** | tar.gz | `tar -czf x.tar.gz 目录/` |
| **解 tar.gz / tar.xz / tar.bz2** | tar | `tar -xf x.tar.gz`（自动识别格式） |
| **给 Windows/Mac 同事打包** | zip | `zip -r x.zip 目录/` |
| **解压别人发来的 zip** | unzip | `unzip x.zip -d 目标目录/` |
| **解压别人发来的 rar** | unrar | `unrar x x.rar` |
| **看一个压缩包里有啥** | tar / unzip | tar: `tar -tf x.tar.gz`；zip: `unzip -l x.zip` |
| **压一个单文件（如日志）** | gzip | `gzip file.log`（注意会删原文件，保留用 `gzip -k`） |
| **不解压看 .gz 文件内容** | zcat | `zcat file.log.gz` |

**一句话总结**：
- **自己压东西** → 服务器内部用 `tar -czf`，跨平台用 `zip -r`
- **解别人的包** → 看后缀：`.tar.*` 用 `tar -xf`，`.zip` 用 `unzip`，`.rar` 用 `unrar x`
- **记不住就记这条**：`tar -xf 包名` 能解开绝大多数 Linux 压缩包（GNU tar 自动识别格式）

## 6. 文件权限管理（必会）
> 🏷️ ⭐ 开发必会 —— 软件开发日常高频使用，务必掌握

### 6.1 权限基础（必会）
> 🏷️ ⭐ 开发必会 —— 软件开发日常高频使用，务必掌握

Linux 文件权限由三部分组成。`ls -l` 看到的第一列共 **10 个字符**，不要一个一个念，按 **「1 + 3 + 3 + 3」切成 4 段**看：

```
drwxr-xr-x  2 root root 4096 May 10 08:30 test
└─┘└─┘└─┘└─┘
 d rwx r-x r-x
 ↑  ↑   ↑   ↑
 │  │   │   └─ 第4段(8~10位)：其他人权限 —— r-x：能看、能进，不能改
 │  │   └───── 第3段(5~7位)：属组权限   —— r-x：组内成员能看、能进，不能改
 │  └───────── 第2段(2~4位)：属主权限   —— rwx：文件主人能读、能写、能进
 └──────────── 第1段(第1位)：文件类型   —— d 表示目录
```

逐段对照表：

| 段 | 在哪几位 | 例子里是 | 含义 |
|----|---------|---------|------|
| 第 1 段 | 第 1 位（1 个字符） | `d` | 文件类型（见下表） |
| 第 2 段 | 第 2~4 位（3 个字符） | `rwx` | **属主**（所有者，这行后面的第一个 root）的权限 |
| 第 3 段 | 第 5~7 位（3 个字符） | `r-x` | **属组**（第二个 root）里成员的权限 |
| 第 4 段 | 第 8~10 位（3 个字符） | `r-x` | **其他人**（既不是主人、也不在组里的所有人）的权限 |

> 记忆方法：**先看第 1 位认类型，后面 9 位每 3 个一组，依次是"主人 → 家里人 → 外人"**，权限从大到小排列（主人通常最大，外人通常最小）。
>
> 每一段内部位置永远固定：**第 1 格 r（读）、第 2 格 w（写）、第 3 格 x（执行）**，有这个权限显示字母，没有就是 `-`。例如 `r-x` = 有读、没写（中间是 `-`）、有执行。

再看两个例子练手：

```
-rw-r--r--  1 root root  1200 May 10 08:31 a.txt
 -  rw-  r--  r--
 ↑   ↑    ↑    ↑
普通文件；主人能读写不能执行；组和外人都只能读（典型的普通文件 644）

-rwx------  1 root root  2600 May 10 08:32 id_rsa
 -  rwx  ---  ---
普通文件；只有主人能读写执行，组和外人什么权限都没有（典型的私钥 700）
```

**文件类型（开发只需认这 3 种）：**
| 符号 | 类型 | 见得多不多 |
|------|------|-----------|
| - | 普通文件（代码、配置、图片…） | ⭐⭐⭐ 最多 |
| d | 目录（文件夹） | ⭐⭐⭐ 最多 |
| l | 符号链接（软链接，快捷方式） | ⭐⭐ 常见 |
| b/c/s/p | 块/字符设备、套接字、管道 | ❌ 开发不用，不用记 |

**权限字符：**
| 字符 | 权限 | 文件 | 目录 |
|------|------|------|------|
| r | 读 | 可查看内容 | 可列出文件 |
| w | 写 | 可修改内容 | 可创建/删除文件 |
| x | 执行 | 可执行文件 | 可进入目录 |
| - | 无 | 无权限 | 无权限 |

### 6.2 权限数字表示（为什么 r=4、w=2、x=1？）（必会）
> 🏷️ ⭐ 开发必会 —— 软件开发日常高频使用，务必掌握

每组权限（r/w/x 三个字母）可以用**一个 0~7 的数字**表示，三组合起来就是一个三位数，如 `755`、`644`。

#### 6.2.1 数字是怎么来的：3 个"开关"对应 3 个二进制位

把 r、w、x 想象成 3 个开关，**开=1，关=0**，开关的位置是固定的：

```
      r位  w位  x位
      ↓    ↓    ↓
权限  1    1    1    → rwx（全开）
```

按二进制转十进制，每一位的"权重"是：**r 位 = 4（2²）、w 位 = 2（2¹）、x 位 = 1（2⁰）**。有哪个权限就把对应的数加上：

| r(4) | w(2) | x(1) | 数字 | 字母 | 含义 |
|:---:|:---:|:---:|:---:|------|------|
| 1 | 1 | 1 | **7** | rwx | 全开 |
| 1 | 1 | 0 | **6** | rw- | 能读能改、不能执行 |
| 1 | 0 | 1 | **5** | r-x | 能读能进、不能改 |
| 1 | 0 | 0 | **4** | r-- | 只读 |
| 0 | 0 | 0 | **0** | --- | 什么都不给 |

> 3(-wx)、2(-w-)、1(--x) 这三种组合开发几乎碰不到,不用记。

> 所以三组数字拼起来：
> - `755` = 主人 7(rwx) + 组 5(r-x) + 其他人 5(r-x) → `rwxr-xr-x`
> - `644` = 6(rw-) + 4(r--) + 4(r--) → `rw-r--r--`
> - `600` = 6(rw-) + 0(---) + 0(---) → `rw-------`
> - `777` = 全开 → `rwxrwxrwx`（危险，别乱用）

**口算练习（看到数字能立刻翻译成字母）：**
```
700 → rwx------   主人全开，别人啥也没有
750 → rwxr-x---   主人全开，组能看能进，外人完全不能碰
640 → rw-r-----   主人能改，组只能看，外人不能碰
775 → rwxrwxr-x   主人和同组都能改，外人能看（组内协作目录）
```

#### 6.2.2 必须背下来的 5 个常用数字（90% 场景）

| 数字 | 字母 | 用在什么上 | 通俗解释 |
|------|------|-----------|---------|
| **755** | rwxr-xr-x | **目录**、可执行脚本/程序 | 我全能，别人能看能进不能改 |
| **644** | rw-r--r-- | **普通文件**（配置、代码、网页） | 我能改，别人只能看 |
| **600** | rw------- | **私密文件**（SSH 私钥、密码文件） | 只有我能看能改 |
| **700** | rwx------ | **私密目录**（~/.ssh、私人文件夹） | 只有我能进 |
| **777** | rwxrwxrwx | 几乎不用（`/tmp` 除外） | 门全拆，危险 |

> 记忆口诀：**目录 755、文件 644、私密 700/600、别碰 777。**

#### 6.2.3 一个必须知道的前提：文件的执行权限不是你想的那样

- **普通文件默认没有 x**：新建文件默认是 644（`-rw-r--r--`），因为文本、图片、配置本来就不该被"执行"
- **目录必须有 x**：新建目录默认是 755（`drwxr-xr-x`），没有 x 就进不去
- 记住系统默认值即可：**文件 644、目录 755**

### 6.3 chmod — 修改权限（必会）ccc注:这个挺重要的我觉得
> 🏷️ ⭐ 开发必会 —— 软件开发日常高频使用，务必掌握

chmod = **ch**ange **mod**e（改变模式）。改权限有两种写法：

| 方式 | 长什么样 | 特点 | 什么时候用 |
|------|---------|------|-----------|
| **数字方式** | `chmod 755 f` | 三组权限**整体重写**，不管原来是什么 | 知道目标权限、想一次性设好（最常用） |
| **符号方式** | `chmod u+x f` | 在原有权限上**增/减某一个位**，其他位不动 | 只想加个执行权、去掉组写权，不想影响其他位 |

> ⚠️ 前提：**只有文件的属主本人或 root 才能 chmod**。普通用户想改别人的文件会报 `Operation not permitted`，加 sudo 用 root 身份改。

#### 6.3.1 数字方式（整体重写）

```bash
# 数字方式（r=4 w=2 x=1，三组数字依次是 属主/属组/其他人）
chmod 755 file.txt              # rwxr-xr-x：我全能，别人能看能执行不能改
chmod 644 file.txt              # rw-r--r--：我能改，别人只能看（普通文件最常见）
chmod 600 file.txt              # rw-------：只有我能看能改（私钥、密码文件）
chmod 700 dir/                  # rwx------：只有我能进这个目录
```

特点：**一刀切重写**。比如文件原来是 600（rw-------），你执行 `chmod 644` 后就是 644，和原来是什么完全无关。

#### 6.3.2 符号方式（只动某一个权限位）

符号方式的语法是三段式：

```
chmod   谁   操作   给什么权限    文件名
         ↓     ↓        ↓
         u     +        r
         g     -        w
         o     =        x
         a              X（大写：仅目录加 x）
```

**① "谁"（who，可组合，如 `ug`）：**

| 字母 | 代表 | 说明 |
|------|------|------|
| `u` | user 属主 | 文件主人 |
| `g` | group 属组 | 文件所属组里的成员 |
| `o` | others 其他人 | 既不是主人也不在组里 |
| `a` | all 所有人 | 等价于 ugo；**省略谁时默认就是 a** |

**② "操作"（operator，三选一）：**

| 符号 | 含义 | 例子 |
|------|------|------|
| `+` | **追加**权限（没有的加上，已有的保持） | `u+x` 给属主加执行权 |
| `-` | **去掉**权限（有的去掉，没有的忽略） | `g-w` 去掉组的写权 |
| `=` | **直接设成**（等号后面列出的就是全部，没列的全部清掉） | `u=rwx` 属主只能是 rwx |

**③ "什么权限"（perm）：** r、w、x。还有一个大写 `X`（见 6.3.4，解决目录和文件权限递归的坑）。

**完整示例：**

```bash
chmod u+x script.sh             # 只给属主加执行权（最常用：脚本写完跑不了就加它）
chmod g-w file.txt              # 把组的写权限去掉，其他位一律不动
chmod o-rwx file.txt            # 其他人所有权限全去掉（等价 o=）
chmod a-x file.txt              # 所有人的执行权限都去掉
chmod u=rwx,g=rx,o=r file.txt   # 一次性精确指定三组权限（等价 754）

# 一次给多组人设置，用逗号连起来（逗号两边不能有空格！）
chmod u+rwx,g+rx,o-rwx dir/     # 主人全开、组加读和执行、外人全关
chmod ug=rw,o=r file.txt        # 主人和组设为 rw，外人只读
```

> 📌 **两个常见疑问**：
> 1. `chmod +x f` 到底给谁加？——**省略"谁"时等价于 `a+x`，三组都会加上执行位**：644 的文件执行 `chmod +x` 后变成 **755（rwxr-xr-x）**，不是只给属主！想只给属主加执行权限，写全 `u+x` 更稳妥。
> 2. **`+`/`-` 是增量修改，`=` 是覆盖**：`u+x` 只动 x 位，r、w 保持原样；`u=rwx` 会把属主的三个位强制设成 rwx。增量修改用 `+/-`，想一步到位用 `=`。

#### 6.3.3 目录权限的特殊含义（复习：rwx 对文件夹意味着什么）

在讲递归前必须先记住：**目录的 r、w、x 含义和文件完全不同**，这是 90% 新手踩坑的根源。把目录想象成一个**房间**：

| 权限 | 对文件的含义 | 对**目录**的含义（类比房间） |
|------|-------------|------------------------------|
| `r` | 能看文件内容 | 能**列出房间里的东西名单**（`ls 目录名`） |
| `w` | 能改文件内容 | 能在房间里**搬东西进出**：新建、删除、改名文件（需配合 x） |
| `x` | 能运行这个程序 | 能**走进房间**（`cd` 进去、访问里面的路径），没有它连门都进不了 |

- 有 r 没 x：能拿到"物品清单"（ls 看得到文件名），但**进不去门**，打开里面任何文件都报 Permission denied
- 有 x 没 r：能进门，**知道文件名就能直接访问**（`cat dir/a.txt`），但 `ls dir` 列不出名单
- 所以**正常目录至少要给 x**，r 和 x 通常成对出现（5 = r-x）

只改文件夹本身（不影响里面的内容）：

```bash
chmod 755 /opt/myapp                 # 只改这一层目录
chmod 700 /home/lisi/private         # 私人目录：只有自己能进
ls -ld /opt/myapp                    # 看目录权限要加 -d，否则 ls 看的是里面的内容
```

#### 6.3.4 ⭐ `-R` 递归修改（你问的重点，也是最容易用错的选项）

**`-R` = Recursive（递归），作用是"连子带孙一起改"。**

不加 `-R`：命令只作用于你写的那个文件/目录**本身**，目录里面的东西一概不动。
加了 `-R`：先改目录本身，再钻进去改它的每一个子目录、每一个文件，一层一层直到最深。

```bash
chmod 755 myproject/          # 只改 myproject 这一层目录，里面的文件/子目录权限不变
chmod -R 755 myproject/       # myproject + 里面所有子目录 + 所有文件，全部改成 755
```

**用一张图理解递归范围：**

```
chmod 755 myproject/          只动 ⭐ 这一层
                    myproject/ ⭐
                    ├── a.txt        （不动）
                    ├── sub/         （不动）
                    │   └── b.txt    （不动）

chmod -R 755 myproject/       ⭐ 和里面的每一个都动
                    myproject/ ⭐
                    ├── a.txt        ✅ 改成 755
                    ├── sub/         ✅ 改成 755
                    │   └── b.txt    ✅ 改成 755
```

> 💡 **`-R` 在很多命令里都是同一个意思**：`chown -R`（递归改所有者）、`cp -r`（递归复制目录，cp 用小写 r）、`rm -r`（递归删除目录）、`ls -R`（递归列出所有层）。记住"R/r = 钻到目录里面去"即可。

**🚨 但是 `chmod -R 755 目录/` 是个大坑！**

```bash
chmod -R 755 myproject/      # 看着没问题，实际会出事
```

`-R 755` 不加区分地把**目录和普通文件都设成 rwxr-xr-x**：
- 目录带 x 是对的（要能进入）
- 但 `.txt`、`.py`、`.conf`、图片这些**普通文件也被加上"可执行"标记**——它们本来不该是程序，结果 `ls -l` 一片绿、git status 显示一堆改动、还可能被安全扫描工具报警

**正确写法有 3 种，按需选一种：**

```bash
# 写法一：大写 X（最简单，推荐记这个）
# 大写 X 的规则：只给"目录"加执行位；普通文件只有"本来就有 x"才保留，不会新加
chmod -R u+rwX,go+rX,go-w myproject/
# 效果：目录 → 755；普通文件 → 644；已经可执行的 .sh 脚本保持可执行

# 写法二：find 分别处理（最精确，部署 Web 项目时的标准做法）
find myproject -type d -exec chmod 755 {} \;   # 只挑目录设 755
find myproject -type f -exec chmod 644 {} \;   # 只挑文件设 644
# 如果里面有脚本需要可执行，单独再给：
find myproject -name "*.sh" -exec chmod 755 {} \;

# 写法三：你非常确定里面全是程序/脚本、每个文件都该可执行时
# （几乎只有这种场景才适合 chmod -R 755）
chmod -R 755 /usr/local/myapp/bin/
```

> 自己动手验证这个坑（推荐做一遍，印象深刻）：
> ```bash
> mkdir -p /tmp/pt/sub && echo hi > /tmp/pt/a.txt && chmod 644 /tmp/pt/a.txt
> chmod -R 755 /tmp/pt && ls -l /tmp/pt/a.txt     # a.txt 变成 -rwxr-xr-x（被加了 x，错！）
> chmod 644 /tmp/pt/a.txt                          # 改回来
> chmod -R u+rwX,go+rX,go-w /tmp/pt && ls -l /tmp/pt/a.txt  # a.txt 是 -rw-r--r--（对！）
> ```

#### 6.3.5 日常场景速查

| 需求 | 命令 |
|------|------|
| 脚本写完运行报 Permission denied | `chmod +x deploy.sh` |
| 整个项目目录：我能随便改，同组能看 | `chown -R lisi:dev project/ && chmod -R u+rwX,g+rX,o-rwx project/` |
| Web 站点目录标准权限（目录 755、文件 644） | 上面"写法二"的两条 find |
| 上传目录需要让 Web 用户能写文件 | `chmod 775 uploads/`（且属组设为运行 Web 的用户，如 nginx） |
| 私密文件夹只有自己能进 | `chmod 700 ~/private/` |
| SSH 私钥权限不对连不上 | `chmod 600 ~/.ssh/id_rsa` |
| 文件夹所有人完全开放（仅限临时测试，**别在生产用**） | `chmod 777 /tmp/share` |

> 🔑 经验数字：**目录用 755，文件用 644，私密的用 700/600**，这三个覆盖 95% 的场景。777 是"把门全拆了"，除了 `/tmp` 这类临时目录，看到自己敲 777 就要警惕——十有八九应该用改所有者（chown，见 6.4）或改组来解决，而不是放开权限。

### 6.4 chown / chgrp — 修改所有者和属组（必会）
> 🏷️ ⭐ 开发必会 —— 软件开发日常高频使用，务必掌握

#### 6.4.1 属主和属组到底是什么（用你自己的实验结果讲）

先看一条真实的 `ls -ld` 输出（`.` 代表当前目录，也就是你实验里的 `/aaa`）：

```bash
ls -ld
# drwxr-xr-x. 3 lwc root 34 9月  11 19:50 .
#  └─────┬──┘  │   │   │
#     权限位    │   │   └─ 属组
#             硬链接 属主
```

- **lwc → 属主（所有者，user）**：这个目录属于哪个用户，他是文件主人，对应第一组权限位 `rwx`
- **root → 属组（用户组，group）**：这个目录归属哪个用户组，组里的成员对应第二组权限位 `r-x`

你之前执行 `chown -R lwc aaa` 后看到的结果正是：

> ✅ 只修改了**属主**为 lwc，**属组保持不变，依旧是 root**。

这是因为命令里只写了用户名、没写冒号和组名。完整的权限拆解：

```
d   rwx      r-x      r-x
目录 属主lwc  属组root  其他人
     读写进    读进      读进
              不能写    不能写
```

#### 6.4.2 为什么需要 chown？（先想明白场景）

chmod 改的是"**主人/组/外人能干什么**"，chown 改的是"**谁是主人、哪个组是属组**"——先有属主属组，权限位才有意义。

典型场景：**用 root 部署了项目，结果普通账号或 nginx 改不了文件**：

```bash
# root 上传的代码，属主属组都是 root
ls -ld /www/myproject
# drwxr-xr-x 3 root root 4096 Sep 10 10:00 /www/myproject
# nginx 以 nginx 用户运行，对它只有 r-x（能看不能改）→ 上传/写日志报 Permission denied
```

解决办法不是 `chmod 777`（把门全拆），而是**把文件的属主/属组交给真正该用它的人**：`chown -R nginx:nginx /www/myproject`。

> ⚠️ **前提**：chown 只有 **root 能执行**。普通用户哪怕你是文件主人，也不能把文件"送给"别人（安全限制，防止把恶意文件甩锅）。所以命令前一般加 `sudo`。

#### 6.4.3 命令语法：冒号前后两个名字

```
chown  [选项]  属主:属组  文件名
                 ↑   ↑
              可只写一个，也可两个都写
```

| 写法 | 含义 |
|------|------|
| `chown lisi f` | **只改属主**为 lisi，属组不变（你实验里就是这种） |
| `chown lisi:dev f` | 属主改 lisi、属组改 dev（最常用） |
| `chown lisi: f` | 属主改 lisi，属组**自动变成 lisi 的主组**（冒号不能省） |
| `chown :dev f` | **只改属组**为 dev，属主不变 |
| `chgrp dev f` | 同上，专门改属组的老命令 |

> 📌 古老写法用点号 `chown lisi.dev f`，现在统一用**冒号**（用户名里可能有点，冒号不会歧义）。

#### 6.4.4 常用示例

```bash
# ① 只改属主（属组不动）
sudo chown lisi a.txt

# ② 同时改属主和属组
sudo chown lisi:dev a.txt

# ③ ⭐ 递归改整个目录（-R，和 chmod 的 -R 一个意思：连子带孙）
sudo chown -R lisi:dev /www/myproject/     # 部署项目后几乎必做

# ④ 只改属组（两种等价写法）
sudo chown :dev a.txt
sudo chgrp dev a.txt

# ⑤ 照抄另一个文件的属主属组（--reference，不用手打用户名）
sudo chown --reference=/www/myapp/manage.py /www/myapp/newfile.py
```

#### 6.4.5 chmod 和 chown 怎么配合？（部署项目标准动作）

```bash
# 第 1 步：定归属——整个项目交给开发账号 lisi（属主）和 dev 组
sudo chown -R lisi:dev /www/myproject/

# 第 2 步：定规矩——目录 755、文件 644（主人能改、别人能看）
find /www/myproject -type d -exec chmod 755 {} \;
find /www/myproject -type f -exec chmod 644 {} \;
# 同组人也要能改的协作目录：用 775/664，并保证大家都在 dev 组里
```

记忆：**chown 决定"东西是谁的"，chmod 决定"各路人能对它干什么"**。权限被拒时先 `ls -l` 看属主属组对不对，再看权限位够不够——顺序别搞反。

### 6.5 权限应用实例（必会）
> 🏷️ ⭐ 开发必会 —— 软件开发日常高频使用，务必掌握

**实例 1：Web 站点目录**

```bash
# 归属给运行 Web 服务的用户（nginx/apache）
sudo chown -R nginx:nginx /usr/share/nginx/html

# 目录 755、文件 644（find 分开设，避免普通文件被加执行位）
sudo find /usr/share/nginx/html -type d -exec chmod 755 {} \;
sudo find /usr/share/nginx/html -type f -exec chmod 644 {} \;

# 用户上传目录需要可写：组可写 + 归属 nginx 组（不要 777！）
sudo chmod 775 /usr/share/nginx/html/uploads
```

**实例 2：SSH 目录权限（不对会连不上，ssh 会强制拒绝）**

```bash
chmod 700 ~/.ssh                    # 目录只有自己能进
chmod 600 ~/.ssh/id_rsa             # 私钥只有自己能读（最严格）
chmod 644 ~/.ssh/id_rsa.pub         # 公钥可以给别人看
chmod 644 ~/.ssh/authorized_keys    # 授权密钥列表
```

**实例 3:Permission denied 排查流程(最实用)**

```
操作报 Permission denied,按顺序排查:

第 1 步:我是谁?
  id / whoami                        # 确认当前用户名和所属的组

第 2 步:文件归谁?我对应哪一组权限位?
  ls -l 文件 / ls -ld 目录
  # 属主是我 → 看第 1 组;我在属组里(id 能查到)→ 看第 2 组;否则 → 看第 3 组

第 3 步:权限位够不够?
  # 读文件要 r;改文件要 w;运行脚本要 x
  # cd 进目录要 x;ls 列目录要 r;在目录里增删改名要 wx

第 4 步:改权限还是改归属?
  # 该给某个人 → sudo chown 属主:属组 文件(-R 连带目录内容)
  # 该放开某类操作 → chmod u+x / g+w 等,尽量别用 777
  # 改完用对应账号重新验证(别用 root 测,root 绕过一切权限位)
```

> 💡 **运维向补充**(开发了解即可):如果权限明明对还拒绝,可能是 SELinux 强制访问控制(运维负责),临时关掉验证:`setenforce 0`,永久关改 `/etc/selinux/config`。

## 7. 链接文件（必会）
> 🏷️ ⭐ 开发必会 —— 软链接是版本切换、兼容旧路径的核心手段，务必掌握

### 7.1 软链接（符号链接）（必会）
> 🏷️ ⭐ 开发必会 —— 软件开发日常高频使用，务必掌握

```bash
# 软链接是一个特殊文件，指向另一个文件
ln -s source_path link_name

# 特点：
# - 可以跨文件系统
# - 可以对目录创建
# - 原始文件删除后链接失效（变成"悬空链接"，ls 显示红色闪烁）
# - 类似 Windows 快捷方式

# 示例
ln -s /usr/local/mysql/bin/mysql /usr/bin/mysql
ln -s /var/www/html /home/user/website

# 查看链接
ls -l /usr/bin/mysql
# lrwxrwxrwx 1 root root 30 Jul 30 10:00 mysql -> /usr/local/mysql/bin/mysql
```

**常见坑：**

**坑 1：目标已存在 → 报 `文件已存在`**

```bash
ln -s /usr/local/mysql/bin/mysql /usr/bin/mysql
# ln: 无法创建符号链接"/usr/bin/mysql": 文件已存在
```

原因：`/usr/bin/mysql` 已经有东西了（旧的 mysql 客户端或已有软链接）。解决：

```bash
ls -l /usr/bin/mysql                         # 先看是什么占着
ln -sf /usr/local/mysql/bin/mysql /usr/bin/mysql   # -f 强制覆盖（确定旧的没用再加）
```

**坑 2：链接名所在目录不存在 → 报 `没有那个文件或目录`**

![llj](D:\AI\linux\安装虚拟机和centos步骤\llj.png)

你**当前已经 cd 进到 eee 目录里面了**！

**坑 3：源路径不存在也能创建成功 → 悬空链接**

```bash
ln -s /var/www/html ~/website        # 能创建成功（ln -s 不检查源是否存在）
ls /var/www/html                     # 但源目录根本不存在！
# ls: 无法访问/var/www/html: 没有那个文件或目录
```

原因：`ln -s` 只负责"建一个指向某路径的路标"，不会验证那条路通不通。

**怎么识别悬空链接：**

```bash
ls -l ~/website
# lrwxrwxrwx ... /home/qyz/website -> /var/www/html  （文件名红色闪烁 = 悬空）
```

**怎么修复：**

```bash
# 方法1：创建源目录（如果你确实想用 /var/www/html）
sudo mkdir -p /var/www/html
sudo chown qyz:qyz /var/www/html     # 改成你的用户能写
ls ~/website                         # 现在能正常访问了

# 方法2：删了重指到真实存在的目录
rm ~/website
mkdir -p ~/html
ln -s ~/html ~/website
ls ~/website                         # 正常，能看到 ~/html 里的内容
```

> 💡 悬空链接不是错误，只是"指向的东西还没建好"。比如部署网站时先建软链接再传文件，传完之前就是悬空的。

**坑 4：软链接的文件夹原来就存在不管他是空的还是非空的 **

比如你的lwc下面的111下面有一个yyy文件夹和eee文件夹，yyy作为源路径，eee作为软连接，应该这么写：

```
sudo ln -s /home/lwc/111/yyy /home/lwc/111/rrr/linky    # 把rrr下面的原来不存在的linky作为软链接
不要用相对路径   sudo ln -s ./mm ./vvv/linkv 这样写能够创建 但看不见而且报红
```

能不能直接把 rrr 作为软链接呢，可以，但是必须先删除原来已经存在的真实目录 `rrr`！

### 7.2 软链接 vs 硬链接（了解硬链接即可）

开发**只创建软链接**,硬链接知道概念就行(有兴趣可 `man ln`)。关键区别:

| 特性 | 硬链接 | 软链接 |
|------|--------|--------|
| inode | 相同 | 不同 |
| 跨文件系统 | ❌ | ✅ |
| 对目录 | ❌ | ✅ |
| 原始文件删除 | 仍可用 | 失效 |
| 相对路径 | 不支持 | 支持（相对于链接位置） |
| 文件类型 | 普通文件 | l 开头的链接文件 |

#### 7.3.1 inode 是什么（理解硬链接的关键）

**一句话理解**：文件名和文件内容是分开存的，中间靠 inode（索引节点）连起来。

```
目录里：文件名 a.txt ──指向──→ inode 12345 ──指向──→ 数据块（存"hello"）
```

- **inode** 存文件的"元信息"：权限、属主、大小、时间戳、数据块位置
- **文件名**只是目录里的一条记录，指向某个 inode
- **硬链接** = 同一个 inode 多一个文件名指过去（所以删原文件，硬链接还能读）
- **软链接** = 一个独立的小文件，内容是"目标路径的字符串"（目标没了，字符串就指空了）

```bash
ls -i a.txt                # 看 a.txt 的 inode 号
stat a.txt                 # 看 inode 完整信息（大小、时间、链接数）

# 演示硬链接共享 inode
echo "hello" > a.txt
ln a.txt b.txt              # 硬链接
ls -li a.txt b.txt          # 看到两个文件 inode 相同，链接数=2
rm a.txt                    # 删原文件
cat b.txt                   # 仍然可读（inode 数据未被释放）
```

> 💡 开发岗只需要知道 inode 这个概念能解释"为什么硬链接删原文件还在"就行。

#### 7.2.2 readlink / realpath — 路径解析

```bash
# readlink -f（最常用）:跟随所有软链接直到真实路径
readlink -f /usr/bin/java      # 输出 /usr/local/jdk17/bin/java

# realpath - 把带 . / .. 的路径标准化成绝对路径
realpath ../etc/../etc/passwd  # 输出 /etc/passwd

# 实战:找到命令的真实安装路径
ls -l /usr/bin/java           # 通常是个软链接
readlink -f /usr/bin/java     # 直接看最终路径
```

#### 7.2.3 软链接实战场景
```bash
# 场景1：版本切换（最常用）
ln -s /usr/local/jdk-17 /usr/local/java
# 升级时只需改软链接指向
ln -snf /usr/local/jdk-21 /usr/local/java

# 场景2：跨盘符引用
ln -s /mnt/data/logs /var/log/app
# /var 在小盘，/mnt/data 在大盘

# 场景3：兼容旧路径
mv /opt/app /opt/app_v2
ln -s /opt/app_v2 /opt/app
# 旧脚本用 /opt/app 仍然能工作

# 场景4：管理多版本 Python
ln -s /usr/bin/python3 /usr/bin/python
```

## 8. 用户与用户组管理（必会）
> 🏷️ ⭐ 开发必会 —— 多用户环境下理解账号、权限与环境配置的核心，日常高频使用

### 8.1 用户、UID 与用户组的关系（必会）
> 🏷️ ⭐ 开发必会 —— 理解账号体系的地基，后面所有权限问题都建立在这三个概念上

Linux 是多用户多任务系统：同一台服务器可同时被多人登录、多个程序并行运行。用户管理的意义在于：

- **隔离**：普通用户之间默认不能随意翻看彼此的文件
- **安全**：root 拥有最高权限，日常操作应使用普通用户，需要时再提权（最小权限原则）
- **归属**：每个服务（mysql、nginx、tomcat 等）通常用专属的低权限用户运行，一旦服务被攻破，攻击者拿到的也只是该用户的权限

**① UID 是什么？—— 用户名是"称呼"，UID 才是"身份证号"**

Linux 表面上让你用用户名（lisi）登录，但系统内核**只认数字**，这个数字就是 **UID（User ID，用户编号）**。

- 用户名：给人看的，好记、能随便改（类似公司里喊"老王"）
- UID：给系统看的，全局唯一、决定权限（类似身份证号，号码不变）

最关键的一点：**文件的属主存的是 UID 数字，不是用户名**。你执行 `ls -l` 看到的 `lisi`，是系统拿文件里存的数字去 `/etc/passwd` 反查名字后显示出来的。这能解释一个新手常见的"灵异现象"：

```bash
# 把用户 lisi 改名叫 wangwu 后，他原来的文件 ls -l 仍然显示属主是 wangwu
# 因为文件存的是 UID 1001，系统重新查了一遍：1001 现在叫 wangwu
# 如果 passwd 里没有 1001 这个用户，ls -l 会直接显示数字 1001
```

> ⚠️ 判断身份看的是 **UID 而不是名字**：UID=0 的就是 root（哪怕把 root 改名为 admin），用 `id` 命令看到的才是真身份。

用户按 UID 分为三类：

![image-20260918100221179](C:\Users\35181\AppData\Roaming\Typora\typora-user-images\image-20260918100221179.png)

| 类型 | UID 范围 | 说明 |
|------|---------|------|
| 超级用户 root | 0 | 系统唯一，拥有全部权限 |
| 系统用户 | 1~999（CentOS 7） | 给服务/守护进程用，一般禁止登录（shell 为 /sbin/nologin） |
| 普通用户 | 1000 起 | 给真人使用，登录后默认在自己家目录 |

**② 用户和用户组是什么关系？—— 一个"人"和一个个"圈子"**

- **用户（User）**：一个能登录系统的具体身份，比如 lisi、zhangsan
- **用户组（Group）**：一群用户的集合，类似公司里的"部门/项目组"标签，也有一个编号叫 **GID（Group ID）**

为什么要有"组"？因为权限只能按"**属主 / 属组 / 其他人**"三类来设（见第 6 章）。如果要给 10 个开发同事都开放某个目录，不可能一个一个用户去授权——把他们拉进同一个组，给组授一次权就行了。**组就是"批量授权"的单位。**

两者的关系记住 3 句话：

1. **每个用户有且只有一个"主组"**：记录在 `/etc/passwd` 第 4 个字段。`useradd lisi` 时系统会自动建一个和用户同名的私人组 `lisi`（GID 也 1001 起），主组默认就是它——新建文件的属组默认就是这个组
2. **一个用户还可以加入多个"附加组"**：记录在 `/etc/group`。就像一个员工主属"研发部"，同时还能加入"docker 组""wheel 组"这些圈子
3. **用户和组是多对多**：一个组可以有多个成员，一个用户也可以属于多个组

```bash
# 看 lisi 的完整身份（最直观的一条命令）
id lisi
# 输出：uid=1001(lisi) gid=1001(lisi) groups=1001(lisi),10(wheel),992(docker)
#              ↑身份证号        ↑主组（只有一个）      ↑所属的全部组（主组+附加组）

#另外附加:
ls -lh  #只能查看当前文件夹内部的权限
[qyz@lee02 /]$ ls -lh tmp 是查看tmp文件夹下面的文件的权限
如果想查看当前我已经进入的文件夹的权限，不是里面内容 用 ls -ld
如果想查看当前我没有进入的文件夹的权限，那就先查当前文件夹里面的内容，再过滤：例如/tmp/redir_test  我进入了tmp 想查看
redir_test的权限，我可以用 ls -lh | grep redir_test  不需要从根目录出发 不要这样写 ls -lh | grep /tmp/redir_test
```

上面这个输出的含义：lisi 的主组是 `lisi`，附加组是 `wheel`（可以 sudo 提权）和 `docker`（可以操作 Docker），**加入组就是获取权限最常见的方式**：

| 想让 lisi 干什么 | 做法 | 本质 |
|------------------|------|------|
| 能执行 sudo 管理命令 | `usermod -aG wheel lisi` | 加进 wheel 附加组 |
| 能操作 docker | `usermod -aG docker lisi` | 加进 docker 附加组 |
| 和同事共同读写 /shared 目录 | 大家加进同一个组，目录属组设为该组并开组权限 | 用组批量授权 |

> 💡 `-aG` 里的 **-a（append 追加）一定不能漏**：只写 `-G` 会把附加组**覆盖**成你写的这几个，原来加入的 wheel、docker 全没了。改完后**重新登录**才生效（详见 8.5 节）。

### 8.2 用户相关的核心文件（必会）
> 🏷️ ⭐ 开发必会 —— 排查"为什么登录不上/为什么没权限"必看

Linux 用 4 个文件记录用户和组的信息，密码单独加密存放在 shadow 里。

**① `/etc/passwd` —— 用户账户信息（所有人可读）**

每行一个用户，用冒号 `:` 分隔成 7 个字段：

```
root:x:0:0:root:/root:/bin/bash
 │   │ │ │  │     │       └── 7.登录 shell（/sbin/nologin 表示禁止登录）
 │   │ │ │  │     └────────── 6.家目录
 │   │ │ │  └──────────────── 5.描述信息（GECOS，注释用）
 │   │ │ └─────────────────── 4.主组 GID
 │   │ └───────────────────── 3.UID
 │   └─────────────────────── 2.密码占位符（真实密码在 /etc/shadow；x 表示有密码）
 └────────────────────────── 1.用户名
```

**② `/etc/shadow` —— 加密密码与密码策略（仅 root 可读）**

每行 9 个字段：

```
lisi:$6$abc...:19500:0:99999:7:::
 │     │         │    │   │    │ │ └── 9.保留字段（保留给未来使用，目前为空）
 │     │         │    │   │    │ └──── 8.账号过期日期（从 1970-01-01 算起的天数；空=不过期）
 │     │         │    │   │    └────── 7.密码失效宽限（天，密码过期后还能登录改密的天数，过后账号锁定）
 │     │         │    │   └─────────── 6.密码过期前警告（天，提前 N 天提醒）
 │     │         │    └─────────────── 5.密码最小使用期（天，0=可立即改密码）
 │     │         └──────────────────── 4.密码最大有效期（天，99999=不过期）
 │     │────────────────────────────── 3.上次改密日期（从 1970-01-01 算起的天数）
 │     └────────────────────────────── 2.加密后的密码（! 或 * 开头=锁定，空=无需密码）
 └──────────────────────────────────── 1.用户名
```

> 💡 **字段 7 vs 字段 8 别搞混**：字段 7 是**密码**过期后还能宽限几天（仍可登录改密）；字段 8 是**账号**整体到期日（到了这天账号直接失效，与密码无关）。两者完全独立。

**③ `/etc/group` —— 用户组信息（所有人可读）**

每行 4 个字段：

```
wheel:x:10:lisi,zhangsan
│      │  │  └── 4.组成员（属于该组但主组不是它的用户）
│      │  └──── 3.组 GID
│      └─────── 2.组密码占位符（基本不用）
└───────────── 1.组名
```

**④ `/etc/gshadow` —— 组的加密密码与管理员（仅 root 可读）**

**⑤ `/etc/skel` —— 新用户家目录的模板**
`useradd` 创建用户时，会把该目录下的所有文件（如 `.bashrc`、`.bash_profile`）复制到新用户家目录。想给所有新用户统一加配置（别名、提示符等），就改这里。

**⑥ `/etc/login.defs` —— 创建用户的默认值**
定义默认邮箱目录、密码有效期、UID/GID 起始范围等。`useradd` 不写参数时的默认值大多来自这里：

```bash
grep -E '^(UID_MIN|UID_MAX|PASS_MAX_DAYS|CREATE_HOME)' /etc/login.defs
```

### 8.3 useradd — 创建用户（必会）
> 🏷️ ⭐ 开发必会 —— 创建账号的高频命令

用 `useradd` 而不是手动编辑 `/etc/passwd`，因为它会自动完成更新 passwd/shadow/group、分配 UID、可选建家目录并复制 `/etc/skel` 模板等一整套动作。

> ⚠️ **必须用 root 权限**（`sudo` 或 root 身份）执行，否则会因无法写 `/etc/passwd`、`/etc/shadow`、`/home` 而失败。下面示例为简洁省略了 `sudo`，实操时请在前面加 `sudo`。

**语法：** `useradd [选项] 用户名`

**常用选项：**

| 选项 | 作用 | 示例 |
|------|------|------|
| `-u` | 指定 UID | `useradd -u 1200 lisi` |
| `-g` | 指定主组（组名或 GID，组必须已存在） | `useradd -g dev lisi` |
| `-G` | 指定附加组（可多个，逗号分隔） | `useradd -G wheel,dev lisi` |
| `-d` | 指定家目录路径（只改记录，**不自动创建**） | `useradd -d /data/lisi lisi` |
| `-m` | **强制创建家目录**并复制 `/etc/skel` 模板（推荐显式带上） | `useradd -m lisi` |
| `-M` | 显式不创建家目录 | `useradd -M lisi` |
| `-s` | 指定登录 shell | `useradd -s /bin/bash lisi` |
| `-c` | 添加描述信息（备注） | `useradd -c "开发-李四" lisi` |
| `-e` | 指定账号过期日期 | `useradd -e 2026-12-31 lisi` |
| `-r` | 创建系统用户（UID<1000、默认不建家目录、无 shell） | `useradd -r mysql` |
| `-p` | 指定**已加密**的密码（不常用，明文改密用 `passwd` 或 `chpasswd`） | 一般改用 `passwd` |

> 💡 **关于家目录的"默认行为"**：`useradd` 不带 `-m` 时是否建家目录，由 `/etc/login.defs` 里的 `CREATE_HOME` 决定。**不同发行版默认不同**：Debian/Ubuntu 默认 `no`（不建），RHEL/CentOS 8+ 默认 `yes`。**跨发行版想保证有家目录，必须显式带 `-m`**。

**示例（按日常使用频率排序）：**

```bash
# ① 90% 的场景就用这一条：建普通用户（-m 建家目录，其他都默认）
sudo useradd -m lisi

# ② 建完立刻给 sudo 权限（不用重新建用户）
sudo usermod -aG wheel lisi    # -aG 是追加到附加组，不会覆盖已有组
# 注：useradd -G wheel lisi 也能一步到位，但日常更常用"先建再改"

# ③ 建服务账号（给 nginx、mysql 这种进程用，不需要登录系统）
sudo useradd -r -s /sbin/nologin appuser
# -r    → 系统用户（UID 自动给一个 1~999 的值，不属于普通用户段）
# -s /sbin/nologin → 禁止交互登录（即使有密码也登不进）
# 这种账号用来"跑服务"，不是给人用的
```

**下面这些选项工作中几乎不用手敲**（记住有这些能力即可，需要时回来查表）：

```bash
# 一次性配全所有属性（不推荐新手用，参数太多容易出错，分步更稳）
sudo useradd -m -g dev -G wheel -c "后端开发-李四" -s /bin/bash lisi

# 把家目录放到 /data 而不是默认 /home（特殊需求才用，比如 /data 是独立数据盘）
sudo useradd -d /data/lisi -m lisi
```

> 💡 **新手判断标准**：
> - **必须会**：示例 ①（`useradd -m 用户名`）+ ②（`usermod -aG wheel` 给 sudo）
> - **知道有这回事**：示例 ③（服务账号），学了 Nginx/MySQL 部署后会回头来建
> - **不用死记**：示例 ④（-d 自定义家目录）、`-u` 指定 UID、`-c` 备注等，需要时回来查选项表

创建后必须设密码才能登录：

```bash
sudo passwd lisi
```

> 💡 **为什么"没加 -m，设完密码登录后家目录也出现了"？** 这是 PAM 模块 `pam_mkhomedir` 的功劳：部分系统配置了"首次登录时自动补建家目录"（CentOS 7 图形安装或执行过 `authconfig --enablemkhomedir` 后生效）。但这是**登录时的补救机制，不是 useradd 的功劳**——没登录前 `/home/lisi` 就是不存在，写文件进去会失败。所以规矩不变：**建用户一律显式加 -m**，不要赌登录补救。

> ⚠️ **建完用户马上会遇到的问题**：`lisi` 现在**还不能用 sudo**，一执行就报"lisi 不在 sudoers 文件中。此事将被报告。"——需要 root 执行 `sudo usermod -aG wheel lisi` 并重新登录，完整排查见 [8.9.1](#)。

### 8.4 passwd — 设置/修改密码（必会）
> 🏷️ ⭐ 开发必会 —— 改密码、锁账号的高频命令

普通用户只能改自己的密码，root 可以改任何用户的密码。

**语法：** `passwd [选项] [用户名]`（不写用户名 = 改自己的）

**常用选项：**

| 选项 | 作用 |
|------|------|
| 无 | 交互式设置/修改密码 |
| `-l` | 锁定账号（shadow 中密码前加 `!`，禁止登录） |
| `-u` | 解锁账号 |
| `-d` | 删除密码（账号可无密码登录，慎用） |
| `-S` | 查看账号密码状态 |
| `-e` | 强制用户下次登录改密码 |
| `-n 天` / `-x 天` | 设置密码最小/最大使用天数 |
| `-w 天` | 过期前警告天数 |
| `-i 天` | 过期后宽限天数 |
| `--stdin` | 从标准输入读密码（脚本批量设置用，免交互。⚠️ **仅 RHEL/CentOS/Fedora 系列**支持，Debian/Ubuntu 的 passwd 无此选项） |

**示例：**

```bash
# 1. 修改自己的密码
passwd

# 2. root 改其他用户密码
passwd lisi

# 3. 查看密码状态（L=锁定、NP=无密码、PS=有密码）
passwd -S lisi

# 4. 锁定 / 解锁账号
passwd -l lisi     # 锁定，lisi 无法登录
passwd -u lisi     # 解锁

# 5. 强制用户下次登录改密码
passwd -e lisi

# 6. 脚本免交互批量设密码（CentOS/RHEL 系可用 --stdin）
echo 'NewPass@123' | passwd --stdin lisi

#    跨发行版通用写法：用 chpasswd（Debian/Ubuntu/CentOS 都支持）
echo 'lisi:NewPass@123' | sudo chpasswd
```

### 8.5 usermod — 修改用户（必会）
> 🏷️ ⭐ 开发必会 —— 加 sudo 权限、改组、改 shell 必用

修改已有用户的属性（组、家目录、shell、过期时间等）。

**语法：** `usermod [选项] 用户名`

**常用选项：**

| 选项 | 作用 |
|------|------|
| `-u` | 修改 UID |
| `-g` | 修改主组 |
| `-G` | 重新设置附加组（**会覆盖原有附加组**） |
| `-aG` | 追加附加组（保留原有基础上再加，最常用） |
| `-d` | 修改家目录（只改记录，不移动目录） |
| `-m` | 配合 `-d` 把旧家目录内容搬到新目录 |
| `-s` | 修改登录 shell |
| `-c` | 修改描述信息 |
| `-l` | 修改用户名（重命名） |
| `-L` / `-U` | 锁定 / 解锁（等价 passwd -l/u） |
| `-e` | 修改账号过期日期 |

**示例：**

```bash
# 1. 把 lisi 追加进 wheel 组（保留原组）—— 最常用，加 sudo 权限
usermod -aG wheel lisi

# 2. 主组改成 dev，附加组设为 wheel,docker（覆盖式）
usermod -g dev -G wheel,docker zhangsan

# 3. 改成禁止登录
usermod -s /sbin/nologin lisi

# 4. 改用户名（老名 → 新名）
usermod -l newname oldname

# 5. 改家目录并迁移文件
usermod -d /data/lisi -m lisi
```

> ⚠️ `-G` 会覆盖原有附加组，`-aG` 才是追加。想把用户加进多个组时务必用 `-aG`，否则之前的附加组会丢。

### 8.6 userdel — 删除用户（必会）
> 🏷️ ⭐ 开发必会 —— 删账号用

**语法：** `userdel [选项] 用户名`

| 选项 | 作用 |
|------|------|
| 无 | 只删用户记录（不删家目录和邮件） |
| `-r` | 连同家目录、邮件一起删除 |

**示例：**

```bash
# 只删账号，保留家目录文件
userdel lisi

# 删账号 + 删家目录 + 删邮件（彻底清除）
userdel -r lisi
```

> ⚠️ 删除前先 `id 用户名` 确认该用户是否还在跑进程；若仍有进程以该用户身份运行，删除会导致归属异常。

### 8.7 用户组管理（必会）
> 🏷️ ⭐ 开发必会 —— 统一授权、分组管理必用

组的作用：把"一类人"归到一起，方便统一授权（如开发组 dev 共享一份代码目录）。

**groupadd — 创建组**

```bash
groupadd dev             # 创建普通组（自动分配 GID）
groupadd -g 2000 dev     # 指定 GID
groupadd -r sysgrp       # 创建系统组
```

**groupmod — 修改组**

```bash
groupmod -g 2001 dev     # 改 GID
groupmod -n devops dev   # 改组名 dev → devops（-n 指定新名）
```

**groupdel — 删除组**

```bash
groupdel dev
# 注意：不能删除任何用户的主组；先移走成员或删用户
```

**gpasswd — 管理组成员**

| 选项 | 作用 |
|------|------|
| `-a 用户` | 把用户加入组 |
| `-d 用户` | 把用户移出组 |
| `-r` | 删除组密码 |
| `-A 用户,...` | 设置组管理员 |
| `-M 用户,...` | 设置组成员列表（覆盖式） |

```bash
gpasswd -a lisi dev              # 把 lisi 加进 dev 组
gpasswd -d lisi dev              # 把 lisi 移出 dev 组
gpasswd -M lisi,zhangsan dev     # 设置组员（覆盖）
```

> `gpasswd -a` 等价于 `usermod -aG`，都是"追加到组"的常用写法。

**newgrp — 临时切换主组**

```bash
newgrp dev        # 当前会话临时把主组切到 dev（需要组密码或自己就是组成员）
```

```bash
# id：查看用户的 UID / GID / 附加组（最常用，验证用户配置是否正确）

# uid=1001(lisi) gid=1001(lisi) groups=1001(lisi),10(wheel)
```

### 8.9 sudo 与 sudoers 补充（必会）
> 🏷️ ⭐ 开发必会 —— su / sudo 基本用法见【第一章 10.1.7】，这里补 sudoers 精细化配置

**① 先认识 wheel 组——CentOS 的"管理员组"**

你前面建完用户后用 `sudo usermod -aG wheel 用户名` 给 sudo 权限，但 wheel 到底是个什么东西？

- wheel 是 CentOS/RHEL 系统预置的一个**特殊用户组**（GID 固定为 10），名字来自"steering wheel（方向盘）"——寓意"掌握方向盘的人"，即系统管理者
- 它的特殊之处不在组本身，而在 `/etc/sudoers` 里默认就有这一行（已启用）：

```
%wheel  ALL=(ALL)       ALL
```

- 意思是"wheel 组的所有成员，可以在任何主机上以任何用户身份执行任何命令"——**所以把一个人加进 wheel 组，他就自动获得了完整 sudo 权限，不用手动改 sudoers 文件**
- 这也是 CentOS 推荐的授权方式：比直接改 `/etc/sudoers` 安全得多（改坏语法会导致所有 sudo 失效，连 root 都救不回来，只能进单用户模式）

```bash
# 常用三连
sudo usermod -aG wheel lisi        # 给 lisi sudo 权限（-aG 追加，别漏 -a）
id lisi                            # 确认 groups 里出现了 10(wheel)
grep wheel /etc/group              # 看当前 wheel 组里有哪些人
# wheel:x:10:lisi,zhangsan
```

> 💡 **Ubuntu 没有 wheel 组**，对应的是 `sudo` 组（名字就叫 sudo）。所以 Ubuntu 里授权是 `usermod -aG sudo 用户名`，原理完全一样——组名写在 sudoers 里，进组就有权限。

**② sudoers 文件与 visudo**

sudoers 文件 `/etc/sudoers` 定义"谁在哪些主机上能以谁的身份执行哪些命令"。**必须用 `visudo` 编辑**（保存时自动做语法校验，写错会导致 sudo 全部失效）。

```bash
visudo     # 等价于编辑 /etc/sudoers，带语法检查
```

**sudoers 规则格式：**

```
用户/组   主机=(可切换到的身份)   可执行的命令
```

**常用示例：**

```bash
# 1. 给单个用户完整 sudo 权限（等价 root）
lisi    ALL=(ALL)       ALL

# 2. 给整个组完整 sudo 权限（% 开头代表组，如 wheel）
%wheel  ALL=(ALL)       ALL

# 3. 免密 sudo（NOPASSWD，脚本 / 自动化常用）
lisi    ALL=(ALL)       NOPASSWD: ALL

# 4. 只允许执行特定命令（最小权限）
lisi    ALL=(root)      /usr/bin/systemctl restart nginx, /usr/bin/systemctl status nginx

# 5. 只允许执行某命令且免密
deploy  ALL=(ALL)       NOPASSWD: /usr/bin/systemctl restart nginx
```

**验证配置：**

```bash
sudo -l            # 查看当前用户能执行哪些 sudo 命令
sudo -l -U lisi    # 查看 lisi 用户能执行哪些
```

#### ⚠️ 8.9.1 常见报错："zhangsan 不在 sudoers 文件中。此事将被报告。"

**完整报错长这样：**

```
[zhangsan@localhost ~]$ sudo useradd wangwu
[sudo] password for zhangsan:
zhangsan 不在 sudoers 文件中。此事将被报告。
# 英文系统显示：zhangsan is not in the sudoers file.  This incident will be reported.
```

**这句话什么意思？**

- "不在 sudoers 文件中" = zhangsan 没有被授权使用 sudo。CentOS 7 里只有 **root 自己**和 **wheel 组的成员**能用 sudo
- "此事将被报告" 不是有人要找你麻烦，只是说这次越权尝试会被记进安全日志 `/var/log/secure`
- **根因**：`useradd zhangsan` 只建了账号，**不会自动把他加进 wheel 组**（第 8.3 节建完用户如果忘了 `usermod -aG wheel`，就会遇到这个错）

**解决步骤（必须用 root 身份操作，sudo 都用不了就别再用 sudo 了）：**

```bash
# 第 1 步：先拿到 root 身份（三选一）
#   ① 知道 root 密码：直接切
su -                    # 输 root 密码，提示符变成 #
#   ② VMware 控制台里直接用 root 登录
#   ③ 云服务器：用厂商网页控制台的 VNC 以 root 登录

# 第 2 步：把 zhangsan 加进 wheel 组（-a 追加，别漏；漏掉 -a 会覆盖掉他的其他附加组）
usermod -aG wheel zhangsan

# 第 3 步：确认加进去了
id zhangsan
# 应能看到 groups=...10(wheel)
grep wheel /etc/group   # wheel:x:10:zhangsan

# 第 4 步：让组成员身份生效（关键，很多人做完第 2 步就去试，结果还报错）
#   最稳妥：退出重新登录
exit                    # 退出 root，再 exit 退出 zhangsan，重新用 zhangsan 登录
#   不想退出登录的临时办法：
newgrp wheel            # 当前会话临时切到 wheel 组（开新终端还是要重新登录）

# 第 5 步：验证
sudo whoami             # 输 zhangsan 自己的密码，输出 root = 成功
sudo -l                 # 列出 zhangsan 被允许的 sudo 命令
```

**为什么加进 wheel 组就可以了？** 上面 ① 已讲过：CentOS 的 `/etc/sudoers` 默认启用了 `%wheel ALL=(ALL) ALL`，进组即获权。

**其他相关情况：**

| 现象 | 原因 | 处理 |
|------|------|------|
| 加了 wheel 组、重新登录了还是报错 | CentOS 装系统时 wheel 那行被注释了 | root 执行 `visudo`，确认 `%wheel ALL=(ALL) ALL` 前面**没有 #** |
| 不想给全部权限，只让他能重启 nginx | 用最小授权 | `visudo -f /etc/sudoers.d/zhangsan`，写入 `zhangsan ALL=(root) /usr/bin/systemctl restart nginx`（放在 sudoers.d 目录下的独立文件，比改主文件安全） |
| 每次 sudo 都要输密码，想免密 | 自动化场景 | 独立文件中写 `zhangsan ALL=(ALL) NOPASSWD: ALL`（学习机可以，生产慎用） |
| 想确认刚才的"报告"记在哪 | 看安全日志 | root 执行 `tail /var/log/secure`，能看到 `incorrect sudo attempts` 记录 |

### 8.10 实用速查（必会）

| 我要做什么 | 命令 |
|------------|------|
| 建普通用户（带家目录） | `sudo useradd -m 用户名` |
| 给用户设密码 | `sudo passwd 用户名` |
| 给用户 sudo 权限 | `sudo usermod -aG wheel 用户名` |
| 切换到某用户 | `su - 用户名` |
| 临时用 root 跑命令 | `sudo 命令` |
| 切回 root | `su -` 或 `sudo -i` |
| 删除用户（保留家目录） | `sudo userdel 用户名` |
| 删除用户 + 清家目录 | `sudo userdel -r 用户名` |
| 看登录中的用户 | `w` 或 `who` |
| 看登录历史 | `last` |
| 查看用户 uid/gid/组 | `id 用户名` |

> 💡 **批量建用户**（如新员工入职 10 人）：用 shell 循环 `for u in user{01..10}; do sudo useradd -m $u && echo "$u:Pass@123" | sudo chpasswd; done`——但这不是开发岗日常，需要时回来抄。
