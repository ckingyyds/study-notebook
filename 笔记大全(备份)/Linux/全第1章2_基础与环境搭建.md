## 9. Linux 目录结构（必会）(正式学习)

> 🏷️ ⭐ 开发必会 —— 软件开发日常高频使用，务必掌握

### 9.1 FHS 标准与树形结构（必会）

> 🏷️ 📖 概念了解 —— 知道这个标准存在就行，遇到疑惑时回来查

Linux 的目录结构**不是随便长的**，它遵循 **FHS（Filesystem Hierarchy Standard，文件系统层次标准）**，由 Linux 基金会维护（现行 FHS 3.0）。为什么需要这个标准？

- **跨发行版兼容**：不管是 CentOS、Ubuntu 还是 openSUSE，`/etc/passwd` 永远是用户账户文件，`/var/log/` 永远是日志目录——你在 A 发行版上学会的东西，在 B 发行版上直接能用
- **软件开发者**：写安装脚本时知道该把二进制放 `/usr/bin/`、配置放 `/etc/`、日志放 `/var/log/`，不用每个发行版写一套
- **运维/排障**：出错了知道去哪里找东西，不用满硬盘乱搜

FHS 把目录分成三层：

| 层次             | 目录                              | 用途                                           |
| ---------------- | --------------------------------- | ---------------------------------------------- |
| **可共享且只读** | `/usr`                            | 系统软件、命令、库文件、文档（装好后一般不改） |
| **可共享可写**   | `/home`、`/var/mail`              | 多台机器可挂载同一个目录                       |
| **不可共享**     | `/etc`、`/var/lib/nginx`、`/proc` | 本机私有，不能跨机器共享                       |

**树形结构**：Linux 使用 **单根（`/`）** 的树形目录结构，所有文件和目录都从根节点开始往下分支——不像 Windows 有 C:、D: 多个盘符。

### 9.2 "一切皆文件" —— Linux 核心哲学

> 🏷️ 📖 概念了解 —— 理解这个理念，后面很多困惑会豁然开朗

这是 Linux 最重要的设计理念，也是和 Windows 区别最大的地方：

| 在 Linux 里... | 本质上就是一个文件                                       |
| -------------- | -------------------------------------------------------- |
| 普通文本、程序 | 文件 ✅                                                   |
| 目录           | 也是文件（存着该目录下有哪些文件）                       |
| 硬盘、U盘      | `/dev/sda`、`/dev/sdb` —— 文件                           |
| 鼠标、键盘     | `/dev/mouse`、`/dev/input/event0` —— 文件                |
| 显示器         | `/dev/null`（黑洞）、`/dev/zero`（吐零）—— 文件          |
| 网络接口       | `/dev/tcp/host/port`（bash 内置访问）、`/sys/class/net/` |
| 进程信息       | `/proc/1234/` —— 目录型"文件"                            |
| 系统参数       | `/proc/sys/...` —— 可读写的虚拟文件                      |
| 管道、Socket   | 特殊类型的文件                                           |

**意义**：你可以用同一套工具（`cat`/`echo`/`cp`/`chmod`/重定向 `>`）操作几乎所有东西，不用针对硬盘学一套 API、针对进程再学一套。这也是为什么 `echo 3 > /proc/sys/vm/drop_caches` 就能清理缓存——你就是在"写"一个文件而已。

### 9.3 核心目录一览（完整树形图）（必会）

> 🏷️ ⭐ 开发必会 —— 这张图先建立整体印象，后面每节逐个拆解

```
/ (根目录，FHS 顶层)
├── bin/        ← /usr/bin 的软链接（CentOS 7+）
├── sbin/       ← /usr/sbin 的软链接
├── lib/        ← /usr/lib 的软链接
├── lib64/      ← /usr/lib64 的软链接
├── boot/       启动引导文件（内核 vmlinuz、GRUB 配置、initramfs）
├── dev/        设备文件（块设备/字符设备，由 udev 动态生成）**设备文件**，用来操作硬件（读写硬件、发指令），是硬件的访问入口**
├── etc/        系统级配置文件（FHS 规定的配置中心）
│   ├── passwd         用户账户信息
│   ├── shadow         用户密码（加密存储）
│   ├── group          用户组信息
│   ├── fstab          开机自动挂载表
│   ├── hosts          本地 DNS 映射（IP ↔ 主机名）
│   ├── hostname       主机名（CentOS 7+）
│   ├── resolv.conf    DNS 服务器配置
│   ├── sudoers        sudo 权限规则
│   ├── crontab        系统级定时任务
│   ├── yum.repos.d/   YUM 软件源配置
│   ├── sysconfig/     服务级配置（network、iptables 等）
│   ├── ssh/           SSH 服务端/客户端密钥与配置
│   ├── profile.d/     Shell 环境变量脚本（登录时自动加载）
│   └── my.cnf         MySQL 配置（如果装了 MySQL）
├── home/       普通用户家目录
│   ├── alice/         用户 alice 的个人目录
│   └── bob/           用户 bob 的个人目录
├── lib/        ← /usr/lib 软链接（CentOS 7+）
├── lib64/      ← /usr/lib64 软链接
├── media/      可移动介质自动挂载点（U盘、光盘，桌面版插上自动挂到 /media/用户名/卷名）
├── mnt/        临时挂载点（自己 mount 用的"空文件夹"）。平时例子：① VMware 共享文件夹挂在 /mnt/hgfs（虚拟机和宿主机互传文件）；② WSL 里访问 Windows 盘：/mnt/c、/mnt/d；③ 临时插 U 盘/移动硬盘：mount /dev/sdb1 /mnt/usb；④ 临时连公司 NFS 共享
├── opt/        自己额外装的软件，一个软件一个文件夹（类似 Windows 的 Program Files）。平时例子：① Linux 版 Chrome 装 /opt/google/chrome；② JetBrains 全家桶（IDEA/PyCharm）Toolbox 装 /opt；③ 解压版 Tomcat 放 /opt/tomcat；④ JDK 放 /opt/jdk；⑤ 企业微信/腾讯会议 Linux 版也在这
├── proc/       进程和系统信息（虚拟文件系统，不占磁盘空间）
│   ├── cpuinfo        CPU 型号/核心数/频率
│   ├── meminfo        内存总量/已用/可用
│   ├── version        内核版本与编译时间
│   ├── [PID]/         每个运行中进程的状态、命令行、打开文件
│   ├── mounts         当前已挂载的文件系统
│   └── sys/           内核运行时参数
├── root/       root 用户家目录（注意：不是 /home/root）
├── run/        运行时数据（PID 文件、Socket 文件，重启清空）
├── srv/        服务数据目录（如 FTP 服务器的文件放 /srv/ftp）
├── sys/        硬件与驱动信息（虚拟文件系统，由内核导出）**硬件信息描述，用来查看硬件属性、参数，是硬件的信息档案**
│   ├── class/net/     所有网络接口
│   ├── block/         所有块设备（硬盘分区）
│   └── devices/       设备驱动树
├── tmp/        临时文件目录（所有人可写，特殊权限：满 30 天自动清理）
├── usr/        系统软件主目录（FHS 中最大、最核心的目录）
│   ├── bin/           常规用户命令（ls, cp, git, python...）
│   ├── sbin/          系统管理命令（需要 root 权限，如 ip, iptables, useradd）
│   ├── lib/           共享库文件（so 文件，供程序调用）
│   ├── lib64/         64 位共享库
│   ├── include/       C/C++ 头文件（开发时 #include <...> 的来源）
│   ├── local/         管理员手动安装的软件（优先级最高，通常 ./configure && make install 放这）
│   │   ├── bin/       自定义命令
│   │   ├── lib/       自定义库
│   │   └── share/     自定义共享资源
│   ├── share/         只读共享资源
│   │   ├── doc/       软件文档
│   │   ├── man/       手册页（man 命令从这里读）
│   │   ├── locale/    语言包（i18n）
│   │   └── zoneinfo/  时区数据
│   ├── src/           内核源码（可选安装）
│   └── X11R6/         X11 图形窗口系统（如果装了 GUI）
└── var/        可变数据（运行中不断变化的内容，体积可能很大）
    ├── log/           系统和服务日志（排障第一站）
    │   ├── messages       系统综合日志（含内核/服务/驱动）
    │   ├── secure         安全日志（SSH 登录、sudo 记录）
    │   ├── cron           定时任务执行日志
    │   ├── boot.log       启动过程日志
    │   ├── dmesg          内核环形缓冲区日志（dmesg 命令读的就是这个）
    │   ├── yum.log        YUM 安装/卸载记录
    │   ├── audit/         SELinux 审计日志
    │   └── nginx/         Nginx 访问/错误日志
    ├── run/           ← /run 的软链接（兼容老路径）
    ├── tmp/           临时文件（比 /tmp 保留时间稍长，约 10 天）
    ├── lib/           服务持久数据（MySQL 数据放 /var/lib/mysql、Redis 快照、Docker 镜像）
    ├── cache/         应用缓存（YUM 下载的 RPM 包、pip 缓存）
    ├── opt/           /opt 下第三方软件运行产生的可变数据（如 /var/opt/oracle）
    ├── mail/          用户邮件（老服务器用，现在很少）
    ├── spool/         队列数据（打印队列、定时任务队列）
    └── www/           Web 服务文档根目录（Nginx/Apache 的默认站点，CentOS 特有路径）
```

### 9.4 各目录深度详解（必会）

> 🏷️ ⭐ 开发必会 —— 重点看 ⭐ 标记的目录，是你每天会接触的

#### ⭐ /usr —— 系统软件的主体

**FHS 定义**：`/usr` 是"Unix System Resources"的缩写（不是 "user"！容易误解），存放**可共享、只读**的系统软件和资源。

关键子目录：

| 目录                      | 内容                                                | 说明                                     |
| ------------------------- | --------------------------------------------------- | ---------------------------------------- |
| `/usr/bin`                | 用户命令（ls, cp, git, python, java...）            | 普通用户和 root 都能执行                 |
| `/usr/sbin`               | 系统管理命令（ip, iptables, useradd, systemctl...） | 一般需要 root 权限执行                   |
| `/usr/lib` + `/usr/lib64` | 动态链接库（`.so` 文件）                            | 程序运行时需要的共享库                   |
| `/usr/local`              | **管理员自己安装的软件**                            | 优先级高于 `/usr/bin`，`PATH` 里排在前面 |

**为什么 `/bin`、`/lib`、`/sbin` 在 CentOS 7 里变成了软链接？**

- 历史原因：早期 `/` 分区空间小，核心工具单独放 `/bin`、`/lib` 以便在 `/usr` 还没挂载时就能启动系统
- 现代系统 `/` 和 `/usr` 通常在同一个分区，FHS 合并了它们
- CentOS 7+ 做了软链接：`/bin → /usr/bin`、`/lib → /usr/lib`、`/sbin → /usr/sbin`，**但兼容性保留**——老脚本写 `/bin/ls` 照样能跑

#### ⭐ /etc —— 配置中心（你改得最多的目录）

**FHS 定义**：所有**系统级配置文件**都在这里。

你作为开发者/运维实际会改的文件（以下命令可直接复制到终端运行）：

```bash
# ===== 用户与权限 =====
cat /etc/passwd          # 查看所有用户（只可读，加密密码在 shadow）
cat /etc/shadow          # 查看加密密码（仅 root 可读，普通用户会拒绝）
cat /etc/group           # 查看所有用户组
visudo                   # 修改 sudo 权限（必须用 visudo！别直接 vim，语法错了 sudo 全挂）

# ===== 网络 =====
cat /etc/hosts           # 本地 DNS 映射，紧急修复域名解析时用
cat /etc/resolv.conf     # DNS 服务器地址
cat /etc/sysconfig/network-scripts/ifcfg-ens33   # 网卡配置文件（CentOS 7）
# Rocky 9 / CentOS Stream 9 用 nmcli，不再用这个文件

# ===== 服务配置（按装了什么服务）=====
ls /etc/nginx/nginx.conf           # Nginx 主配置（用 ls 确认是否存在）
ls /etc/my.cnf                     # MySQL 主配置
ls /etc/redis/redis.conf           # Redis 配置
cat /etc/ssh/sshd_config           # SSH 服务端配置（改端口、禁 root 登录）
cat /etc/crontab                   # 系统级定时任务
cat /etc/profile                   # 全局环境变量（所有用户登录时加载）
ls /etc/profile.d/*.sh             # 环境变量脚本（每个 .sh 会被 profile source）

# ===== YUM 软件源 =====
ls /etc/yum.repos.d/*.repo         # 软件源配置（换国内源时改这里）
cat /etc/yum.repos.d/CentOS-Base.repo   # 看当前源配置

# ===== 要编辑某个配置文件，用 vi 或 vim =====
# 示例：编辑 SSH 配置
sudo vi /etc/ssh/sshd_config
# 改完按 Esc，输入 :wq 保存退出
# 改完服务配置要重启服务才生效：
sudo systemctl restart sshd
```

**绝对不要直接编辑的文件**：`/etc/passwd`（改用 `useradd/usermod`）、`/etc/sudoers`（必须用 `visudo`，否则语法错了 sudo 全挂）

#### ⭐ /var —— 变化的数据（体积可能暴增）

**FHS 定义**：存放运行中**不断变化**的数据。

最重要的几个子目录（以下命令可直接复制运行）：

```bash
ls /var/log/           # 🎯 排障第一站，90% 的问题从这里找答案
ls /var/lib/           # 服务持久数据
ls /var/lib/mysql/     # MySQL 数据库文件（你的业务数据在这里！定期备份）
ls /var/lib/redis/     # Redis RDB/AOF 文件
ls /var/lib/docker/    # Docker 镜像、容器数据
ls /var/lib/nginx/     # Nginx 临时文件
ls /var/cache/        # 缓存（YUM 下载的 RPM 包、pip 缓存等，可安全删除）
ls /var/opt/          # /opt 下第三方软件的运行数据（日志/数据文件，详见后文 /opt 小节）
ls /var/run/           # PID 文件（进程号文件，如 /var/run/nginx.pid），/run 的兼容路径
ls /var/spool/         # 队列（打印队列、邮件队列）
du -sh /var/log/*      # 看哪个日志最占空间
du -sh /var/lib/mysql/ # 看 MySQL 数据多大
```

**⚠️ 磁盘空间预警**：`/var/log` 和 `/var/lib/mysql` 最容易把磁盘撑满，定期用 `du -sh /var/log/*` 看看。

#### ⭐ /proc —— 虚拟文件系统（实时系统信息）

**FHS 定义**：不是真文件，是**内核数据的接口**，读取时内核动态生成内容。

常用文件：

```bash
cat /proc/cpuinfo        # 查 CPU（model name、cores、siblings）
cat /proc/meminfo        # 查内存（MemTotal、MemAvailable）
cat /proc/version        # 内核版本
cat /proc/loadavg        # 系统负载（前三个数字是 1/5/15 分钟平均）
cat /proc/mounts         # 当前挂载点（比 mount 命令输出更干净）
ls /proc/1234/           # 查看 PID 1234 进程的全部信息
cat /proc/1234/cmdline   # 该进程启动命令
cat /proc/1234/status    # 该进程状态（VmRSS 是实际内存占用）
cat /proc/sys/net/ipv4/ip_forward   # 是否开启 IP 转发
echo 1 > /proc/sys/net/ipv4/ip_forward   # 临时开启（重启失效）
```

**特点**：`ls -l /proc/cpuinfo` 显示大小为 0 字节——因为它不是真文件，读的时候才生成。

#### /sys —— 硬件信息（另一个虚拟文件系统）

和 `/proc` 类似但更结构化，主要存**硬件与驱动**信息：

```bash
ls /sys/class/net/              # 列出所有网络接口（含 Docker 虚拟网卡）
cat /sys/class/net/ens33/speed # 网卡速率
cat /sys/block/sda/queue/nr_requests  # 硬盘队列深度
```

#### /dev —— 设备文件

**FHS 定义**：硬件设备在文件系统里的映射，由 `udev` 系统动态生成。

常用设备文件：

| 文件           | 类型     | 用途                                                         |
| -------------- | -------- | ------------------------------------------------------------ |
| `/dev/sda`     | 块设备   | 第一块硬盘（整块）                                           |
| `/dev/sda1`    | 块设备   | 第一块硬盘的第一个分区                                       |
| `/dev/sdb`     | 块设备   | 第二块硬盘（U盘插上通常是这个）                              |
| `/dev/null`    | 字符设备 | 黑洞，写入的东西全部丢弃（`command > /dev/null 2>&1` 静默错误） |
| `/dev/zero`    | 字符设备 | 源源不断输出二进制 0（`dd if=/dev/zero of=file bs=1M count=100` 造测试文件） |
| `/dev/random`  | 字符设备 | 真随机数生成器（慢，阻塞）                                   |
| `/dev/urandom` | 字符设备 | 伪随机数生成器（快，非阻塞，大多数场景用这个）               |
| `/dev/tty`     | 字符设备 | 当前终端                                                     |
| `/dev/stdin`   | 字符设备 | 标准输入（fd 0）                                             |
| `/dev/stdout`  | 字符设备 | 标准输出（fd 1）                                             |
| `/dev/stderr`  | 字符设备 | 标准错误（fd 2）                                             |

**块设备 vs 字符设备**：`ls -l` 第一个字符是 `b` 的是块设备（硬盘、分区，可随机读写），`c` 的是字符设备（串口、终端，按字节流读写）。

#### /opt vs /usr/local —— 软件装哪？

两者都是"非系统软件"的安装位置，FHS 给了约定：

|                   | `/usr/local`                                        | `/opt`                                                       |
| ----------------- | --------------------------------------------------- | ------------------------------------------------------------ |
| **FHS 定义**      | 管理员手动安装的、为整个系统使用的程序              | 第三方附加软件包（add-on），整个应用自成一个目录             |
| **典型例子**      | 自己编译安装的 git、python、node.js                 | Oracle 数据库、WebLogic、腾讯会议、JetBrains Toolbox、Linux 版 Chrome |
| **目录结构**      | 文件分散在 bin/lib/share 里（和系统软件一样的布局） | 整个程序装在一个目录下：`/opt/软件名/`，里面自带 bin/lib/... |
| **装完要做的**    | `/usr/local/bin` 已经在 PATH 里，直接能用           | 要手动把 `/opt/xxx/bin` 加进 PATH，或在 `/usr/local/bin` 建软链接 |
| **卸载方式**      | 要逐个子目录清理，容易留残渣                        | 直接删 `/opt/软件名/` 整个目录即可（类似 Windows 的"绿色软件"） |
| **Java 项目习惯** | JDK 放 `/usr/local/java/` 或 `/opt/java/` 都行      | Tomcat 常放 `/opt/tomcat/`，Jenkins 放 `/opt/tomcat/webapps/` |

**FHS 为 `/opt` 里的软件规定了三个配套目录（静态本体 / 配置 / 可变数据三分离）：**

| 路径               | 放什么                                                 | 类比 Windows                 |
| ------------------ | ------------------------------------------------------ | ---------------------------- |
| `/opt/软件名/`     | 软件本体：程序、库等**静态**文件（升级时被覆盖的部分） | `C:\Program Files\软件名\`   |
| `/etc/opt/软件名/` | 该软件的**配置文件**（配置统一归 /etc 管）             | `C:\ProgramData\软件名\配置` |
| `/var/opt/软件名/` | 该软件运行时产生的**可变数据**：日志、数据库文件、缓存 | 软件的数据目录               |

例如装在 `/opt/oracle` 的数据库，配置应写 `/etc/opt/oracle/`，日志和数据写 `/var/opt/oracle/`。这样以后升级软件、直接覆盖 `/opt/oracle` 时，配置和业务数据都不受影响。

> 💡 **注意路径层级**：是 `/etc/opt`（etc 下面的 opt）和 `/var/opt`（var 下面的 opt），**不是** `/opt/etc`。它们默认可能根本不存在，或存在但是空的——这两个目录是"按需创建"的预留位置：没装过 Oracle 这类严格守规范的软件，系统就不会建（`ls /etc/opt` 可能直接提示 No such file or directory），属正常现象，不是系统有问题。
>
> `/var/opt` 即使存在也大多是空的——很多软件并不严格遵守这个约定（比如 Tomcat 常直接把日志写在自己的 `/opt/tomcat/logs`），但这就是它存在的意义：**让 `/opt` 保持静态、把会增长的数据放到 `/var`**。验证本机有没有：`ls -ld /etc/opt /var/opt 2>&1`。

> 🚫 **常见误解：自己开发的项目不是传到 `/etc/opt`！** `/opt`、`/etc/opt`、`/var/opt` 这一套是给**厂商打包的成品软件**（Oracle、Chrome、Tomcat 安装包）用的。你自己写的 Django/Node/Java/Vue 项目，代码放在自建目录（如 `/www/myproject/`、`/opt/myapp/`、`/data/www/myapp/`，本书 10.5 实战用 `/www/myproject/`），配置放 `/etc/myapp/` 或 `/etc/nginx/conf.d/`，日志放 `/var/log/myapp/`——是"项目拆四地"，和 /etc/opt 无关。详见第 10.5 节目录规划。

```bash
# /opt 典型使用
ls /opt/                          # 看装了哪些第三方软件
ls /opt/google/chrome/            # Linux 版 Chrome 的本体
/opt/google/chrome/google-chrome  # 直接用绝对路径启动
# 不想打长路径：在已有的 PATH 目录里建软链接
sudo ln -s /opt/google/chrome/google-chrome /usr/local/bin/chrome
```

#### /mnt 与 /media —— 两个挂载点的区别

两个目录本质上都是"空目录 + 挂载入口"，区别只在使用约定：

|              | `/mnt`                                        | `/media`                           |
| ------------ | --------------------------------------------- | ---------------------------------- |
| **用途**     | 管理员**手动、临时**挂载文件系统              | **可移动介质**的挂载点             |
| **典型场景** | 临时挂第二块硬盘、NFS 共享、VMware 共享文件夹 | U 盘、光盘、移动硬盘               |
| **谁来挂**   | 自己敲 `mount` 命令                           | GNOME/KDE 桌面环境插上设备后自动挂 |
| **路径形态** | 直接挂 `/mnt` 或自建 `/mnt/data` 等子目录     | 通常自动挂成 `/media/用户名/卷名/` |

```bash
# /mnt 的典型用法（服务器上基本只用这个）
sudo mount /dev/sdb1 /mnt/usb                        # 临时挂第二块硬盘的第 1 个分区
sudo mount -t nfs 192.168.1.100:/share /mnt/nfs      # 临时挂 NFS 网络共享
ls /mnt/hgfs/                                        # VMware 共享文件夹固定挂这里（见 8.1.2 节）
ls /mnt/c/                                           # WSL 中 Windows 的 C 盘自动挂这里、D 盘在 /mnt/d
sudo umount /mnt/usb                                 # 用完卸载

# /media 一般不用手动操作：桌面版插 U 盘后自动出现
ls /media/$USER/                                     # 查看当前用户被自动挂载的可移动设备
```

> 经验：无桌面的服务器上几乎只会用到 `/mnt`；个人桌面版上 U 盘、光盘走 `/media`。挂反了也能用——它们都只是普通空目录，区别纯粹是 FHS 的约定。

#### /home —— 用户家目录

- 每个用户登录后默认进入自己的家目录：`/home/用户名/`

- `~` 缩写代表"当前用户家目录"，`~alice` 代表 alice 的家目录

- 家目录里有很多**隐藏文件**（以 `.` 开头），存个人配置：

  ```bash
  ~/.bashrc          # bash 每次启动时加载
  ~/.bash_profile    # 登录 shell 时加载（只加载一次）
  ~/.bash_history    # 命令历史
  ~/.ssh/            # SSH 密钥、known_hosts
  ~/.vimrc           # Vim 个人配置
  ~/.gitconfig       # Git 个人配置
  ~/.m2/             # Maven 本地仓库
  ~/.npm/            # npm 缓存
  ~/.pip/            # pip 配置
  ```

#### /root —— root 的家目录

- **注意**：root 的家目录是 `/root`，不是 `/home/root`（FHS 规定）
- 普通用户用 `/home/xxx/`，root 单独占 `/root/`
- 里面也有 `.bashrc`、`.ssh/` 等隐藏配置

#### /tmp —— 临时文件目录

- 所有人可写（权限 `drwxrwxrwt`，t = sticky bit，只有创建者能删除自己的文件）
- 系统默认**30 天自动清理**（CentOS 7+ 用 systemd-tmpfiles 管理）
- 开发常用场景：编译临时文件、下载中间文件、解压临时目录
- **⚠️ 不要把重要文件存在这里！** 服务器重启可能清空

#### /run —— 运行时数据（CentOS 7 新增）

- **重启自动清空**的内存文件系统（tmpfs，在内存里，不占磁盘）
- 存 PID 文件、Socket 文件：`/run/nginx.pid`、`/run/mysqld/mysqld.pid`
- 取代了老的 `/var/run/`（现在 `/var/run` 是 `/run` 的软链接）

#### /boot —— 启动引导

```bash
ls /boot/                             # 列出所有启动文件
ls /boot/vmlinuz-*                    # 内核镜像
ls /boot/initramfs-*                  # 初始 RAM 文件系统（内核启动时的临时文件）
cat /boot/grub2/grub.cfg             # GRUB2 引导配置（别手动改，用 grub2-mkconfig）
ls /boot/System.map-*                # 内核符号表
```

**排障经验**：内核启动不了，99% 是 `/boot/` 里的东西坏了，从这找。

#### /lost+found

- FHS 规定每个分区根目录都有这个目录
- `e2fsck` 修复文件系统时，丢失的文件块被"抢救"出来放这里
- 日常基本不用，知道它干嘛的就行

### 9.5 路径概念（绝对 vs 相对）（必会）

> 🏷️ ⭐ 开发必会 —— 写脚本、配 Dockerfile、写 systemd unit 时绝对路径/相对路径是高频考点

| 概念         | 格式             | 举例                                             | 说明                                           |
| ------------ | ---------------- | ------------------------------------------------ | ---------------------------------------------- |
| **绝对路径** | 从 `/` 开始写    | `/etc/nginx/nginx.conf`、`/usr/bin/python3`      | **永远唯一、永远正确**，写脚本时推荐用绝对路径 |
| **相对路径** | 从当前位置开始写 | `../var/log/`、`./bin/run.sh`、`conf/nginx.conf` | 依赖当前 `pwd`，换个目录就失效                 |
| `.`          | 当前目录         | `cp file .` 复制到当前目录                       | 等价于 `pwd` 的结果                            |
| `..`         | 上一级目录       | `cd ../..` 跳两级                                | 永远能正确解析，不受当前目录影响               |
| `~`          | 当前用户家目录   | `cd ~/project`                                   | 等价于 `echo $HOME`                            |
| `~alice`     | alice 的家目录   | `ls ~alice/.ssh/`                                | 换个用户                                       |
| `-`          | 上一次所在目录   | `cd -` 在两个目录间来回跳                        | 很方便，适合对比两个目录                       |

**路径坑（新手容易踩）**：

```bash
# 坑1：脚本里用相对路径，cron 定时执行时 cwd 是 /，脚本就找不到文件了
# 解决：脚本开头加 cd /path/to/project，或者全用绝对路径

# 坑2：执行当前目录下的脚本必须写 ./
sh script.sh        # 可以（用 sh 显式调用）
script.sh           # 不行！Shell 会去 PATH 里找
./script.sh         # 可以（显式指定当前目录）

# 坑3：PATH 里没有当前目录（这是安全设计，不是 bug）
echo $PATH          # 不会有 . 或 ./
```

### 9.6 Linux vs Windows 目录对比（了解）

> 🏷️ 📖 概念了解 —— 新手从 Windows 转过来时对照看

| 对比           | Linux                                | Windows                                        |
| -------------- | ------------------------------------ | ---------------------------------------------- |
| **根目录**     | 单个 `/`                             | 多个盘符：`C:\`、`D:\`、`E:\`                  |
| **路径分隔符** | `/`（正斜杠）                        | `\`（反斜杠，命令行里有时 `/` 也认）           |
| **用户目录**   | `/home/用户名/`                      | `C:\Users\用户名\`                             |
| **系统配置**   | `/etc/`                              | `C:\Windows\System32\` + 注册表                |
| **系统程序**   | `/usr/bin/`、`/usr/local/bin/`       | `C:\Program Files\`、`C:\Program Files (x86)\` |
| **日志**       | `/var/log/`                          | `C:\Windows\Logs\` + 事件查看器                |
| **临时文件**   | `/tmp/`                              | `C:\Windows\Temp\`、`%TEMP%`                   |
| **硬盘分区**   | `/dev/sda1` → 挂载到 `/data/`        | 直接显示为 `D:\` 盘符                          |
| **大小写敏感** | ✅ `/home/alice` ≠ `/home/Alice`      | ❌ 不敏感（NTFS）                               |
| **文件扩展名** | 可选，`file` 和 `file.sh` 没本质区别 | 关键，`.exe`、`.dll`、`.bat`                   |
| **隐藏文件**   | 以 `.` 开头（`.bashrc`）             | 文件属性勾选"隐藏"                             |
| **可执行文件** | 看权限位（`x`），不是看扩展名        | 看扩展名（`.exe`、`.com`、`.bat`）             |

### 9.7 Linux 文件类型（必会）

> 🏷️ ⭐ 开发必会 —— 理解 `ls -l` 第一列的字符含义

**① 先说为什么有"文件类型"这回事**

第一章讲过 Linux 的核心思想是**"一切皆文件"**：普通文本是文件，**目录也是文件，连硬盘、终端、插座（socket）都是文件**。它们既然都叫文件，靠什么区分？——靠 `ls -l` 第一列的**第一个字符**标记：

```
$ ls -l /etc/passwd
-rw-r--r-- 1 root root 2342 Sep 13 10:00 /etc/passwd
└─┬────────┘
  └─ 第 1 个字符 "-" = 文件类型（本节内容）
     后面 9 个字符 rw-r--r-- = 权限位（第二章细讲）
```

**② 天天见的 3 种（占你遇到的 99%）**

| 字符 | 类型               | 例子                             | 一句话说明                                |
| ---- | ------------------ | -------------------------------- | ----------------------------------------- |
| `-`  | 普通文件           | `a.txt`、`run.sh`、`/usr/bin/ls` | 文本、脚本、二进制程序、压缩包……统统是它  |
| `d`  | 目录               | `/etc`、`project/`               | 目录本质是"存着子文件名单的特殊文件"      |
| `l`  | 软链接（符号链接） | `/tmp/p -> /etc/passwd`          | 相当于 Windows 快捷方式，箭头后是真实目标 |

**③ 认识即可的 4 种（在 /dev、/run 下会撞见）**

| 字符 | 类型               | 例子                                                | 什么时候会注意到它                                        |
| ---- | ------------------ | --------------------------------------------------- | --------------------------------------------------------- |
| `b`  | 块设备             | `/dev/sda`                                          | 装系统、挂磁盘时——代表硬盘、U 盘，按数据块读写            |
| `c`  | 字符设备           | `/dev/null`、`/dev/tty`                             | 命令结尾常写的 `2>/dev/null`，这个 null 就是字符设备      |
| `s`  | socket（插座文件） | `/var/lib/mysql/mysql.sock`、`/var/run/docker.sock` | MySQL/Docker **本地进程间通信的"插座"**，服务启动后才生成 |
| `p`  | 管道文件           | `ls | grep` 中间的 `|`                              | 管道符背后的实体，开发几乎只在概念上碰到                  |

> （资料里若出现第 8 种 `D`（Door），那是 Solaris 系统专属，Linux 上根本看不到，忽略即可。）

**④ 拿不准类型时用 file（比看后缀靠谱）**

Linux 的文件后缀只是给人看的约定，**系统不靠后缀认文件**。判断真实内容用 `file`：

```bash
file /etc/passwd          # ASCII text（纯文本）
file /usr/bin/ls          # ELF 64-bit LSB executable（64 位可执行程序）
file -i c.txt             # 顺带看编码：charset=utf-8 还是 us-ascii
# `-i` = `--mime`，输出 **MIME 类型**（互联网标准文件类型标记）

> 
> 不加 `-i`：输出人类看的自然语言描述
> 加 `-i`：输出机器方便读取的 MIME 字符串，附带编码 charset
# 普通file（不带-i）
file c.txt
# 输出：a.txt: ASCII text

# file -i a.txt 带-i
file -i c.txt
# 输出：a.txt: text/plain; charset=us-ascii
纯英文：us-ascii = UTF8，**不用转**，直接写中文就自动变成 UTF8
```

**⑤ 自己动手看一遍（例子在任何 CentOS 上都能跑）**

```bash
# 一条命令同时看清 普通文件 / 目录 / 字符设备 三种开头字符
ls -l /etc/passwd /etc /dev/null
# -rw-r--r-- ... /etc/passwd      ← "-" 普通文件
# drwxr-xr-x ... /etc             ← "d" 目录
# crw-rw-rw- ... /dev/null        ← "c" 字符设备

# 造一个软链接，观察 l 类型和 -> 箭头
ln -s /etc/passwd /tmp/p          # ln -s 源文件 链接名（-s = symbolic，软链接）
验证有没有创建成功
ls -l /tmp/p                      # lrwxrwxrwx ... /tmp/p -> /etc/passwd（l 开头）
cat /tmp/p                        # 顺着链接照样读到原文件内容
rm /tmp/p                         # 删的是链接，不是原文件；反过来原文件被删，链接就成"死链"（ls 里红底闪烁）
```

### 9.8 开发者视角：每天会碰哪些目录？（必会）

> 🏷️ ⭐ 开发必会 —— 一张表帮你聚焦高频目录，其余知道在哪就行

| 目录                        | 你会做什么                                          | 频率       |
| --------------------------- | --------------------------------------------------- | ---------- |
| **你的家目录** `/home/xxx/` | 写代码、存项目、个人配置                            | 每天       |

### 9.9 目录操作基础命令（必会）

> 🏷️ ⭐ 开发必会 —— 最基础的几个命令，敲代码一样熟

```bash
# 查看当前目录（两个参数的区别：-P 显示物理路径、-L 显示逻辑路径）
pwd                     # 等价于 pwd -L，显示你实际"看到"的路径
pwd -P                  # 解析软链接后的真实路径

举例：
# 1. 创建真实目录
mkdir /tmp/realdir

# 2. 创建软链接 linkdir，指向 /tmp/realdir
ln -s /tmp/realdir /tmp/linkdir

`ln` = link，**创建链接**

- 不加 `-s`：**硬链接（hard link）**
- `-s`：`--symbolic` 的缩写，**symbolic link，符号链接，俗称软链接**

软链接 ≈ Windows 的**快捷方式**，不是文件本身，只是一个指向目标的路标。
表面看是别名，但**和单纯别名有本质区别**

# 3. cd 进入【软链接目录】
cd /tmp/linkdir


# 切换目录
cd /etc                 # 绝对路径，永远能用
cd ../home              # 相对路径，依赖当前位置
cd ~                    # 回到家目录（等价于 cd $HOME）
cd -                    # 上一次的目录（在两个目录间反复横跳神器）
cd                      # 回到家目录（没参数时默认回家）
cd /                    # 回根目录

# 列出目录内容（你最常用的 ls 变体）
ls -la                  # 列出全部（含隐藏文件）+ 详细权限
ls -lhS                 # 按大小排序 + 人类可读（G/M/K）
`-l`long，长格式输出：权限、硬链接数、所有者、组、大小、修改时间、文件名
`-h`human-readable，人类可读单位。文件大小自动转为 K/M/G，而不是原始字节数
`-S`Sort by size，**按文件大小从大到小排序**（大写 S！）
ls -lhrt                # 按修改时间排序（新的在底部）
- `-l`：长格式，显示权限、属主、大小、时间等详细信息
- `-h`：human-readable，大小自动转为 K/M/G
- `-r`：reverse，**反转排序**
- `-t`：time，按**修改时间**排序，默认新文件在前

ls -ld /etc            # 只看 /etc 目录本身的信息，不是内容     `-l`：长格式 `-d`：只显示目录本身，不展开目录内文件
ls -d */                # 只列出当前目录下的子目录
tree /etc/nginx/        # 树形展示（需 yum install -y tree）

# 创建目录
mkdir project           # 单个
mkdir -p aaa/bbb        # 新建aaa和aaa下面的bbb  -p代表创建没有父目录的文件夹 比如原来aaa不存在 p表示递归
mkdir -p project/{src,lib,conf,logs}   # 一次性创建多级 + 多子目录（bash brace expansion）
# 上面等价于：mkdir -p project/src project/lib project/conf project/logs

# 删除目录
rmdir empty_dir         # 只能删空目录（非空会报错）
rm -rf project/         # 强制删除（⚠️ 危险！删之前想清楚）
rm -rf *.log            # 删除当前目录所有 .log 文件
```

**rm -rf 安全建议（开发必看）**：

````bash
# 1. 先用 ls 确认要删的东西
ls *.log
# 2. 可以先 mv 到 /tmp/ 观察几天再删（比 rm 靠谱）
mv *.log /tmp/trash_$(date +%Y%m%d)/
# 3. 写脚本时 rm 后面永远跟绝对路径
rm -rf /home/old_project/   # ✅ 安全
rm -rf old_project/          # ❌ 如果 cwd 不对，可能删错东西
# 4. 生产环境 alias rm='rm -i' 交互式确认  
> 给 `rm` 命令起个别名：**以后你敲 `rm`，shell 自动替换成 `rm -i` 执行**

`rm -i`：删除文件前，**弹出确认提示，输入 y 才删，n 取消**

# 设置别名
alias rm='rm -i'

# 测试1：不带sudo，不带-f，才会提示
rm test.txt

# 测试2：不带sudo，但带-f，无提示！
rm -f test.txt

# 测试3：sudo rm xxx，无论如何，不使用你的alias，无提示
sudo rm test.txt
```
要切换成root用户可以不用sudo 会有删除提示 提示后回复y就可以删除了


`-r` `-f` `-rf` 讲解

- `-r` = `--recursive`  **recursive：递归**
作用：**递归删除目录，以及目录里面所有文件、子目录**

> 
> rm 默认只能删文件，不加 `-r` 不能直接删除文件夹
- `-f` = `--force`**force：强制**
作用：
  1. 强制删除，**不弹出任何确认提示**（直接绕过 `-i` 的交互询问）
  2. 如果文件不存在，**不报错、不提示**，安静执行

## ✅ `-rf` = `-r -f` 合并简写

Linux 命令的单字母短参数可以合并写：`-rf` 等价 `-r -f`，顺序无所谓，`-fr` 效果一模一样。

## 对比区别

1. **`rm -f 文件`**
只作用于**文件**，不能删目录。强制删除文件，无确认，文件不存在不报错。

```

```

2. **`rm -rf 目录`**
同时开启**递归 + 强制**，用来删除**整个目录**（目录 + 里面所有内容），无任何确认。

```

> ⚠️ **重要：课件里出现的 `192.168.100.100` 都是示例 IP，不是固定值！**
>
> 实际连接时要用**你自己虚拟机里 CentOS 的真实 IP**。新手机器必看：
>
> **1. 怎么查 CentOS 的实际 IP？**
>
> ```bash
> ip addr          # 推荐命令（CentOS 7+ 自带）
> # 或
> ifconfig         # 老命令，需先 yum install -y net-tools
> ```
>
> 重点看 `ens33`（NAT 模式默认网卡名）那一段，`inet` 后面的就是 IP：

> ```bash

#### 10.1.1 SSH 工作原理（重要）

SSH（Secure Shell）使用 **加密通道** 替代明文传输的 telnet/rsh，核心采用 **非对称加密 + 对称加密** 混合方案：

```
首次连接流程:
1. 客户端发起连接 → 服务端返回公钥指纹
2. 客户端确认后，公钥保存到 ~/.ssh/known_hosts
3. 双方协商出对称密钥（用于后续传输）
4. 后续通信用对称密钥加密（性能高）

后续连接:
1. 客户端检查 known_hosts 中的公钥是否匹配
2. 若不匹配（中间人攻击或服务器重装）会拒绝连接
3. 匹配则直接协商对称密钥进行加密通信
```

- **对称加密**：单密钥，加解密速度快，适合大数据量（AES、ChaCha20）
- **非对称加密**：公钥/私钥对，慢但安全（RSA、ECDSA、Ed25519）
- SSH 协议默认端口 **22/TCP**

#### 10.1.2 安装配置 SSH 服务端

> 💡 **开箱能连就跳过本节**：CentOS 7 选"带 GUI 的服务器"或"基础设施服务器"安装时，openssh-server **已预装并开机自启**，默认配置允许 root 密码登录，直接用 VS Code 连就行。
> 本节写给 3 种特殊情况：① 选了"最小安装"没装 openssh；② 用云服务器要做安全加固；③ sshd 起不来要排查。

```bash
# CentOS 7 默认已安装 openssh-server
# 查看 SSH 服务状态
systemctl status sshd

# 启动 SSH 服务
systemctl start sshd

# 设置开机自启
systemctl enable sshd

# 修改配置（可选）
vi /etc/ssh/sshd_config
# Port 22                       # 端口号
# PermitRootLogin yes           # 允许 root 登录（生产建议 no）
# PasswordAuthentication yes    # 密码登录（生产建议 no，用密钥）
# PubkeyAuthentication yes       # 公钥认证（推荐 yes）
# MaxAuthTries 3                # 最大认证尝试次数
# ClientAliveInterval 300       # 空闲 300 秒发送心跳
# ClientAliveCountMax 2         # 2 次未响应则断开

# 修改配置后重启
systemctl restart sshd
```

> **新手常见卡点：VS Code 让我填 config 配置文件，里面有 `IdentityFile`，我不知道填什么**

>
> **解决方法：把 config 文件改成下面这样（删掉 IdentityFile 那行）**

> ```
> Host 192.168.233.131
> HostName 192.168.233.131
> User root
> Port 22
> ```
>
> 保存后回 VS Code：F1 → `Remote-SSH: Connect to Host` → 选 `192.168.233.131` → 选 Linux → 输 CentOS 的 root 密码 → 连上。
>
> **IdentityFile 是什么？什么时候才需要？**
>
> - 是 SSH 密钥对的私钥路径，用于**免密登录**（不用每次输密码）
> - 本地生成一对密钥：私钥（自己留着）+ 公钥（放服务器）
> - 连接时自动用私钥证明身份
> - **学习阶段不用配**，每次输密码就行；觉得输密码烦了再配，见 10.1.4 节

**SSH 免密登录配置：**

```bash
# 1. 在客户端生成密钥对（推荐 ed25519，更安全更快）
ssh-keygen -t ed25519 -C "your_email@example.com"
# 或使用 RSA（兼容性最好）
ssh-keygen -t rsa -b 4096
# 一路回车，默认路径 ~/.ssh/

# 2. 将公钥复制到服务器
ssh-copy-id root@192.168.100.100
# 或手动追加
cat ~/.ssh/id_ed25519.pub | ssh root@192.168.100.100 'mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys'

# 3. 测试免密登录
ssh root@192.168.100.100
```

#### 10.1.4 免密登录原理（重要）

```
密钥认证流程:
1. 客户端向服务端发起连接请求
2. 服务端用 ~/.ssh/authorized_keys 中保存的客户端公钥加密一个随机数
3. 客户端用本地私钥（~/.ssh/id_ed25519）解密并返回
4. 服务端校验通过，认证成功

注意:
- 私钥（id_ed25519）必须保密，权限 600
- 公钥（id_ed25519.pub）追加到服务端的 authorized_keys（权限 600）
- ~/.ssh 目录权限必须 700
- 权限不对会导致免密失败！
```

#### 10.1.5 SSH 端口转发（高级用法）

```bash
# 本地端口转发：将远程的 3306 映射到本机 13306
ssh -L 13306:127.0.0.1:3306 root@192.168.100.100
# 之后本地访问 localhost:13306 等于访问远程 MySQL

# 远程端口转发：把本地 8080 暴露到远程 9999
ssh -R 9999:127.0.0.1:8080 root@192.168.100.100

# 动态端口转发（SOCKS5 代理）
ssh -D 1080 root@192.168.100.100

# 后台保持 + 压缩
ssh -fNL 13306:127.0.0.1:3306 -C root@192.168.100.100
```

#### 10.1.7 su 与 sudo —— 切换身份与提权

> 🏷️ ⭐ 开发必会 —— 登录后常用，必须掌握
> 远程登录后默认是普通用户身份，要做系统级操作就要切 root 或用 sudo 提权

**su —— 切换用户身份（switch user）**

````bash
# 普通用户切换到 root（最常用）
su - root          # 等价于 su -，注意有那个 "-"

如果：[lwc@[localhost](https://localhost) /]$ su - root
密码：
su: 鉴定故障

解决:
## 最常见 3 个原因（CentOS/RHEL）

1. **root 根本没有设置密码**（新装系统常见，shadow 里 root 是`!!`，代表禁用）
2. root 密码输错（大小写、小键盘没开，输入密码屏幕不显示星号，属于正常）
3. PAM 限制：只允许`wheel`组的用户才能`su`切 root，你的`lwc`不在 wheel 组

## ✅ 方案 1（推荐，不用 su，直接 sudo 进 root）

你现在`lwc`可以用 sudo，直接执行：

```
sudo -i
```

输入 **lwc 自己的密码**，直接进入 root 环境，不需要 root 密码。
等价：`sudo su -`

## ✅ 方案 2：给 root 设置密码，之后就能 su - root

```
sudo passwd root
```

执行后：

1. 输入你 lwc 的密码
2. 然后设置新 root 密码（输入 2 次）
设置完成，再执行：

```
su - root
```
## ✅ 方案 3：如果提示不在 wheel 组（PAM 限制 su）

把 lwc 加入 wheel 管理员组：

```
sudo usermod -aG wheel lwc
```
加完组，**需要重新登录终端**，组才生效。

### 查看当前用户属于哪些组

```
id lwc
```
看输出里面有没有 `wheel`


- `usermod`：修改用户属性
- `-a` append 追加，**不要把原有组覆盖掉**（不加 - a，只用 - G 会直接覆盖附属组！考试坑点）
- `-G` 附属组（附加组，不是主组）
- `wheel`：CentOS/RHEL 里的管理员附属组，默认只有 wheel 组用户可以 `su - root`
- `lwc`：要操作的用户名

# 提示输 root 密码，输对后变成 root，提示符从 $ 变成 #

# 普通用户切换到其他普通用户
su - zhangsan      # 切到 zhangsan，要输 zhangsan 的密码

# root 切换到普通用户（不需要密码）
su - zhangsan      # root 直接切过去，不用密码

# 退出 su 切换的身份
exit               # 或按 Ctrl+D
````

**`su` 和 `su -` 的区别（重要）**

| 命令                | 加载环境变量             | 当前目录     | 工作目录        |
| ------------------- | ------------------------ | ------------ | --------------- |
| `su root`（不带 -） | 不加载，沿用当前用户环境 | 保持在原目录 | 用原用户的 PATH |
| `su - root`（带 -） | 加载 root 的完整环境     | 切到 /root   | 用 root 的 PATH |

```bash
# 示例：不带 - 的坑
[lisi@centos ~]$ su root            # 不带 -
Password:
[root@centos lisi]# pwd             # 还在 /home/lisi
[root@centos lisi]# echo $PATH      # 还是 lisi 的 PATH，可能找不到某些命令

[lisi@centos ~]$ su - root          # 带 -
Password:
[root@centos ~]# pwd                # 切到了 /root
[root@centos ~]# echo $PATH         # 是 root 的 PATH，/sbin /usr/sbin 都在
```

**结论：永远用 `su -`，不要用 `su`**，加 `-` 才是完整的身份切换。

**sudo —— 以管理员权限执行单条命令（更安全，推荐）**

```bash
# 以 root 身份执行一条命令，执行完立刻回到普通用户
sudo systemctl restart nginx        # 重启服务
sudo tail /var/log/messages         # 看日志
sudo yum install -y tree            # 装软件

# 第一次用 sudo 会显示提示，要求输当前用户密码（不是 root 密码！）
# 输一次密码后 5 分钟内再用 sudo 不用再输

# 切到完全的 root shell（等价 su -）
sudo -i                             # 推荐用这个，不用记 root 密码
# 或
sudo su -
```

**sudo 的优势**：

- 不用告诉别人 root 密码
- 每条命令都有审计日志（/var/log/secure）
- 可以精细控制谁能在哪台机器上跑什么命令（/etc/sudoers）
- 5 分钟缓存密码，不用反复输

**su vs sudo 怎么选？**

| 场景                   | 用什么                                                  |
| ---------------------- | ------------------------------------------------------- |
| 只跑一两条 root 命令   | `sudo 命令`                                             |
| 要连续做很多 root 操作 | `sudo -i` 或 `su -`                                     |
| 完全切到 root 干活     | `su - root`（要 root 密码）或 `sudo -i`（只要自己密码） |

**初次使用 sudo 的准备工作**（首次配置才要做）：

```bash
# 用 root 登录后，把普通用户加入 wheel 组（CentOS 默认 wheel 组有 sudo 权限）
usermod -aG wheel lisi              # lisi 就能用 sudo 了

# 或者直接编辑 sudoers（推荐用 visudo，会检查语法）
visudo                              # 打开 /etc/sudoers
# 找到这行去掉前面的 #：
# %wheel  ALL=(ALL)       ALL       # wheel 组所有用户都能 sudo
# 或给单个用户加权限：
# lisi    ALL=(ALL)       ALL
```

> 💡 **CentOS 安装时如果建了普通用户并勾选"将此用户作为管理员"，系统会自动把这个用户加进 wheel 组，开机就能 sudo，不用再配**。如果你装系统时只建了 root，就要手动把普通用户加 wheel。

### 11.1 Vi/Vim 简介（了解）

> 🏷️ ⭐ 开发必会 —— 软件开发日常高频使用，务必掌握

- **Vi**：Unix/Linux 系统**自带**的全屏文本编辑器，1976 年诞生，几乎装在每一台 Linux/Unix 机器上
- **Vim**（Vi IMproved）：Vi 的增强版，加了语法高亮、多级撤销、插件等；CentOS 7 上敲 `vi` 实际打开的就是 vim（做了别名）
- 三种工作模式：**命令模式、编辑模式、末行模式**（见 11.2）

#### 有了 VS Code、IDEA，为什么还必须学 Vim？

一句话：**图形编辑器只能在你自己电脑上用，vim 长在服务器里。** 你的代码最终都要跑到 Linux 服务器上，而服务器绝大多数时候只能用命令行连上去，没有图形界面、装不了 VS Code。下面是工作中的真实场景：

| 场景                                 | 具体要做什么                                                 | 为什么只能用 vim                                             |
| ------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **① 改服务器上的配置文件**（最高频） | Nginx 起不来，登服务器改 `/etc/nginx/nginx.conf`；改应用的 `application.yml` | 服务器只有黑窗口，没有"右键用记事本打开"                     |
| **② 线上紧急改一行代码/配置**        | 凌晨服务挂了，改一个数据库地址、一个开关后重启               | 不可能把代码下载到本地、用 IDEA 改完再传回去，太慢           |
| **③ 写/改 Shell 脚本**               | 定时备份脚本、部署脚本 `deploy.sh` 直接在服务器上编写调试    | 脚本就跑在 Linux 上，就地写最方便                            |
| **④ Docker 容器里排查**              | `docker exec -it 容器 bash` 进去改配置、看日志               | 容器里往往只有 vi（连 vim 都可能没有），更没有图形工具       |
| **⑤ 云上操作**                       | 阿里云/腾讯云网页控制台、跳板机、客户的内网服务器            | 只能 SSH 进去，唯一保证存在的编辑器就是 vi                   |
| **⑥ git 提交/合并冲突**              | `git commit` 默认调用 vi 写提交说明；`git rebase -i` 也在 vi 里操作 | 不熟 vi 连提交信息都不会保存退出（很多新手第一次用 git 就卡在这） |

**学习要求要分清：**

- ❌ 不需要把 vim 用成"写代码主力编辑器"（装一堆插件、和 IDE 比谁快），日常写代码还是 VS Code/PyCharm 舒服
- ✅ 必须做到：**打开文件 → 跳到指定行 → 增删改几行 → 搜索 → 保存退出**，30 秒内完成，不被卡住
- 这就是本章的目标：掌握 11.3 结尾那份"15 个按键最小集合"就达标了

> 💡 类比：IDE 是你家里的全屋工具箱，vim 是口袋里的瑞士军刀。你不会天天用瑞士军刀干活，但出门在外（上服务器）只有它，关键时刻得会用。

### 11.3 命令模式快捷键（必会）

> 🏷️ ⭐ 开发必会 —— 软件开发日常高频使用，务必掌握

先记住两条规律，所有快捷键都能举一反三：

> **规律 1：任何移动命令前都可以加数字，表示重复几次。**
> 如 `5j` = 向下 5 行，`3w` = 向后跳 3 个单词，`10dd` = 删 10 行。
>
> **规律 2：vim 快捷键 = 操作符 + 范围（动词+宾语）。**
> 操作符有 `d`(删)、`y`(复制)、`c`(删并进入编辑)；范围有 `w`(单词)、`$`(到行尾)、`G`(到文件末尾) 等。
> 如 `dw` = 删除一个单词，`d$` = 从光标删到行尾，`yG` = 复制到文件末尾。**操作符按两下 = 作用于整行**：`dd`、`yy`、`cc`。

#### 11.3.1 光标移动

| 按键                  | 作用                                               | 例子/说明                                                    |
| --------------------- | -------------------------------------------------- | ------------------------------------------------------------ |
| `h` `j` `k` `l`(必会) | 左下上右（就是键盘上排在一起的四个键）             | 也可直接用方向键，效果一样                                   |
| `5j` / `10k`(必会)    | 加数字 = 移动 n 次                                 | `5j` 向下 5 行，`3l` 向右 3 个字符                           |
| `w` / `b`             | 跳到下一个 / 上一个**单词开头**                    | `3w` 向后跳 3 个单词                                         |
| `e`                   | 跳到当前/下一个单词的**词尾**                      | 和 `w` 配合记：w 头、e 尾、b 回头                            |
| `0`                   | 跳到**行首**（第 1 列，含空格）                    | 数字零                                                       |
| `^`                   | 跳到行首**第一个非空字符**                         | 缩进的代码行用它更顺手                                       |
| `$`                   | 跳到**行尾**                                       |                                                              |
| `gg`(必会)            | 文件第一行                                         |                                                              |
| `G`(必会)             | 文件最后一行                                       |                                                              |
| `nG` 或 `ngg`         | 跳到第 n 行                                        | `20G` 跳到第 20 行（先 `:set nu` 看行号）                    |
| `H` / `M` / `L`       | 跳到当前屏幕的 顶部/中间/底部                      | High/Middle/Low                                              |
| `f字符`               | 在**本行**向后找字符，光标停到该字符上             | `f;` 跳到本行下一个分号；`;` 重复找，`,` 往回找              |
| `F字符`               | 本行向前找字符                                     |                                                              |
| `%`                   | 跳到配对的括号上                                   | 光标在 `(` 上按 `%` 跳到对应的 `)`，`{}`、`[]` 同理，查代码块超好用 |
| `Ctrl+d` / `Ctrl+u`   | 向下/向上翻**半屏**                                | down/up，看长文件最常用                                      |
| `Ctrl+f` / `Ctrl+b`   | 向下/向上翻**一整屏**                              | forward/backward                                             |
| `zz`                  | 滚动屏幕，让**当前行**移到屏幕正中间               | 写代码写到底部时按一下，不用仰头看                           |
| `zt`                  | 滚动屏幕，让**当前行**移到屏幕最**顶**部（top）    | 想让正在看的行紧贴屏幕最上方，下面多留空间看后续代码         |
| `zb`                  | 滚动屏幕，让**当前行**移到屏幕最**底**部（bottom） | 往上翻看前文时，让当前行贴底                                 |

> 💡 **注意区分**：`H/M/L` 是**光标跳走**（跳到屏幕顶/中/底的某一行，离开当前行）；`zz/zt/zb` 是**屏幕滚动、光标不动**（你还在当前行编辑，只是把它挪到视野的舒服位置）。



#### 11.3.2 删除（删错了用 `u` 撤销，大胆练）

| 按键                | 作用                                             | 例子/说明                                                    |
| ------------------- | ------------------------------------------------ | ------------------------------------------------------------ |
| `x(必会)`           | 删除光标处**一个字符**                           | `3x` 连删 3 个字符                                           |
| `X`(必会)           | 删除光标**前一个**字符                           | 类似键盘 Backspace                                           |
| `dd`(必会)          | 删除**当前行**整行                               | 删除后下面的行自动补上来                                     |
| `ndd`(必会)         | 删除**从当前行开始的 n 行**                      | `3dd` = 当前行 + 下面 2 行，共 3 行（注意不是删到第 3 行）   |
| `dw`                | 删除一个单词（从光标到词尾）                     | 光标停在单词中间也能删到词尾                                 |
| `de`                | 删除到单词末尾（保留后面的空格）                 | 和 `dw` 的区别只在删不删空格                                 |
| `d0` / `d^`         | 从光标删到行首                                   |                                                              |
| `d$` 或 `D`         | 从光标删到**行尾**                               | 大写 `D` 是简写                                              |
| `dG`                | 从当前行**删到文件末尾**                         | 慎用；`dgg` 反向删到开头                                     |
| `ndw` / `dnw`       | 删除 n 个单词                                    | `3dw` 删 3 个单词                                            |
| `d%`                | 从光标**删到配对的括号**（含括号里的内容）       | 光标在 `(` 上按 `d%`，括号和里面的东西一起删；`{}`、`[]` 同理，删代码块超好用 |
| `df字符` / `dF字符` | 从光标删到本行指定字符（**含**该字符）           | `df;` 删到分号为止（连分号一起删）；`F` 反向（向左找）       |
| `dt字符`            | 删到指定字符**前面**（**不含**该字符，t=to）     | `dt)` 删到右括号前、保留右括号                               |
| `:%d`               | 末行命令（**先按冒号**）：清空**整个文件所有行** | 等价 `ggdG`；和上面无冒号的 `d%` 完全是两码事，见下方说明    |

**⭐ 文本对象（text-object，开发中删除/修改最顺手的一招）：**

格式是 `d` + `i`/`a` + 对象：`i` = inner（**不含**外围符号/空格），`a` = around（**连同**符号/空格一起删）。**最大的好处：光标停在单词或括号中间，也能整体删掉，不用先移动到开头。**

| 按键                           | 作用                                                        | 例子                                                  |
| ------------------------------ | ----------------------------------------------------------- | ----------------------------------------------------- |
| `diw`                          | 删除光标所在的**整个单词**（inner word，不含周围空格）      | 光标停在 `nginx` 中间按 `diw`，整个词消失             |
| `daw`                          | 删除单词**连同后面的空格**（a word）                        |                                                       |
| `diw` vs `dw`                  | `diw` 不管光标在词的哪个位置都删整个词；`dw` 只删光标到词尾 | 光标在词中间时优先用 `diw`                            |
| `di"` / `da"`                  | 删除**引号内的内容** / 连引号一起删                         | `"hello world"` 上按 `di"` → `""`；`da"` → 连引号全没 |
| `di'` / `da'`                  | 同上，单引号                                                |                                                       |
| `di(` / `da(`（`)`、`b` 等价） | 删除**小括号内** / 连括号一起删                             | `print(name)` 按 `di(` → `print()`                    |
| `di{` / `da{`（`B` 等价）      | 删除**花括号内** / 连花括号一起删                           | 清空整个函数体/字典内容最快                           |
| `di[` / `da[`                  | 中括号同理                                                  | 清空列表内容                                          |
| `dit` / `dat`                  | 删除 HTML/XML **标签内** / 连标签一起删                     | `<title>abc</title>` 按 `dit` 只删 abc                |

> 🔑 **同一套文本对象也能配 `c`（改）和 `y`（复制）**，这是 vim 最值钱的规律之一：
>
> - `ciw` 改整个单词（删词并进入编辑）、`ci"` 改引号里的内容（**改配置/改字符串的神键**）、`ci{` 改花括号里的内容
> - `yi(` 复制括号内内容、`ya"` 连引号带内容一起复制
> - 记住"**动词 d/c/y + i/a + 范围 w/"'(){}[]t**"这一个公式，三类操作全会了。

> ⚠️ **`d%` 和 `:%d` 千万别混**（你问的 `%d` 就在这）：
>
> - `d%`（普通模式，**不按冒号**）：`d` 是删除操作符，`%` 是"跳到配对括号"的动作 → **删到配对括号**
> - `:%d`（末行模式，**先按 `:` 再按 `%` 再按 `d`**）：冒号后的 `%` 是行范围符号，代表"第 1 行到最后一行"（等价 `1,$`）→ **清空整个文件**）❤️(必会)
> - vim 里**没有**直接敲 `%d`（百分号开头）的命令——先按 `%` 只会让光标跳到配对括号，后面跟 `d` 不构成完整操作。带不带冒号，是两套完全不同的语法。手滑清空全文别慌，`u` 撤销。

> 💡 vim 的"删除"本质是**剪切**：`dd`、`dw`、`diw` 删掉的内容都存在寄存器里，按 `p` 还能粘回来。所以 `dd` + 移动 + `p` 就是"移动一行"。

| 按键          | 作用                                        | 例子/说明                               |
| ------------- | ------------------------------------------- | --------------------------------------- |
| `/word`(必会) | 从当前位置**向下**搜索 word，回车跳到第一个 | `/listen` 后所有匹配会高亮              |
| `?word`       | **向上**搜索                                |                                         |
| `n`           | 跳到**下一个**匹配（顺着搜索方向）          | next                                    |
| `N`           | 跳到**上一个**匹配                          |                                         |

**搜索行为开关（末行命令，Esc 后输入）：**

| 命令                  | 作用                                                         | 反向/取消                          |
| --------------------- | ------------------------------------------------------------ | ---------------------------------- |
| `:set hlsearch`(必会) | 打开搜索**高亮**（所有匹配处变黄）                           | `:set nohlsearch` 彻底关闭高亮功能 |
| `:noh`                | **只清掉这一次**的高亮（功能还开着，下次搜索照常亮）         | 下次 `/word` 自动恢复高亮          |
| `:set incsearch`      | 输入关键字时**边输边跳**（实时预览匹配）                     | `:set noincsearch`                 |
| `:set ignorecase`     | 搜索**忽略大小写**（`/abc` 能匹配 ABC）                      | `:set noignorecase`                |
| `:set smartcase`      | 智能大小写：关键字全小写时忽略大小写；**一旦含大写字母就强制区分** | 常和 ignorecase 一起开             |
| `:set wrapscan`       | 搜到文件末尾后**绕回开头继续找**                             | `:set nowrapscan` 搜到尾就停       |

> 📌 **`:noh` 和 `:set nohlsearch` 的区别**（新手常混）：
>
> - `:noh` = 这次搜完黄得晃眼，**临时擦干净屏幕**，搜索高亮功能本身还开着
> - `:set nohlsearch` = **把高亮功能关掉**，以后搜索都不亮了，想恢复要 `:set hlsearch`
> - 日常用 `:noh` 即可；想让每次打开 vim 都自动有高亮，把 `set hlsearch` 写进 `~/.vimrc`（见 11.6.4）

**两个单次搜索小技巧（不用改任何设置）：**

```
/word\c     这一次搜索忽略大小写（\C 强制区分大小写）
            例：/Port\c  能匹配 port、Port、PORT
/word\C     这一次强制区分大小写
```

> 💡 上面这些 `:set xxx` 都是**临时生效**（退出 vim 即失效）；觉得好用想永久保留，去掉冒号写进 `~/.vimrc`：`set hlsearch`、`set ignorecase`、`set smartcase`。

> 🔑 **新手先掌握这 15 个就够日常 90% 的操作**：`i` `Esc` `h j k l` `w b` `0 $` `gg G` `nG` `dd` `ndd` `yy nyy` `p` `u` `Ctrl+r` `/word` `n` `:wq`。其余的等熟练了再回来查。

### 11.6 Vim 配置文件（必会）

> 🏷️ ⭐ 开发必会 —— 让 vim 每次打开都显示行号、语法高亮，一劳永逸

#### 11.6.1 先分清：临时设置 vs 永久设置（这是本节最关键的一点）

vim 的设置（比如行号、缩进）有两种改法，**命令长得像，但输入的地方完全不同**：

|          | 临时设置                                | 永久设置                         |
| -------- | --------------------------------------- | -------------------------------- |
| 在哪输   | **vim 编辑器里面**（打开文件的状态下）  | 编辑 **`~/.vimrc` 配置文件**     |
| 长什么样 | `:set nu`（**前面带冒号**）             | `set number`（**前面不带冒号**） |
| 怎么操作 | 按 `Esc` 后输入，回车执行               | 像普通文件一样用 vim 编辑保存    |
| 管多久   | 只对当前这一次打开有效，退出 vim 就没了 | 每次打开 vim 都自动生效          |
| 典型用途 | 临时想看下行号、临时排查问题            | 行号、高亮、缩进等每天都要的设置 |

> 记住：**冒号 `:` 开头的命令只能在 vim 里面敲（末行模式）；写进 `~/.vimrc` 的配置一律不带冒号。** 下面分开讲。

#### 11.6.2 临时设置：在 vim 里面直接敲

适用场景：你正在编辑某个文件，想**临时**显示行号、或临时关掉缩进，退出后不保留。

**操作步骤（4 个动作）：**

```
① 按 Esc          → 确保自己在「普通模式」（按一下不放心就多按几下，会嘀一声）
② 输入 :set nu    → 注意开头的冒号！输入冒号后光标自动跳到屏幕最底行
③ 按回车 Enter    → 命令执行，行号立刻出现
④ 继续按 i 编辑，或 :q 退出
```

**常用临时开关对照表：**

| 想干什么               | 输入（Esc 后）                                  | 反向操作                                     |
| ---------------------- | ----------------------------------------------- | -------------------------------------------- |
| 显示行号               | `:set nu`（必会）                               | `:set nonu`（去掉行号，nu 是 number 的缩写） |
| 语法高亮               | `:syntax on`                                    | `:syntax off`                                |
| 粘贴模式（防缩进错乱） | `:set paste`                                    | `:set nopaste`                               |
| 搜索结果高亮           | `:set hlsearch`                                 | `:noh`（只取消这次高亮）                     |
| 查看当前某项设置是什么 | `:set nu?`（加问号，会回显 number 或 nonumber） | —                                            |

> 小技巧：`nu`、`nonu` 都是缩写，完整写法是 `number`/`nonumber`，vim 里效果一样。

#### 11.6.3 永久设置：手把手创建 ~/.vimrc

适用场景：希望**每次打开 vim 都自动有行号、高亮、缩进**，配置一次终身受用。

`~/.vimrc` 是 vim 启动时自动读取的个人配置文件，**默认不存在，第一次需要自己创建**（`~` 代表当前用户家目录，root 用户就是 `/root/.vimrc`，普通用户 lisi 就是 `/home/lisi/.vimrc`）。

**完整步骤（从零开始，照做一遍）：**

```bash
# 第 1 步：在终端（黑窗口命令行，不是 vim 里面）执行
vim ~/.vimrc
# 文件不存在也没关系，vim 打开空白页面，保存时会自动创建这个文件
```

进入 vim 后：

```
第 2 步：按 i                    → 左下角出现 -- INSERT --，进入插入模式
第 3 步：把下面 11.6.4 的配置内容复制/敲进去
第 4 步：按 Esc                  → 退出插入模式
第 5 步：输入 :wq 再按回车        → w=保存 q=退出（:q! 是不保存退出）
```

回到终端后验证：

```bash
cat ~/.vimrc          # 能看到你写进去的配置，说明保存成功了
vim /etc/passwd       # 随便打开个文件，行号和语法高亮应该自动出现了
```

> ⚠️ **三个新手必踩的坑：**
>
> 1. 配置文件里每行写 `set number`，**前面不要加冒号**！带冒号的 `:set nu` 是在 vim 里面临时敲的，两种写法不能混用
> 2. 注释用**英文半角双引号 `"`**（如 `" 显示行号`），不要用中文引号 `“ ”`，否则启动 vim 会报错
> 3. 配置改完后，**只对"新打开的 vim"生效**；已经开着的 vim 不会自动加载，要在里面执行 `:source ~/.vimrc` 或退出重开

#### 11.6.4 推荐配置（直接抄这份，够用很多年）

**方法一：终端整段粘贴（最省事，推荐新手用）**

不用打开 vim、不用按 i、不用删任何注释——**登录到服务器终端后，把下面整段（从 cat 到 EOF）一次性复制粘贴，再按一次回车**，配置就自动写进 `~/.vimrc` 了：

```bash
cat > ~/.vimrc <<'EOF'
set number
syntax on
set ruler
set showmatch
set autoindent
set smartindent
set tabstop=4
set shiftwidth=4
set expandtab
set hlsearch
set incsearch
set ignorecase
set smartcase
set encoding=utf-8
set fileencodings=utf-8,gbk
set pastetoggle=<F2>
EOF
```

说明：这叫 heredoc，作用是把 `EOF` 之间的内容原样写入文件；单引号 `'EOF'` 保证内容不被转义，照抄即可。执行完没有任何报错就是成功，用下面命令验证：

```bash
cat ~/.vimrc        # 看到上面 16 行配置
vim /etc/passwd     # 打开即有行号和高亮，说明永久生效
```

> 如果之前已经有一个 `~/.vimrc`，上面的命令会**整体覆盖**它。想保留原内容、只追加新配置，把第一行的 `>` 改成 `>>`。

**方法二：纯净无注释版（用 vim 手动编辑时复制这段，不用删注释）**

`vim ~/.vimrc` → 按 `i` → 粘贴下面内容 → `Esc` → `:wq`：

```vim
set number
syntax on
set ruler
set nu
set showmatch
set autoindent
set smartindent
set tabstop=4
set shiftwidth=4
set expandtab
set hlsearch
set incsearch
set ignorecase
set smartcase
set encoding=utf-8
set fileencodings=utf-8,gbk
set pastetoggle=<F2>
```

**带注释讲解版（想了解每一行是干嘛的再看，不用照抄）：**

```vim
" ========== 基础显示 ==========
set number              " 显示行号（临时关闭在 vim 里敲 :set nonu）
syntax on               " 语法高亮（代码关键字变彩色）
set ruler               " 右下角显示当前光标位置（第几行第几列）
set showmatch           " 光标高亮匹配的括号（敲 ) 时闪一下对应的 ( ）

" ========== 缩进（写代码/Python 尤其重要）==========
set autoindent          " 自动缩进：新行和上一行对齐
set smartindent         " 智能缩进：遇到 if/for 等自动多缩进一层
set tabstop=4           " 一个 Tab 显示成 4 个空格宽
set shiftwidth=4        " 自动缩进时每层 4 个空格
set expandtab           " 按 Tab 键实际插入空格（Python 推荐，避免 Tab/空格混用报错）

" ========== 搜索 ==========
set hlsearch            " 搜索到的内容高亮显示
set incsearch           " 边输入边高亮（实时搜索）
set ignorecase          " 搜索时忽略大小写
set smartcase           " 但只要关键字里含大写字母，就自动变回区分大小写

" ========== 编辑体验 ==========
set encoding=utf-8              " vim 内部使用 UTF-8 编码
set fileencodings=utf-8,gbk     " 打开文件时依次尝试的中文编码（防乱码）
set pastetoggle=<F2>            " 按 F2 切换粘贴模式（见下方说明）
```

逐行解释几个重点：

| 配置                          | 解决你什么痛点                                               |
| ----------------------------- | ------------------------------------------------------------ |
| `set number`                  | 老师说"看第 20 行"时不用自己数                               |
| `syntax on`                   | 配置文件、脚本一眼看出关键字和注释                           |
| `set tabstop=4` + `expandtab` | Python 对缩进极敏感，统一成 4 个空格，避免 `TabError`        |
| `set hlsearch`                | `/关键字` 搜索后所有匹配处都变黄，再按 `:noh` 取消高亮       |
| `set fileencodings=utf-8,gbk` | 打开 Windows 传过来的老文件不乱码（先试 UTF-8，失败试 GBK）  |
| `set pastetoggle=<F2>`        | 从外部粘贴大段代码前按 F2，粘贴的内容不会被自动缩进搞乱；粘完再按 F2 切回来 |

> 没有写 `set nocompatible`——只要 `~/.vimrc` 文件存在，vim 会自动关闭 vi 兼容模式，不用显式设置。
> 想要更省事的话，网上有现成的大神配置（如 amix/vimrc），但**学习阶段建议先用上面这份精简的**，每个配置都知道是干嘛的，以后再按需加。

#### 11.6.5 配置写错了怎么办？

- vim 一打开就报一堆红色错误、提示某行有问题 → 说明那行语法错了（常见：用了中文引号/冒号），执行 `vim ~/.vimrc` 进去把报错行删掉或改正，`:wq` 重开
- 改了配置没反应 → 检查是不是在"已经打开的 vim"里看效果，退出重开；或手动 `:source ~/.vimrc`
- 想恢复出厂状态 → 把 `~/.vimrc` 改名备份：`mv ~/.vimrc ~/.vimrc.bak`，重开 vim 就是默认样子

### 11.9 Vim 常见问题（必会）

> 🏷️ ⭐ 开发必会 —— 软件开发日常高频使用，务必掌握

- **中文乱码**：在 `.vimrc` 加 `set fileencodings=ucs-bom,utf-8,gbk,gb18030,big5`
- **粘贴后缩进错乱**：进入粘贴模式 `:set paste`，粘贴后 `:set nopaste`
- **强制退出卡死**：按 `Esc` 后输入 `:q!`
- **误按 Ctrl+s 卡住**：按 `Ctrl+q` 解除（Ctrl+s 是终端锁屏快捷键，几乎所有 SSH 客户端如 Tabby/MobaXterm/Xshell 都生效，VS Code 内置终端也适用）
- **文件太大打开慢**：用 `less` 或 `sed -n '1,100p' file` 查看片段
- 快捷键使用练习
  1.拷贝当前行yy，拷贝当前行向下的5行 5yy，并粘贴（输入p）。
  2.删除当前行dd，删除当前行向下的5行 5dd
  3.在文件中查找某个单词[命令行下/关键字，回车查找，输入n就是查找下一个]
  4.设置文件的行号，取消文件的行号.[命令行下:set nu和:set nonu]
  5.编辑/etc/profile文件，在一般模式下，使用快捷键到该文档的最末行[G]和最首行[gg]
  6.在一个文件中输入“hello”，在一般模式下，然后又撤销这个动作u
  7.编辑/etc/profile文件，在一般模式下，并将光标移动到，输入20,再输入shift+g
